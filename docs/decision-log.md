### 初始产品与知识模型（1–10）

| # | 当前有效决定 | 关键理由 |
|---:|---|---|
| 1 | 用户只面对一个“记忆教练”Agent，内部可有多个节点和工作流，不做多个角色 Agent。 | 用户要完成记忆闭环，不应先学习角色分工或选择 Agent。 |
| 2 | 知识分为事实、概念、程序三类；语言是独立属性。 | 三类知识需要不同问法和判断方式，语言不改变知识本身的学习目标。 |
| 3 | 数据采用来源 → 知识点 → 复习问题三层模型。 | 来源负责追溯，知识点负责学习目标，问题负责主动回忆，避免三者混成卡片正文。 |
| 4 | Mac 是长期数据事实来源；Agent 服务只是临时执行者。 | 用户的完整知识、掌握度和历史不应依赖临时工作流或形成第二份云端主库。 |
| 5 | AI 负责理解与语义；确定性程序负责流程、排期和写入。 | 把有创造性的工作交给模型，把数据完整性和边界交给可验证代码。 |
| 6 | 采集整理采用六个主阶段和条件分支：读取／转写、识别、按需核验、冲突分流、知识拆分、题目与规格生成校验。 | Agent 必须是一条可解释、可恢复的流程，而不是一次万能提示词。 |
| 7 | 一个知识点只含一个主要学习目标，并保留必要上下文。 | 过度拆分会失去意义，过度聚合又无法准确提问和排期。 |
| 8 | 每个知识点绑定来源短证据片段或可定位位置。 | 让用户能判断 Agent 是否忠于来源，也为后续评分提供依据。 |
| 9 | 冲突只暂停受影响知识点，不阻塞同一来源的其他知识。 | 把风险控制在最小范围，避免一处争议让整次采集全部失效。 |
| 10 | 每个知识点拥有固定评估规格和经校验的问题变体。 | 问题可以变化，但判断标准必须稳定、可追溯。 |

## B. 评分、时间与单题事务（11–23）

| # | 当前有效决定 | 关键理由 |
|---:|---|---|
| 11 | Agent 自动判断 Again、Hard、Good；Easy 只能由用户主动选择。 | Easy 表示用户主观感到明显轻松，模型不能可靠代替这种感受。 |
| 12 | Realtime 负责实时语音，Responses 负责结构化评分；评分失败不更新排期。 | 语音流畅性与可验证判断是不同职责，不能让语音会话自由决定掌握结果。 |
| 13 | 纠错分两层：会话内立即改判；会后修订知识、问题或评分规格。 | 既修复本次排期，也避免同类误判持续出现。 |
| 14 | 正式队列优先级为：逾期且曾答错 → 其他到期 → 新知识 → 有限提前复习。 | 先处理最可能遗忘和最需要巩固的内容，同时保证新知识能进入循环。 |
| 15 | Mac 在会话开始时生成略多于预计需要的固定候选快照。 | 会话中不被新输入改变，服务也不能任意重新挑题。 |
| 16 | **已修订**：五分钟是继续开始新题的时间窗口，不是总会话或单题硬截止；到点后自然完成当前题。单题约一分钟只给一次轻提示音和文字，不扣分、不强制结束。 | 产品是复习教练而非考试，必须尊重用户回答节奏。 |
| 17 | 使用 VAD 自动判断说话边界，同时提供“我答完了”按钮／口令，并允许用户打断 Agent。 | 自动化提高流畅度，显式控制保证识别失误时仍可完成任务。 |
| 18 | 每题最多一次提示和一次重答；一题只生成一个 FSRS 结果；提示后答对最高为 Hard。 | 防止单题无限循环，同时如实反映“在帮助下想起”。 |
| 19 | 每题先给短而分层的反馈，会后再提供可查看的详细总结。 | 实时对话不被长篇解释打断，详细依据仍可追溯。 |
| 20 | **已修订**：正式复习音频在 Mac 本地滚动保留七天用于调试，Review Today 服务不保存；Demo／POC 结束全部删除。 | 兼顾转写和误判排查与隐私控制；不把产品边界误称为第三方零留存。 |
| 21 | 长期历史只保存轻度清理后的回答文字，不保存逐字原始转写。 | 保留理解和复盘价值，同时减少长期语音隐私负担。 |
| 22 | 每题完成后立即保存；中断时已完成题保留，未完成题恢复后重新提问。 | 避免五分钟会话后统一提交导致整段进度丢失。 |
| 23 | 一题一事务：回答 → 评分 → 可选改判 → 本地历史与 FSRS 原子写入。 | 掌握历史和下一次日期必须同时成功或同时不生效。 |

## C. 实时架构、服务与数据一致性（24–35）

| # | 当前有效决定 | 关键理由 |
|---:|---|---|
| 24 | 采用受控 Realtime：Mac 用短时凭证和 WebRTC 直连音频；服务通过 sideband 控制同一会话。Realtime 不得选题、评分、运行 FSRS 或绕过提示限制。 | 获得低延迟语音，同时让产品规则仍由 LangGraph 和客户端代码掌控。 |
| 25 | 正式复习时，服务端 LangGraph 只做临时编排；Mac 提供候选快照并最终持久化。 | 服务知道本轮需要什么，但不复制用户完整知识库。 |
| 26 | 每题使用唯一 `attempt_id`，Mac 原子写入并返回 ACK 后才能进入下一题。 | 网络重试不能造成重复记账或排期漂移。 |
| 27 | **阶段性修订**：正式产品未来做登录；远程 POC 原考虑一次性设备验证，但当前本机 Demo 不实现登录或设备配对。 | 先验证单机闭环，不用尚不存在的公共服务扩大身份系统范围。 |
| 28 | Mac 本地数据库采用 SwiftData。 | 与原生 SwiftUI 项目一致，适合作为首版本地事实来源。 |
| 29 | 知识修订保留版本；旧历史指向旧版本，语义变化时新版本重置 FSRS。 | 既保留历史真相，也不把旧掌握度错误继承给新含义。 |
| 30 | 长期数据库和 LangGraph 临时状态分离；提交时检查知识版本。 | 防止恢复中的旧任务覆盖用户刚修改的知识。 |
| 31 | **已修订**：Demo 中 Mac 与本机服务的采集任务使用 `http://127.0.0.1:8742`；复习控制通道使用同一主机上的 WebSocket。HTTPS 留到远程部署。 | 本机 Demo 用自签证书会卡在 ATS；HTTP 绑定 loopback 已满足当前边界。 |
| 32 | Agent 服务技术栈为 Python + FastAPI + LangGraph。 | 便于直接使用 LangGraph 与 AI 工具，同时用 FastAPI 提供清晰本机接口。 |
| 33 | Agent 只保存带 TTL 的短期 checkpoint；完成后清理内容，长期只保留不含正文的必要技术指标。 | 支持失败恢复，又不形成服务端长期知识库。 |
| 34 | **已修订**：Demo 的 LangGraph checkpoint 使用普通 SQLite，配合本机文件权限和 TTL（默认 24 小时）；加密 SQLite 与 Postgres 留到公共部署再评估。 | localhost + TTL + 不存长期知识已覆盖 Demo 隐私；加密会拖慢第一条可跑链路。 |
| 35 | 自建 FastAPI 嵌入开源 LangGraph，不使用 LangGraph Agent Server 或 LangSmith Cloud 作为运行时。 | 保留对本地数据、接口和恢复机制的理解与控制。 |

## D. 采集、核验与生成约束（36–44）

| # | 当前有效决定 | 关键理由 |
|---:|---|---|
| 36 | 工具路线由图和程序条件控制，不让模型自主决定所有工具调用。 | 提示词不是可靠权限边界，联网、重试和写入必须可预测。 |
| 37 | 网页只做公开 HTTP 抓取和正文提取，不使用无头浏览器；实施 SSRF 防护，失败时提示粘贴正文。 | 覆盖主要输入场景，同时避开登录态、动态浏览器和内网访问风险。 |
| 38 | 语音随记采用录完后批量转写并自动入库；成功后删除采集音频，失败或待处理时保留本机重试。 | 首版优先稳定整理，不把语音采集复杂化为实时会话。 |
| 39 | 客观主张、来源观点和个人想法都可入库，但必须保留归属。 | 用户不只学习事实；系统不能把观点伪装成已核验结论。 |
| 40 | 风险检测使用确定性规则与模型分类的“或”组合。 | 规则覆盖明确高风险类别，模型补足上下文判断，任一命中都不静默跳过。 |
| 41 | 核验优先权威或一手来源；没有时至少两个独立可靠来源；证据不足或冲突则暂停。 | 用可解释证据决定能否进入复习，不凭模型自信度强行通过。 |
| 42 | 模型输出先做 JSON 结构校验，再做独立语义校验；最多自动修复一次，否则进入待处理。 | 格式正确不代表内容正确，反复修复也不能无限消耗和掩盖失败。 |
| 43 | 问题生成者和答案评估者是两个独立调用职责；Demo 可使用同一模型版本但采用不同指令。 | 降低“自己出题自己认定正确”的偏差，并方便分别评测。 |
| 44 | 评估规格包含学习目标、必答点、同义表达、常见误解、证据、必要顺序、主问题和最多两个变体，不制造虚假权重。 | 让语义评分有明确依据，同时避免看似精确但无来源的分数体系。 |

## E. 评分、排期与候选规则（45–54）

| # | 当前有效决定 | 关键理由 |
|---:|---|---|
| 45 | 语义决定正确性，时长不自动扣分；提示事件限制最高等级；Easy 只由用户升级。 | 把知识掌握与表达节奏、技术耗时区分开。 |
| 46 | 用户可将结果改为任意 Again／Hard／Good／Easy；保留原等级，生效等级进入 FSRS。 | 尊重用户最终判断，同时保留评测 Agent 准确率的证据。 |
| 47 | FSRS 在 Mac 使用固定算法版本和默认参数；服务只返回等级；历史保存算法和参数版本。 | 让实验期排期可复现，不因模型或服务变化静默改变。 |
| 48 | 每个知识点只有一个 FSRS 状态，问题变体共享排期并轮换。 | 评估的是同一知识，而不是把不同措辞误当成多份记忆。 |
| 49 | 新知识至少等待两小时才进入正式复习；会话快照不接收新项目。 | 区分即时理解与经过间隔的主动回忆。 |
| 50 | 提前复习仅限未来 24 小时内到期，每次最多两题；仍不足就自然结束并标记 early review。 | 避免为了凑满五分钟过度提前破坏排期。 |
| 51 | 同优先级内软性交错：同一来源最多连续两题，条件允许时混合知识类型，但不丢弃到期题。 | 减少上下文惯性，提高真实回忆，且不牺牲排期优先级。 |
| 52 | macOS 本地通知提供现在开始、15 分钟后、1 小时后和今日跳过；每天最多稍后两次。 | 主动召回但不连续催促，也不依赖服务器常驻。 |
| 53 | 无候选时不通知并记录“无需复习”；21 天验证增加可用日完成率。 | 不把系统没有任务误判成用户漏做。 |
| 54 | 同日额外会话只使用仍到期或尚未复习的新候选，不重复当天已完成题目；不做自由练习。 | 保持所有正式复习都受排期驱动，避免刷题改变实验口径。 |

## F. 知识生命周期、语言与故障降级（55–64）

| # | 当前有效决定 | 关键理由 |
|---:|---|---|
| 55 | 支持暂停、可恢复软删除和永久删除；共享来源仍被其他知识引用时保留。 | 给用户可逆管理能力，同时避免删除一条知识破坏其他来源追溯。 |
| 56 | 恢复暂停或软删除知识时保留历史，但从下一次正式会话重新进入，不制造逾期债务。 | 恢复学习目标，不用过去暂停时间惩罚用户。 |
| 57 | 每条知识只有一个主要主题；Agent 匹配或建议，用户可编辑；不做自由标签。 | 支持轻量浏览，不扩张成复杂知识管理。 |
| 58 | 提供“用中文复习／用目标语言复习”的简单用户控制，内部仍记录内容、问题和回答语言。 | 用户不需要理解复杂语言字段，但系统需要稳定驱动不同问答。 |
| 59 | 正式复习允许文字回答；21 天 POC 至少 15 个完成日中有 10 天语音为主。 | 文字保证环境和技术可达性，语音指标仍验证产品核心假设。 |
| 60 | Realtime 失败后先用 macOS TTS 朗读确定文本，再降级纯文字；降级会话可完成但按实际方式统计。 | AI 语音故障不能让整次复习和排期丢失。 |
| 61 | 采集采用本地优先持久任务状态机和唯一任务 ID，指数退避、重启恢复，本地提交 ACK 后才完成。 | 离线或服务波动时原始输入不丢、结果不重复。 |
| 62 | 语音转写通常自动处理；只有低质量、异常或可疑时要求用户确认。 | 保持低摩擦，又不给明显错误内容自动入库。 |
| 63 | 所有需人工介入内容进入统一待处理中心，按优先级处理，不为每条单独推送；会后显示数量。 | 避免通知骚扰，并为冲突和失败提供统一恢复入口。 |
| 64 | 冲突处理可采用限定版本、改为来源观点、继续暂停或删除；不能强制把已知冲突标为确认事实。 | 用户保留学习选择，系统仍守住事实可靠性边界。 |

## O. 已修订决定摘要

以下旧结论不可继续作为当前实现依据：

| 旧结论 | 当前结论 |
|---|---|
| 五分钟是会话或回答硬截止 | 五分钟只限制继续开新题，当前题自然完成；一分钟仅柔性提示 |
| 正式音频不保留 | Mac 本地滚动保留七天用于调试，服务不落盘，Demo／POC 结束全删 |
| POC 先做一次性设备验证 | 当前本机 Demo 无登录／配对；未来远程阶段再决定一次性验证或正式登录 |
| 先做公共单实例服务 | 当前只做 App 托管的 localhost 开发服务，正式安装与部署后置 |
| 菜单栏或全局快捷入口二选一 | 当前明确主窗口 + 菜单栏，全局快捷键后置 |
| 首次启动预检三种形态待选 | 不做独立引导页；学习 Task 显示服务状态，Settings 提供诊断 |
| 采集通道写 HTTPS/HTTP | Demo 明确使用 HTTP `127.0.0.1:8742`；HTTPS 留到远程阶段 |
| Demo checkpoint 必须加密 SQLite | Demo 用普通 SQLite + 文件权限 + TTL；加密留到部署 |
| 实现前必须形成完整接口规格 | Harness V2 已先冻结跨切片主契约；实现细节随代码补齐 |
| 视觉方向不做吉祥物 | 允许一个克制的品牌角色承担语音状态与温柔反馈，但不引入考试压力、养成关系或夸张游戏化 |
| 发光圆角声音口作为角色识别核心 | 嘴回归不规则手绘表情；语音识别由轮廓、重心和动作承担 |
| C 形耳扣展开为单侧半环耳机 | 待机不显示耳机；语音会话直接佩戴正常的轻量双耳耳机 |
| 本机 Python 服务由终端手动启动 | Harness V2 的开发 Mac POC 由 App 自动托管；正式分发后置 |
| 主窗口 + 菜单栏承担采集 | Harness V2 的输入统一进入“学习”工作区；菜单栏采集后置 |
| 首页是含采集框的今日记忆跑道 | Today 是纯数据看板；Session 学习和输入进入独立“学习”工作区 |
| 主题愿望不是独立 Mode | 主题探索成为四种受控工作流之一，与资料学习明确衔接 |
| 每一刀才冻结接口，不要求总规格 | Harness V2 先冻结跨切片接口与事件主契约，再进入代码 |
| 服务状态统一放今天页顶部 | 服务状态在当前学习 Task 展示，详细诊断在 Settings；Today 不承载输入 |
