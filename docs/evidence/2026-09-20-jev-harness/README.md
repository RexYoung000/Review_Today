# Jev 真实 Harness 接入与隔离对照

工程接入已完成，日常 App 默认关闭。五类判断均已在真实 Harness 节点中生效；正式复习评分、排期、现有供应商配置未修改。实验完成不表示具备日常自动接管准确性，也不表示 Rex 已验收。

## 本批范围与记录

- [live.jsonl](live.jsonl)：完整 116 次执行，31 个固定对话 × 2 方，以及 27 个节点样例 × 2 方。追加写入，包含实际上下文、提示词、结构、输出、Jev 原始响应、模型配置、用量、判断采用情况及程序状态；无凭证。
- [live-summary.json](live-summary.json)：可重算汇总；原始断言失败保留，不以复核覆盖历史。
- [review.json](review.json)：原始文件摘要、重点场景复核、重复候选断言修正及已知限制。
- [smoke.jsonl](smoke.jsonl)：先行 8 次管线检查、10 次 HTTP 调用。保留其中证据探针的问题范围不一致，未混入完整对照。
- [binding-flow.jsonl](binding-flow.jsonl) 和 [binding-summary.json](binding-summary.json)：修复出题标准绑定后的 4 轮真实生成式检查，结果全部通过。保留首次出题、固定合成答案、评价及下一题的完整状态。
- [controlled-final-delivery.txt](controlled-final-delivery.txt)：最终 **668 项测试、306 项子测试通过**，其中新增判断专项 35 项。前几次检查日志也保留。

所有数据库位于独立临时目录，不读取日常会话。对话回放阻断真实网页与知识写入；网页节点使用合成搜索结果和正文，冻结非焦点准备过程。因此本批验证模型与 Harness 分工，不能证明真实搜索服务成功或原生 App 体验通过。

学习评价节点在接收答案前绑定标准，两方都得到同一题目、参考及固定标准。DeepSeek 基线保留现有评价结构与模型，节点探针额外提供固定标准；整轮对话基线完全使用关闭 Jev 的原流程。前次已知回归样例不算独立保留验证集。

Jev 入口仅 **1/31 直接采用**；其余 30 次交回 LLM：5 次保留职责或混合请求、7 次 LLM 判断冲突/保留项、3 次字段不确定、1 次超时、14 次连接失败。这里的 30 次不全是模型判断错误。连接故障期间，无凭证的官方模型端点检查及 curl 都出现 TLS 建连失败；后来恢复，未修改 TLS 验证或供应商配置。

真实局部错例：`A006-repair-question` 中，Jev 把“我不是才和你聊天吗”判为 social，LLM 按前文识别为会话纠错并回答原问题。`A007` 的续学与部分工具字段不确定也交回原流程。跨会话目标、控制和产品范围未由 Jev 自动补齐。

基线 `A017-internal-material` 把内部材料分析误分成资源代办并拒答；实验分支通过自动断言，但其回复“只在本地整理”不准确：材料仍由已配置的外部 LLM 处理，实际保证仅是未发送至网页工具。这项话术需继续校准，不能称整轮体验全部正确；也不能把单次基线随机错例算成 Jev 的稳定收益。

## 程序契约验证

受控检查覆盖：关闭时保留原模式与输出结构；开启后真实采用并跳过重复筛选；明确手动模式优先；混合请求、控制、跨会话与产品范围保留 LLM；有效候选、空选择、非法/重复 ID、数量与官方域名约束；支持来源不能扩到未支持页面；预先绑定题目标准、同义表达与核心误解分开、提示与迁移条件继续执行；旧题和题目/参考版本变化失效。

故障检查覆盖：5 秒上限、零自动重试、认证失败停用实例、缺失字段与非法概率/模型、预算预留、缓存按内容/版本/模式失效，以及取消/过期不启动兜底、迟到结果只记用量。业务代码不依赖测试模块。工程记录区分调用错误与有意义的否定。

完整模型批次后，复核发现两份新题标准因模型摘录改写了 Markdown 或合并非连续句子而未绑定。已修复为程序将实际讲解/参考原文绑定进标准，不依赖模型复制引文，不在用户作答后补造标准。补跑真实“出题→作答→下一题”：Jev 分支标准版本 1 在作答前存在，评价使用同一指纹，下一题绑定版本 2；固定答案未覆盖“只有一个候选时无法排序”的要点，程序判未通过，没有为了实验通过修改学生答案。

此外补了账目/复核修正：保留最初回退错误原因；关闭客户端或收到非法数值响应后仍正确脱敏；重复候选按同一内容核对；统计部分回退和不完整费用。原始文件各自保留运行时源码摘要；前批缺陷未覆盖，修复后的结果另存。标准由模型制定的语义质量仍需独立校准。

## 逐项结论

| 节点 | 当前结论 | 下一步依据 |
|---|---|---|
| 学习记录筛选 | 适合小范围试点，优先 | 有效替代独立 LLM 筛选，本批无误选；延迟更长，关系细分类仍需复核 |
| 网页候选筛选 | 适合小范围试点，其次 | 本批满足相关性与官方域名限制；仍须读取和核验正文 |
| 学习答案评价 | 需要继续校准 | 标准绑定和程序判分已生效；10 个有效响应不足以证明稳定准确，另有 2 次超时，反馈链路增加成本与耗时 |
| 明确结论的证据支持 | 需要继续校准 | 仅两个简单结论实际由 Jev 判断；多来源综合仍依赖 LLM |
| 入口自动分流 | 暂不采用日常自动接管 | 直接采用仅 1/31，回退多且整轮更慢；保留当前实验接入便于后续逐项校准 |

下一步应先选一个候选筛选节点，以独立样例校准是否放行和阈值；本批未设置生产概率门槛，也未开启日常实例。

## 复现

在 `agent-service` 目录执行：

```sh
bash run-controlled.sh
.venv/bin/python tests/run_jev_harness.py
.venv/bin/python tests/run_jev_harness.py --report ../docs/evidence/2026-09-20-jev-harness/live.jsonl
.venv/bin/python tests/run_jev_harness.py --case A013-current-plan-next --verify-question-binding
```

报告命令因保留原始失败返回非零，这是预期结果。真实调用使用 `--live --jev-key-stdin --output <新的结果文件>`；凭证由现有安全来源送入标准输入，不放入命令参数或仓库。可用 `--stage dialogue|nodes`、`--case <已有案例 ID>` 限定批次。临时实例由运行器显式注入能力，日常服务没有新增启用环境变量。
