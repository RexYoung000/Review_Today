# A012 闲聊有限接应

## 已确认规则与实现

Rex 选择“有限接应”：问候、感谢、简单情绪自然回应，明确陪聊将范围留在学习困惑与知识理解；不主动发展泛聊、不按轮数拒绝。明确不学时尊重休息，学习困难可给建议；混合表达继续处理实际问题或操作。当前请求优先，不复述无关的历史记忆限制，原文保留。

同次 IntentDecision 增加 conversation_kind（默认 ordinary）及 social 意图。纯社交/陪聊只用意图调用，问候感谢与陪聊回应由程序约束，普通情绪使用不超过120字的轻量回应。学习支持复用一次正文生成，不进入教学准备或网页工具，不写学习计划、检查题、掌握状态或知识成果。混合问题、真实操作、续学、对话纠错及编程边界由原路径处理。旧检查点可读取，未完成且缺新字段时重判；已完成历史不重写。

新输入仍沿用既有保护：旧收尾提示可收起、未执行的自动续讲中断、未提交的保存先暂挂并按真实意图恢复/取消；本次没有绕开写入保护。已存在的学习任务、理解与待录入内容保留。

## 真实模型结果与遗漏修正

初轮见 `initial-live-replay.jsonl`：识别学习支持时同时返回 social+defer，原白名单排除了这个组合，误回较长的普通回答；状态虽保留，分流断言失败。另实看问候、感谢和疲惫表达仍重复学习邀请。修复支持+暂缓组合，问候/感谢直接简短回应，简单情绪提示取消学习尾句，并补受控案例。

最终 `live-replay.jsonl` 的19轮全部通过路由、工具与状态检查：

- 问候→感谢→疲惫→陪聊→重复陪聊→明确不学→学习困难→情绪+RAG→harness→暂缓。
- 问候→询问历史→真的吗→你再看看→陪聊；最后只回应当前陪聊，不再解释旧记忆限制。
- 显式建立 for 循环学习→学习支持→陪聊→谢谢并继续讲解；支持/陪聊两轮的任务、计划、草稿与来源状态不变，随后继续原课程。

全部19轮无网页调用、没有新增知识录入提示；知识问题正常解答，显式学习目标仍建任务。短接应只经过一次意图模型调用；学习支持经过意图与正文调用，没有新增模型复核。这些是有限样本和当次模型输出，不代表所有表达的识别率或完整教学内容质量。话术自然度仍待 Rex 验收；原生布局未改，本轮不重复做 Mac 构建/视觉验收，也不关闭 M1。
