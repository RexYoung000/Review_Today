1. **保留现在的正式数据。** 七份文件中五份不同于 10 月 25 日基线，当前修改时间显示在本轮前已变化，但原因和业务差异未核实。建议先只复制现有字节到新的受限位置，在副本核对完整性和变化；经 Rex 确认后为新批次建立独立基线。旧基线和失败记录保留，不把当前数据回滚到旧备份，不把观察快照直接作为已批准基线。
2. **旧 274 批次继续停用。** 缺失的 23 个严格路径所需 17 个去重字节对象已从归档读回核对，但不写回旧路径、不恢复旧额度。新批次从已验证归档准备独立依赖，在新实际路径固定指纹；旧缺失单独保留。
3. **重建独立、持久的准备环境。** 新批次使用受限 `.noindex` 根目录、自有 UUID／空运行库／端口／pending＋HOLD。新完整 NativeQA 副本沿用产品主界面和托管实现，按新路径重做环境封装、签名与机器码／资源核对。现存 274 候选绑定旧环境，不能直接复用为新批次。
4. **先跑离线守卫，再确认执行。** 覆盖 pending 拒绝、真实 SDK 假传输上限、零网页、首错停止和全部当前严格组。新基线获得同意且离线通过后，才请求实际执行和新调用上限确认。

上述数据基线与旧运行现场处置超出了“扩展历史副本检查”的原范围，需要明确决定；本轮只形成方案，不据此改变 276 标准。

## 新调用上限建议

沿用已审阅的 274 小范围路径：**最多 20 次模型请求、0 次 provider 网页操作**，包含全部启动、后台、失败、重试和已有有界修复；只是次数上限，不是金额上限。本建议尚未激活，也不恢复任何旧批余量。

| 操作 | 预计模型请求 | 通过条件 |
|---|---:|---|
| 完整 App 冷启动并自行拉起新服务 | 8 | 父子 PID、真实端口与就绪对应，不预先启动 Python、不借旧服务 |
| 原生输入固定 RAG 小知识点 | 3 | 完整讲解实际覆盖整道题，题目只显示一次 |
| 故意漏答部分题意 | 2 | 正确部分获反馈，缺口不提前认证或邀请保存 |
| 针对实际题目完整补答 | 2 | 仅认证已证明概念，显示未保存标题／要点／总结 |
| 浅色默认／深色最小窗口、焦点与退出读盘 | 0 | 内容无裁切遮挡，退出后子进程关闭，仍零知识卡／来源／复习 |
| 预计总量／额度内预留 | **15／5** | 所有请求合计不得超过 20 |

固定输入、逐关标准、排除范围见 [plan.json](plan.json)。窗口目标为内容区 1280×820 与 760×620；达不到实际尺寸就记录未通过。当前桌面是否锁定本轮没有检查，不沿用旧批的锁定或解锁状态。

## 停止与回退

启动首个探测失败、任何功能关最终失败、需要修改代码／数据／替换输出／重启才能继续、保护条件变化或达到上限时，立即禁止新请求，留存失败及在途回执，不重发凑成功。遇系统目录权限提示保留现场，交 Rex 处理。

新批执行后只能正常关闭自己创建的 App／服务，保留新运行目录、账本、输出和观察证据；正式数据不参与恢复。失败不消耗旧冻结额度，不用旧结果填补新结果。不自动发布、部署或更换日常 App。
