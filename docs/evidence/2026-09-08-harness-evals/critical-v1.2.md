    ## 知识点
    - **asyncio** 使用 async/await 语法编写**并发**代码，目标场景是 I/O 密集和网络任务。
    - **并发机制**：协程在等待（如 I/O 操作）时**让出执行机会**，让其他任务得以运行，属于任务的交错执行。
    - **限制**：并发不等于并行——asyncio 默认不利用多个 CPU 核同时执行；事件循环中若出现阻塞调用，仍会阻塞整体执行；异步方式**不保证** CPU 密集型计算更快。
    
    ## 关键关系
    | 概念 | 含义 | asyncio 的适用性 |
    | --- | --- | --- |

    ## 第一步：asyncio 的 I/O 并发
    
    先明确一个容易混淆的点：**asyncio 解决的是 I/O 密集型任务的并发问题，不是 CPU 密集计算加速**。需要同时等待网络响应、文件读写、数据库查询这类场景，才是它的主场。
    
    核心机制有三个：
    
    - **协程（coroutine）**：用 async def 定义的函数。调用它不会立即执行函数体，而是返回一个协程对象，要等事件循环调度它才真正运行。
    - **事件循环（event loop）**：负责安排协程的运行。它可以同时维护很多挂起中的协程，谁该运行就运行谁。
    - **await**：当协程运行到 await 时，如果等待的操作还没完成，它就把执行权交还给事件循环，让其他协程有机会跑。
    
    真正的并发体现在“让出执行权”这一步。看个简化例子：
    
    ```python
    import asyncio
    
    async def fetch(url):
        print("fetching", url)
        # 模拟网络等待，await 时会让出控制权
        await asyncio.sleep(1)
        print("done", url)
    
    async def main():
        await asyncio.gather(
            fetch("a"),
            fetch("b"),
            fetch("c"),
        )
    
    asyncio.run(main())
    ```
    
    三个 fetch 协程几乎同时开始，总耗时大约 1 秒，而不是 3 秒。原因正是每个协程在 await asyncio.sleep(1) 处都让出执行权，事件循环转去启动下一个。
    
    关键点：**这只是并发，不是并行**。并发是多个任务交替推进、重叠等待；并行才是真正同时利用多个 CPU 核心。asyncio 是单线程模型，三个协程在同一线程内切换，不会同时计算。
    
    所以异步 I/O 的性能收益来自“等待时不空转”：一个协程在等网络，另一个还能继续做自己的计算或发起新的请求。若任务本身不需要等待、全是 CPU 计算，这种交替反而带来切换开销。

    ## 阻塞调用为什么会让并发卡住
    
    在单线程的事件循环里，同一时刻只跑一段代码。当协程执行到 `time.sleep(5)`、同步的 `requests.get("url")` 这类阻塞调用时：

    ## 关键区分：阻塞、等待、事件循环
    
    for asyncio 来说，代码里写 `await some_io()` 时，当前协程会**挂起**，把控制权交还给事件循环，由事件循环调度其他已就绪的协程。这个让出动作是 async 的核心，它不占用 CPU 空转，而是‘等待外部事件完成’。
    
    我们举个直观类比：
    
    > 异步就像咖啡店只有一个店员（单线程 + 事件循环）：接到订单后，把咖啡机启动（发起 I/O），然后马上去服务下一个顾客（处理别的任务），等咖啡好了（事件完成）再来取。多核并行则像开多个咖啡店，每个店有独立店员，各自同时做不同订单的咖啡——这才是真正意义上的同时操作。
    
    更具体地对比：
    
    | 维度 | async / await（asyncio） | 多核并行（如多进程） |
    | --- | --- | --- |
    | 需要多个 CPU 核心 | 不需要，单线程即可运转 | 必须多核才能真正同时执行 |
    | 真正的硬件层面同时执行 | 否（同一时刻只有一个协程在跑） | 是（每个核心各跑一个任务） |
    | 适合任务类型 | I/O 密集（网络、文件、数据库等待） | CPU 密集（大量运算、图像处理） |
    | 解决的问题 | 减少等待导致的空闲，提高吞吐 | 缩短总的计算时间 |
    | 关键机制 | 事件循环 + await 让出控制权 | 操作系统/硬件调度多个进程/线程 |
    | 是否受 GIL 影响（仅 CPython） | 基本不受（因为不做 CPU 密集计算） | 多线程受 GIL 限制，多进程不受 |
    
    特别提醒：协程内的**阻塞调用**（如普通的 `time.sleep`、同步 `requests.get`）会**卡住整个事件循环**，导致其他协程无法运行，等于‘异步失效’；应改用异步版本（`asyncio.sleep`、`aiohttp`）。
    
    ## 为什么 asyncio 不能替代并行做 CPU 密集任务
    
    因为 asyncio 本质是单线程内循环调度，**同一时刻只有一个任务在 CPU 上执行**。CPU 计算本身不产生等待，所以 async 在这种情况下没有收益，反而因为调度开销变慢。要做真正的并行加速，应使用 `multiprocessing`（多进程）或配合线程池做混合方案。

    ### 并发与并行
    
    **并发（concurrency）** 指多个任务在重叠的时间段内推进，但不一定同一时刻都在执行。**并行（parallelism）** 指多个任务在同一时刻真的同时执行，这需要多核 CPU 或多个 CPU。并发是“逻辑上同时”，并行是“物理上同时”。
    
    举例：一个人同时接待多个顾客，泡咖啡时去接电话，这叫并发；两个收银员同时给两个顾客结账，这叫并行。
    
    ### async（异步）的本质
    
    async 是**并发编程的一种模型**，特别是基于事件循环的协作式多任务。在 Python 的 asyncio 中，用 async def 定义协程，await 一个耗时的 I/O 操作（如网络请求、文件读写）时，协程会**主动让出 CPU**，事件循环调度其他协程继续执行，直到 I/O 完成后再回来。
    
    关键点：**整个 asyncio 默认运行在单线程、单进程内**，同一时刻只有一个协程在执行。所以它**不是并行**，它只是在等待 I/O 时切换任务，提高了 CPU 和网络资源的利用率，而不是利用多核同时计算。
    
    ### 一个实例体会区别
    
    假设有 10 个网络请求，每个耗时 1 秒：
    
    - 同步串行：需要约 10 秒。
    - asyncio 并发（单线程）：因为请求是 I/O 等待，可以在等待时切换，总共约 1 秒多。
    - 多进程并行（假设 10 核）：同时执行 10 个请求，约 1 秒多。但多进程会为每个进程分配独立内存，开销大。
    
    async 在这里达到类似并行的“墙钟时间”效果，但原理不同：它不是在多核上同时跑计算，而是**在单个线程里让多个任务在等待时交替推进**。
    
    ### 什么时候用谁
    
    - **async 适用**：大量 I/O 操作，如网络爬虫、Web 服务器、数据库访问。这些操作本身不占 CPU，主要时间是等待外部资源。
    - **并行（多进程、多线程）适用**：CPU 密集型计算，如大数据处理、复杂数学运算，需要多个核真正同时计算。
    
    ### 常见误解
    
    很多人误以为 async 就一定比多线程快。其实 asyncio 的优势在于**开销小**（协程切换比线程切换轻量），但在多核 CPU 密集型任务上，asyncio 反而不如 multiprocessing，因为它只用一个核。
    
    **一句话总结**：并行吃多核，async 吃等待；async 不是 Python 层面的“同时”，而是“不等”。
    
    ### 适用条件
    
    - 你所说的 async 指 Python asyncio 的异步 I/O 模型。
    - 你不需要深入事件循环内部的调度算法。
