# 语音复习重构：实现与隔离验证

日期：2026-09-23。工程接入已实现；真人语音、扬声器回声和自然程度仍待体验。本轮不恢复 Harness 整体测评、不扩展 Jev 正式评分、不更换日常 App 或 DeepSeek 配置。

## 实际交付

- 资料默认仅保存；显式“已学过，加入复习”或知识详情的独立开关才参与到期队列。来源和内容校验保留，无入门考试。新加入首轮两小时，旧参与状态、历史、当前到期日期保持。
- 开始时冻结跨主题到期清单，按逾期顺序；默认全部，也可指定分钟或数量。每个知识点一次、题目变体轮换，当前题保存后才检查时间目标和进入下一题。关闭暂停，重开继续。
- 文字／实时语音共用同一控制器：原始答案、题意澄清、具体缺口、提示、讲解、追问、跳过及纠正。首次独立表现决定排期，提示后答对不能覆盖；解释后不强制重考。纯跳过、技术失败均不评分。
- Mac 原子保存结果、完整 FSRS 状态和队列游标。重复提交不记两次，纠正从之前的状态重算，后续已有新复习则拒绝改旧结果。服务回执失败不会撤销本机保存。
- 固定 swift-fsrs `4fbaf20184d62f82a9f44f343337c61a2c5483e9`，显式 FSRS 6 默认权重、目标保留率 0.9、无随机扰动、学习／重学 10 分钟。旧演示参数在下一次有效复习时重新初始化；0.9 是参数，并非测得的正确率。
- SQLite Backup API 在 SwiftData 打开旧库前生成一致备份，包括已提交的 WAL 内容；失败不继续迁移。备份目录与数据库同级的 `ReviewBackups`，完成标记包含备份路径。

## 真实文字与原生保存

[最终 13 条文字样例](text-live-03.json) 全部符合独立制定的期望：同义、遗漏、混合错误、忘记、澄清、提示、讲解、自述理解、请求纠正、困难但正确、跳过、提供完整纠正答案，以及追问中透露答案要点。规则 V3 增加帮助披露字段，原生控制器据此记录帮助，避免将听到答案后的复述算作独立回忆。它们是有限的合成烟测，不是普遍准确率证明。

[原生最终结果](native-real-result.json)：3 个固定候选，完成 2 个、跳过 1 个；先漏答→提示→答对仍按 Again 保存；暂停恢复保持原清单；完成后纠正首个转写，重算为 Good，复习次数仍为 1。[本地落盘状态](native-local-state.json) 保留答案、帮助点、排期前后及纠正版本；[实际 HTTP 输入输出](native-http-trace.json) 包括失败阶段和最终阶段，均为合成内容。

上述原生真实模型流程使用规则 V2；最后的 V3 增量通过真实模型节点样例及原生控制器契约验证，未再重跑整段原生界面流程。

实际请求继续使用配置中的 `deepseek-v4-flash`；供应商在本轮返回 `deepseek-flash`。官方说明旧名称目前映射到 V4.1 Flash，按 Flash 计费，因此没有为此改写用户配置。[DeepSeek 模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

## 真实音频

[最终音频烟测](voice-live-04.json) 通过实际本地 WebSocket→阿里云北京 `qwen3.8-omni-flash-realtime`：播报题目、6.44 秒 macOS 合成回答的转写、生成期间取消、后续播报及断开重连。未开启真人麦克风，合成音频临时文件在测试退出时删除；仅保留文字、字节数量、延迟和用量。

本机检测停顿后提交音频，语音模型负责转写与播报，当前文字模型负责评价。模型无排期／保存／下一题工具权限。播报采用最多 3 MB 的内存缓冲：返回文本与程序授权文本一致后才释放音频，变更题目、擅自回答或增加保存声明时拦截，可继续看文字。该核对可能使首个可播放音频稍晚，本轮实测 1.306 秒。

窗口开始前不连接麦克风；暂停／关闭停止采样和播放并清理缓冲。正常结束停止采样，允许已经本地提交成功后的简短结尾播报结束，再关闭连接。不会生成复习录音回放。本机清理不代表供应商零留存。[阿里云模型与地域／音频计费说明](https://help.aliyun.com/en/model-studio/qwen3-8-omni-flash-realtime)

## 保留的失败与修复

1. `voice-live-01.json`：语音模型直接回答题目，随后打断报错。添加明确逐字朗读请求以及程序播报核对，防止模型越权发言。
2. `voice-live-02.json`：题目已正确朗读，但打断后再次取消同一响应导致错误。增加取消状态与终态等待，旧音频不能绑定新播报。
3. `voice-live-03.json`：音频操作和重连已成功，测试过早读取用量表；等待桥接关闭后采集，04 完整通过。该次不能作为完整统计通过。
4. [原生同步失败](native-initial-failure.json)：旧暂停任务读取了变化后的会话版本，拼接了旧题目，服务拒绝后续请求。改为派发前固定同步快照，纠正也递增同步版本。
5. 原生第二阶段：完整的替代答案被模型标成“请求纠正”，未重算。规则 V2 明确“请求纠正”与“提交替代答案”的区别，并拒绝非答案意图携带评分数组的矛盾结果。最终原生重算次数及对应真实样例已复测。
6. 追加的 WAL 备份检查发现，继承 WAL 模式的备份在只读打开时需要额外日志文件。备份完成后改为 DELETE 日志模式，交付独立可读的备份文件；生产源库的日志模式保持原状。

以上错例和失败请求均保留，未据此宣称模型能无误理解所有口语。
