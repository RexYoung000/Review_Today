# 同一聊天连续语音 POC · 2026-10-03

已接入本机日常 App；代码、隔离原生流程与合成音频真实服务链路已验证。交付类型是 **Native Prototype**，状态为 **code complete**；真人麦克风／外放／自然停顿与最终体验仍待 Rex 确认，不记为完整体验验收或发布。

## 实际入口与行为

Agent 聊天底部保留「开始听写」麦克风，旁边新增波形「开始语音对话」。听写继续回填草稿；语音对话说完稍停后自动发送，Agent 在同一聊天中回复并播报。点击语音才请求系统麦克风权限，代理没有开启真实麦克风。

- 黑白 B 面板区分连接、聆听、转写、处理、播报、失败。声波使用输入或实际输出强度；处理时无假声波，减少动态保留静态强弱提示。
- 静音只关闭输入，已提交的转写／回答和播放可继续；「结束语音」或 Esc 停止音频并恢复原稿。未发送文字和附件不会随语音发出。
- 开口打断清当前／待播音频，并按既有规则停止正在生成的回复；不取消学习目标。历史、其他聊天和失效修订不自动重播。
- 首句语音原子创建会话；重复／乱序转写有绑定和去重。播放记录只将设备已完整播完的段落计为完成，被打断的当前段另记。
- 语音“继续刚才”可播报由本次输入明确恢复的旧 Run；保存后续接也通过 `voice_input_ids` 传递因果关系，不放开所有同聊天回复。
- 本机保存失败只在当前页面保留未提交文字，需重试或复制；不能将它称作已落盘。连接失败可结束语音回到文字，不自动重启麦克风。

## 当前限制

首版等待完整行／段落确认后分句，末行通常等最终文字完成；每句音频需核对文字一致后放行，句间尚无预取。真实样例从音频提交到转写约 0.39–0.63 秒、文字 Agent 完成约 5.18–6.19 秒、首句音频再约 2.05–3.12 秒；本机停顿判断另计。不能称为低延迟逐 token 语音，速度与句间等待是下一轮优先优化项。

真实样例出现一次“只讨论→之讨论”的转写差异，旧风格也出现旁枝与不够准确的拟人表达。已收紧为一个核心点、通常 2–4 句，并补验一次；没有据此宣布所有场景稳定自然。硬件拒绝权限、设备切换、真人中文停顿／回声、系统 VoiceOver 全流程、真实锁屏和休眠仍未实际走查。生命周期中断、迟到回包与权限取消由注入合同覆盖。
