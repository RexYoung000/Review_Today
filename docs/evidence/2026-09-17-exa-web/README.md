# A008：Exa 独立搜索与网页读取接通（2026-09-17）

## 实现

经 GitHub 方案调研及 Rex 确认，Harness 直接连接官方 `https://mcp.exa.ai/mcp`，仅调用 `web_search_exa` 和 `web_fetch_exa`。不调用 DeepSeek 内置搜索、Exa Agent 或研究生成工具，也不依赖开发机全局 mcporter/Node/skill。原三个模型及凭据保持不变。

本机 `.env` 显式选 `search=exa/read=exa`，使用匿名限额模式，未注册/登录或付费。仓库默认仍不自动启用服务。未来正常使用若触发匿名限额，会明确提示并停止重试；不静默更换服务。

适配器校验 MCP 初始化、JSON-RPC 请求 ID、JSON/SSE 帧、工具错误与来源格式。搜索只得到候选；读取工具返回的 URL 必须对应请求，正文再送给模型判断证据。固定 HTTPS 端点、公开 URL 校验、响应大小上限、步骤预算、取消关闭和会话版本拦截保留。取消保证本地不发布旧结果，不承诺远端已开始的抓取立即终止。Exa 远程读取成功不表示本地 Fake-IP/DNS 已修复。

## 真实回放发现并修复的缺陷

最初的时效回放搜到了 `pythonlang.cn` 中文镜像，模型误把页面标题里的 Python.org 当成官方归属，还把刚刚抓取视作内容最新。旧脚本仅检查链路状态，曾显示 PASS，但人工检查判为语义失败，保留在 [初次失败](initial-mirror-failure.json)。

修复：查询准备在看到搜索结果前声明官方域名约束；Harness 将域名加入检索词并强制过滤候选实际 hostname（防止镜像/相似域名/域名后缀伪装）；官网归属不明时不能完成官方核验。证据判断明确区分当前日期、抓取时间和页面时效。回放额外断言来源实际属于 `python.org` 或其子域，不能仅靠 verified 标签通过。

这些域名由用户需求/查询准备确定，并非对全网机构归属作独立认证；时效判断仍依赖页面内容与模型。匿名服务的缓存新鲜度未提供保证，不把本次成功扩大为所有网站和所有最新信息都可核验。
