2026-09-08；分支 `codex/harness-evaluations`，PR #26 保持草稿。当前标准 `2026-09-08.v2.1`。已完成评测基础设施与飞书实施；人工校准、有效全量基线、定时启用和原生产品验收未完成。

## 已落地

- 100 场景，五模式 × 五领域各 4 例；75 开发、25 冻结验收；smoke 25 / critical 20；正向攻克流程有固定练习题与迁移题。
- 六维 0–3 分、N/A、合格/优秀条件、硬失败、计划分母、每模式 18/20、关键 60/60、校准绑定及版本匹配门槛；不设综合加权分。
- 25 组三档候选对照与人工签认入口。裁判原判和有效复核分开；证据无原文匹配时拒绝，并保留原始裁判结构。未授权保存、客观规则失败和运行失败不能由手动勾选变成成功。
- 飞书保留历史并增量迁移。每场景本地更新、至多每分钟进度同步；优秀、领域、抽查、复发、根因候选与人工分组、版本比较可追踪。比较只在相同标准、参考、裁判、模型角色和批类型内成立。
- 已提交版本调度、文件锁、版本指纹、隔离工作树与不确定执行标记。小时/周任务均暂停；真实定时唤醒、休眠/断网补跑尚待启用验收。

## 从哪里修复与优化

1. **裁判校准**：A11/S11 等原文引用被缩略或改写，导致待判；T21 的裁判甚至引用用户输入作为教练证据，已拒绝。保留错误原判方便核对，不放宽引用匹配求通过。
2. **优秀边界**：首轮多条候选“合格”被判“优秀”，也有优秀被降档。需要 Rex 审阅三档锚点，不能靠重复请求挑一次一致结果。
3. **严重错误分类争议**：v2.1 P11 把“尚未抓住基本框架”的否定反馈判作 false_mastery；这不是声称已经掌握。机器严重错误数 1 尚未被人工确认，不能以此声称发现已证实的严重产品缺陷。
4. **产品行为候选**：O41 出现意图目标引用错误；T41 出现计划步骤引用错误；T21 没有完成明确请求的检索/阅读；P11 不断改题、追加讲解，未按限定完成攻克流程。均保留证据，需 Rex 确认修复范围。
5. **已修评测缺陷**：明确严重错误不再被“待判”状态遮住；攻克题在首轮绑定约定练习范围；裁判校验失败保留具体原因和原始结构；看板完整基线/关键重复指标按 100/60 计划数过滤，局部探针不充当完整基线。完整基线计划 0 时表示未运行；通过率卡显示的 0 不代表实际 0%。

## Rex 的验收入口

打开 [25 组评分对照](https://my.feishu.cn/base/ZDJeb5B9na4TAgs8PDncQRMKnFh?table=tblPGOYnuaNa0dxp&view=vewCz7RGJA)，逐条对照合格与优秀条件。认可后填校准人、校准时间并勾对照确认；不认可就在校准说明中记录具体边界。结果复核另在「v2抽查与争议」填写复核等级、人、时间、原因与依据。

人工签认后先重新核验裁判绑定与 30 条对照，达到标准后执行全量 100+60，并核验真正的定时触发后启用自动任务。当前无需更换模型或放宽门槛，正式通过结论和产品发布授权始终分开。
