## 阻断本轮验收：保存查询对象错位

**观察事实：** 点击当前预览后，本机保存 5 张卡，后台邀请 v4 已 saved，保存任务 completed 且有 `mac_ack`，回执 ID 与五张卡完全一致。随后原生输入：

> 刚才保存的 RAG 知识卡存好了吗？这次一共保存了几张，分别叫什么？只查询这次的真实保存结果，不新增或修改知识卡，也不要推进学习。

模型正确选择 `knowledge_card_status=true`，没有误发保存或续学动作。它却从回顾正文选了三个知识主题，其中第一项摘录总结开场“检索相关不等于答案正确，原因可以从两个环节来说”；该开场句不在邀请冻结的事实片段中，后两项在。`knowledge_capture_status._offer_covers_focus` 因此拒绝为三个讨论主题整体认证，`facts` 进入 `scope_unconfirmed`，程序模板盖过“本次实际保存了哪些卡”的查询对象。

**用户影响：** 明明完成保存，却不能查询数量和名称，还被要求重新明确范围；会使用户无法判断刚才的保存是否有效。原生显示及后台回复一致，问题不在气泡同步或卡片丢失。

**证据和复现：** [真实最终状态](after-status-query.json)、[原生文字](native-status-query-failure.txt)、[保留原模型输出的离线复现](status-diagnosis.json)。在禁止网络且隔离 SQLite 的进程内，用原路由和最终数据调用现有程序，逐字重现错误回复；仅诊断性省略语义主题选择时，现有真实回执投影为 saved／5。该对照不修改生产或现场，**不建议把“无条件忽略主题”作为修复**。

**建议下一条范围，待对齐：** 用户明确查询“这次保存结果”时，绑定可追溯的本次保存操作、邀请版本与真实回执，返回其数量和名称；询问“刚才讲过的内容是否全保存”仍核对选段范围，新话题、旧批结果、版本和失效规则保持。先用本次数据做零新增真实调用的受控复验，再决定真实续验；本批未实施该修复。
