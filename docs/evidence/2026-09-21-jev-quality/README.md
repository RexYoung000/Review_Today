# Jev 卡片与出题质量验证

已接入两项隔离实验能力：卡片语义检查替换、教学新题及评分标准检查。正式复习、日常开关和知识库合并均未修改。工程检查通过不等于语义检查稳定可靠；本轮保留真实漏检、误判和超时。

## 实现与程序验证

- `capture_quality` 在真实保存流程的 `semantic_validate` 节点工作；有效 Jev 结果跳过原 LLM 检查。不确定／失败回原节点；程序引用检查仍可否决。现有一次修正收到具体不符合项，并重新检查。
- `question_quality` 覆盖资料教学、问题攻克和未完成作答后的新追问。先检查／至多修正一次，再显示和绑定标准。每个必答点单独核对必要性。旧题和开放式澄清没有标准时沿原流程，不称已通过质量检查。
- 需要检查的教学输出暂存，避免正文提前泄露旧题；修正同步可见问题和绑定标准。失败保持可重试状态，清除失败修正的缓存；完成的讲解／评价可复用。取消、预算、认证停用和版本守卫沿用既有引擎。
- 全量与最终定向日志分别保留；测试覆盖真实 `_save_memory` 接线、教学／问题攻克／后续题、原文引文守卫、修正／拒绝、无重复 LLM 检查、原流程关闭、故障回退、逐项不确定、缓存变化、取消迟到、超限不截断及重试不反复复用坏稿。首次专项检查的失败是测试把事件字段误写成 `type`，修为实际的 `stage` 后通过，不算产品通过证据。
- 最终生产代码全量检查为 [713 tests / 327 subtests 通过](controlled-final.txt)。早期两轮为 711 tests；随后增加原生复现对应的 Auto 教学分流检查。测试日志仅清理行尾空白，结果与警告保留。已有签名 Debug 测试 App 构建成功，最终使用工作区代码重新加载空闲测试后台；没有改 Swift 界面。

## 真实模型批次

全部使用合成材料和临时数据库；固定节点比较给两方相同材料和判断问题，不把 DeepSeek 当标准答案。标准来自原文和已确认规则。脚本调用真实供应商并保存实际结构化输入输出；Jev 还保存原始响应。DeepSeek 实际后端版本未由现有适配器返回，记录的是当前配置模型名。未进行正式知识库写入或排期操作。

| 批次 | 自动结果 | 重要限制 |
| --- | --- | --- |
| [live-01.jsonl](live-01.jsonl)，v1 | 19/19：8 组两方节点 + 3 个流程 | 人工复核发现真实生成题仍附带题目未问的原料必答点，不能把 19/19 当内容全部正确 |
| [live-02.jsonl](live-02.jsonl)，v2 | 16/23：10 组两方节点 + 3 个流程 | Jev 节点 5 个有效并符合预期、5 次超时；LLM 节点 8/10 命中特定标签；流程包含超时后回退 |
| [live-03-fixture-fix.jsonl](live-03-fixture-fix.jsonl)，v2 | 1/2 | 只修正 RAG 样例残留的光合作用顶层摘要／主题，再做两方检查；LLM 命中，Jev 超时。没有覆盖上一批失败 |

v1 整题检查漏掉了额外必答点，v2 拆成逐点判断，并把这次错例加入开发回归。v2 对该固定错例的 Jev 调用超时，LLM 对照发现了问题；尚未证明 Jev 已稳定修复该错例。v2 的普通过程题被 LLM 错误质疑全部必答点，说明回退模型也不能当金标。限定样例的初版混有顶层主题错误，LLM 在“可用性”拒绝却没有命中指定“忠实性”项；这不是一例会直接放行的坏卡，也不是干净的单维限定实验。

流程探针分别验证真实“生成卡片→检查→待提交”、“不合理标准→定向修正→重新检查”及“教学→出题→作答前绑定”。v1、v2 各 3 个流程自动完成；v2 卡片检查和题目修正期间共发生 3 次 Jev 超时，由 LLM 接续完成。没有进行原生卡片保存回执，不把 ready_to_commit 写成已在 Mac 正式入库。

## 原生交互与保留问题

复用 Rex 正在使用的隔离 Jev 测试窗口和已有数据目录；只在无运行任务时重新加载测试后台。旧会话消息摘要在开始时保存于 [native-history-before.json](native-history-before.json)。

[native-before-entry-fix.json](native-before-entry-fix.json) 保留第一批实际点击发送的结果：资料学习模式确实采用 `jev-quality-2` 并预先绑定题目标准；Auto 明确教学请求却落到知识整理；错误答案被入口标为 `answer + correction` 而绕过评价。前者的直接原因是程序无条件覆盖 material 分流，后者是入口 LLM 混淆答错与用户纠错。两项均修订并另行复验，不把原失败删除或宣称是 Jev 出题判断通过。

[native-final.json](native-final.json) 保存新增合成会话的结果、源文件摘要及人工复核，三条原会话的消息摘要全部不变。最终 Auto 新会话实际进入资料学习，首题采用 Jev 检查；明确答反顺序后，入口仅标 `answer`，Jev 检出核心误解／顺序错误，程序判定未通过，没有完成学习任务。LLM 给出纠正反馈，下一题经 Jev 检查后绑定为第 2 版标准并显示。原生可见内容与服务记录一致。

| 最终原生轮次 | 实际 HTTP | 整轮耗时 | 已知估算费用 USD |
| --- | --- | --- | --- |
| Auto 材料教学与首题 | Jev 3 + LLM 3 | 14.492 秒 | 0.001366–0.002485 |
| 错误答案评价与下一题 | Jev 3 + LLM 2 | 15.953 秒 | 0.002125–0.003822 |

这两轮共 11 次调用，用量无缺失；耗时中位数 15.223 秒，范围 14.492–15.953 秒，费用合计 $0.003491–0.006307。不是与关闭 Jev 的整轮成对实验，不能推算提速或降本。

**原生人工复核仍未通过全部语义要求：** 首题只问两个动作与先后顺序，第三个必答点却要求解释资料作为上下文的作用，Jev v2 仍给 `required_2=pass`（该选项概率 0.53）。本轮不因概率低临时增加阈值，也不声称逐点拆分已消除漏检。作答评价还把已说出的两个动作名称标成 contradicted，混入了另一个顺序错误；整体不通过是正确的，但分项标签与反馈仍不够精确。较早的教学题还存在提示答案过明显的问题。这些都保留为语义错例，不用路由完成覆盖它们。

逐项结论：卡片质量检查、题目／标准检查均已在隔离流程接通，均**需要继续校准**。当前只证明局部判断、程序约束与回退真实执行；原生卡片提交回执未验证，日常自动放行准确性和正式验收未完成。

## 复现

`agent-service/.venv/bin/python agent-service/tests/run_jev_quality.py` 默认只校验小样例清单。真实运行使用 `--live --jev-key-stdin --output <新的文件>`；`--case <案例 ID>` 只执行指定两方节点。沿用现有凭证来源送入标准输入，不放在参数、仓库或日志里。全量受控检查运行 `bash agent-service/run-controlled.sh`。
