# 检查范围核验的方案试跑

2026-10-13，Rex 对 ZCode 第 4 条第二小点的检查与评估方向回复「ok」；本批只评估能否复用现有核验，不授权功能修改或新增日常调用。当前讨论见 [第二小点](../../design-references/zcode-agent.md#topic-4-2)，续接见[工作状态](../../work-status.md#cursor)。

## 能否复用现有调用

日常教学已有讲解／出题与后续作答评价；作答评价收到范围绑定与完成条件，并区分本题通过和整步完成。出题前的独立题目质量复核目前只在隔离实验中启用，而且没有接收实际范围与该步完成条件。因此，现成实验调用不能直接当作日常已有能力；若日常新增出题前独立范围核对，会增加模型调用。

候选触发范围只限尚未发布且声明整步验证的新题；普通概念题无需增加该调用。核验拟只接收题目、实际讲解与当前步骤完成条件，不接收用户答案、旧评价、保存状态或后续课程；只返回覆盖结论、遗漏与简短依据，主流程使用它而不由检查器修改进度。该方案尚未确认采用，失败试跑不能作为启用依据。

## 两次真实组件调用

使用上一批保存的合成 RAG 讲解、原题与完成条件，加一个明确要求解释三项限制的对照题。沿用当前 DeepSeek 教练配置与 `none` 执行强度，每例一次请求，无自动重试；仅在临时进程定义检查结构，没有接入 App 或执行任何保存。临时数据库配置文件未创建。完整 system、输入、输出、字段期望和实际用量保留在 [samples.json](samples.json)。

| 样本 | 评估预期 | 实际 | 耗时 |
|---|---|---|---:|
| 原题：外部资料主要解决哪类问题、效果有何限制 | 不能明确证明全部三项限制，不能授予整步覆盖 | covered，未符合预期 | 1,535 ms |
| 明确逐项询问训练时间边界、私有资料缺失、可能编造，再问外部资料作用与限制 | covered | covered，符合预期 | 1,802 ms |

第一条的预期不是程序真值：人工复核构造了更窄但满足题意的答案：“RAG 引入外部资料是为了补充模型训练未涵盖或后来更新的知识；检索到资料仍不保证资料相关、最新或回答正确。”它没有逐项证明完成条件中的三种模型限制。核验器却从讲义补入三项内容，再拿扩写后的答案证明完整覆盖，因而没有消除原疑点。这里没有评价真实用户，不声称产品已误记掌握。

这两例不能代表准确率或一般耗时。记录本轮失败，不重跑替换；不建议把这版核验接入日常。后续需要先对齐“先收紧默认范围，明确综合检查才验证整节”与“保持日常流程，继续验证独立核验”的选择，再确定实施范围。综合检查若采用仍按需，不改变普通教学继续／跳过与问题攻克完成的既有边界。尚未修改默认判定、增加综合检查入口或更改题目／评分／保存规则；确认评估方向见[决策 225](../../decision-log.md)。
