# 教学题目与评分标准的独立 LLM 复核

本批补上“Jev 已返回通过时仍需检查”的路径。当前隔离测试 App 已加载 `jev-question-quality-4`，日常开关、卡片保存规则、正式复习及排期没有改变。

## 当前行为

- 资料学习、问题攻克、需要展示的后续新题，在发布／绑定标准前执行独立 LLM 复核；输入只有题目、标准、实际参考和规则，不提供 Jev 标签／概率或用户作答。
- LLM 先给出最小充分答案，再逐项判定。Jev 有效否定不能被 LLM 通过覆盖；LLM 否定、不确定或明确 issues 也不能被 Jev 通过覆盖。任何问题都交一次定向修正，优先按原题收窄标准，新稿再次检查。
- Jev 超时／停用／不确定由同次 LLM 复核接续，不叠加原来的不确定项回退。LLM 失败、预算耗尽、取消、过期或修正后仍未通过，不能退回 Jev 单方发布。旧题不事后补标准。
- 新规则及对象标识进入缓存；记录两方原标签、合成标签、最小充分答案、问题和实际模型调用。模型偶尔只给否定标签而未写理由时，保留这一事实，用该项既有规则指导修正，不编造模型解释。关闭 Jev 实验时不新增调用。

## 验证与真实错例

[最终全量检查](controlled-final.txt)：719 tests / 327 subtests 通过。包括 Jev 全通过但 LLM 拒绝、Jev 否定但 LLM 通过、LLM 不确定／故障、修正后复核、发布与绑定、超限、预算、缓存、取消及迟到结果。初次专项检查有一个测试夹具未初始化预算字段导致 KeyError，修正夹具后通过，首次失败保留在 [targeted-01.txt](targeted-01.txt)。测试日志仅清理行尾空白，结果和警告保留。

复用上批两条已知错例和一个正确对照，不新增大案例集，不当作独立验证样本。均使用合成材料、临时数据库和真实 Jev／现有 DeepSeek 模型。

| 批次 | 自动结果 | 实际情况 |
| --- | --- | --- |
| [live-01.jsonl](live-01.jsonl)，v3 | 1/3 | 正确对照通过；光合作用额外原料点仍被 LLM 错放，Jev 当次超时；RAG 的多余点被拦截并修正，但修正后 LLM 两次返回非法 JSON，流程停止 |
| [live-02.jsonl](live-02.jsonl)，v4 | 3/3 | 正确对照因 Jev 超时由 LLM 检查；两条坏标准均拦截、修正后重新通过 |

v4 明确“问作用／归类不等于要求列举相关类别的成员”，最小答案不加入补充解释；输出改成必填逐项标签加问题列表，减少嵌套，不修补非法 JSON 来放行。旧失败原样保留。

人工核对 v4：光合作用题仍问“光能起什么作用，是否算原料”，标准已去掉“列举二氧化碳和水”；RAG 题仍问“两个动作与顺序”，标准已去掉“资料作为上下文的作用”。两道题都保持原题，不通过扩大问题迁就旧标准。光合作用首稿 Jev 全部 pass，但 LLM 给 required_2=needs_fix，程序确实拒绝原标准。这是新增复核发挥作用的实际实例，不是模拟 Jev 结果。

LLM 首批也漏检过，最终的 3/3 是开发回归结果，不能称已经校准全部场景。双重判断仍可能共同漏检或误拒，暂不据此日常自动启用。

## 原生 App

在原 Jev 测试 App 中、后台无任务运行时重新加载工作区服务，新增一条合成会话。七条已有会话消息摘要全部不变，见 [native-history-before.json](native-history-before.json) 和 [native-final.json](native-final.json)。没有 Swift 改动，本次复用已有测试 App。

实际操作：Auto 输入 RAG 合成笔记，要求检查题只问两个动作及顺序。程序先完成 Jev 与独立 LLM 检查，再显示问题并绑定仅两个必答点。随后只回答“两个核心动作是检索和生成，先检索，后生成”，实际评价通过；可见反馈明确本题没有要求效果边界，不凭这道题判定全部掌握。该轮不展示新题，因此没有为未使用的新题重复检查。
