# A012 问候与回复反馈修复（2026-09-21）

状态：实现、受控回归、合成真实模型及原生 App 自测完成，待 Rex 体验验收。当前 Jev 测试 App 已加载修复，日常 App 的 Jev 配置未切换。

## 原因与改动

Rex 的三轮输入为“你好”→“你好吗”→“为什么你只会回我这句话”。前两轮的入口 LLM 已生成不同短答，程序却按 Jev 的 greeting 分类强制覆盖为“你好。”；第三轮进入普通问答，模型编造原因并归咎用户。这是回复选择和反馈处理缺陷，不能直接归结为 Jev 分类准确率不足。

- 问候、感谢保留可用的入口短答，仅去除已观察到的招揽、身份宣讲和不当归因句；空或超长才使用保底，不新增模型复核调用。
- LLM 识别 `reply_feedback`，纯体验反馈复用入口短答；Jev 标签不能覆盖这项职责。附带知识、控制、操作仍处理实际请求，未回答的旧问题继续原纠错流程。
- 混合请求显式要求一句话时，长度要求优先于默认定义／例子模板。反馈不建立学习任务、不评价掌握或推进保存；旧意图可读，未完成旧缓存重判，已完成历史不重写。

- [最终真实结果](live-02.jsonl)：修订后的 12/12 检查通过。基线和 Jev 各 6 轮，覆盖生成式三轮、固定重复前文、反馈附带 RAG 问题、引用投诉句的知识问题。固定前文为合成数据，不冒充原始会话。原始提示、结构、输入、输出、源码摘要和实际用量在 JSONL 中；[人工复核](manual-review.json) 单列限制。
- [原生验证](native.json)：CUA 在独立 App 新会话逐条发送并观察最终文本，再只读核对数据库。服务健康为 `jev-1.13.0`／`jev-entry-2`。原会话六条消息 ID／角色／内容摘要与重启前一致，见 [原历史摘要](original-history.json)。没有重写坏回复。

## 复验与限制

当前打开的「Review Today · Jev 测试」可直接继续输入；旧“你好”会话保留。新启动入口为仓库 `tools/run-jev-app-test.command`，每次创建独立测试数据。原生 UI 未修改，本批不重复 Swift 构建；沿用启动批次已验证的签名构建，空闲重启其 Python 服务加载本次修复。

服务回归：`bash agent-service/run-controlled.sh`。真实合成回放：在 `agent-service` 执行 `.venv/bin/python tests/reply_feedback_real_smoke.py --live --output <新的结果路径>`；读取现有安全凭证，使用临时库，会产生真实模型用量。网页／知识写入被阻断，因此不作为这些能力验证。

生成短答筛选仅处理已观察到的越界形态，不是完整语义判定。引用投诉句已正确走知识回答，但模型仍有过度概括词语含义和语气的表述；本次不宣称这些语言学解释全部正确。样本规模仅验证此次缺陷，不能校准放行阈值或保证所有自然措辞；最终自然度仍由 Rex 验收。
