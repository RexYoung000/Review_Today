## 新检查如何工作

[evidence_gate.py](evidence_gate.py)先核对批准记录的来源和路径集合，再核对原 753 条历史证据。632 条仍按原路径及哈希严格核对；121 条在原路径缺失时使用固定私有目录中的 82 份同哈希对象，并在结果中逐条保留 `original_path_missing=true`。例外范围增加、原文件内容变化、副本丢失／变化／移位或符号链接均拒绝；存在一份正确副本不能掩盖被改动的原文件。

[entry.py](entry.py)是新批次准备前使用的完整离线保护入口。它对 319 个现有源码／配置／入口输入、7 份正式数据、9 份执行依赖、原有和自有各 8 模块、17 份原始备份、旧证据和停止目录分别执行原路径检查。同时核对原有解释器与库目录的两个链接目标。当前运行目录出现新增、缺失或内容变化、链接目标变化仍停止；其他严格组按既定指纹核对，没有采用历史副本例外。

```sh
PYTHONDONTWRITEBYTECODE=1 agent-service/.venv/bin/python -B docs/evidence/2026-10-26-historical-copy-gate/entry.py
```

加 `--json` 可读取完整离线回执。该入口只检查保护条件，没有恢复 App、启动服务、批准额度、修改数据库或激活旧批次的操作。未来新的启动准备需复用 `entry.check()`，再建立自己的 UUID、运行目录和授权；不继续调用已冻结旧 `common.unchanged()` 作为新规则入口，也不修改旧记录让其显示通过。
