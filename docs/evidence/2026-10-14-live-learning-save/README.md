# EVAL-02：单条真实学习到保存验收

2026-10-14，Rex 确认决定 233，授权沿 [EVAL-01 八步建议](../2026-10-14-evaluation-coverage/README.md)进行一条真实 RAG 流程验证。**实际试跑在漏答阶段失败，已按约定停止。评分承认答案缺了题面要求的两块内容，却仍判通过，四个绑定知识点全部记为已验证，并显示包含未回答部分的知识卡邀请。** 整节理解仍未验证；没有实际保存知识卡，没有新增生产修复。

本批最多 30 次实际模型请求，启动探测、请求重试和后台请求都计入。发生产品流程失败或到达请求上限即停止并保留记录，未执行阶段列为未验，不为了通过重跑模型或扩大整改。

采用生产学习工作区、会话同步和现有知识卡入口；QA 仅增加隔离身份、独立磁盘库、请求观察和记录按钮。现有模型与供应商配置保持，空会话开始，无预置讲解、评分或知识卡。计划中的详情步骤只采用实际已保存卡片，知识写入、回执和详情本批未运行；模型、服务 HTTP 和原生状态分别取证。外部网页工具不属于本场景，出现相关调用另记；完整 VoiceOver、所有主题语义稳定率及 Rex 体验不由本次单条验证代替。

## 发现：普通题只回答一部分，却认证了整个绑定范围

本题明确问来源和生成两类风险，并询问为什么要核对来源和适用条件。实际只回答：

> 相似度高只说明资料与问题在语义上接近，所以可能相关；但原资料仍可能有错误或过时。

真实评分的 `completeness` 明确指出没有说明生成风险，也没有说明核对条件的原因，结论为不完整；同时返回 `passed=true`。系统随后把「检索相似度」「来源资料可靠性」「生成忠实性」「适用条件核对」全部记录为 `verified_concepts`，并创建四项范围的 v1 邀请。预览包含未回答的生成风险与条件核对。内容本身可来自正确讲解，但正确讲解不能证明用户已回答这些要点。

这是本批验收的阻塞问题：答题后的邀请应对应实际有效检查，本次触发点与通过范围超出了用户答案。确认不是原生视图自行伪造状态；服务已提交上述范围，界面按它显示。整节仍为 unknown、邀请仍显示未保存、复习默认关闭，这些边界保持，没有真实卡片被错误写入。

源码路径：

- [评分入口](../../../agent-service/agent_service/conversation.py)在题目有效、绑定有效且未用提示时采用 `result.passed`，随后把完整 `binding.concepts` 记录为验证范围。
- [完成守卫](../../../agent-service/agent_service/learning_progress.py)对综合题核对冻结要求与答案引文；普通概念题清除整步完成标记后返回，不独立核对题面缺项与 passed 的矛盾。
- [邀请形成](../../../agent-service/agent_service/knowledge_invitation.py)采用已通过评价与概念范围，并核对讲解引文来源。这能证明知识来自讲解，不能证明用户完整作答。

本次只复现一个真实主题和一个漏答答案，不报告通用误判率。之前 EVAL-01 的受控流程与 TARGET／SCOPE 整节守卫仍按原覆盖范围成立，不能据它们把本次真实失败改成通过。

## 请求、隔离与准备问题

本批 **13 次确认实际模型请求、45,159 个供应商报告 token**：8 次启动模型／强度／流式探测，3 次第一轮路由与教练（包含一次重新生成），2 次漏答路由与评分。没有额外独立核验 Agent，没有换模型或供应商；报告 token 不直接转换为费用。全部 13 个请求身份均有用量回报。

首次 QA Python 别名缺虚拟环境元数据与依赖，导致导入失败，此时请求为 0；只修 QA 目录接线。之后真实探测成功，但按 host 过滤的运输观察没有捕获 SDK 路径；原计数失败及 8 次真实用量保持在 [probe-requests-initial.json](probe-requests-initial.json)。观察改接生产请求身份入口，在每次 SDK 调用前计入本批预算，供应商 SDK 关闭自身重试，服务重试／回落仍各自进入该入口；调用前异常保守计数，不假称已经上网。本批后续五次均由对应真实用量确认，最终仍为 13。

修正观察时只复用同批、同配置刚完成的真实探测结果，避免重新花费八次；没有替换教学、路由、评分或知识生成结果。旧测试监听器按其确切隔离工作目录关闭后，由当前 QA 重新托管服务。此复用属于 QA 启动条件，不证明一次全新冷启动探测链。记录入口见 [audit_runtime.py](audit_runtime.py)与 [NativeLiveQA.swift](NativeLiveQA.swift)。

请求预算的首次 host 过滤自检虽通过，不能覆盖本次 SDK 路径，原记录保持为 [budget-selfcheck-initial.json](budget-selfcheck-initial.json)；最终 [budget-selfcheck.json](budget-selfcheck.json)在实际 `parse_model` 请求入口以合成 SDK 回包核对第 30 次可进入、第 31 次被拦，另一个新进程不能重置计数，自检没有远端调用。真实试跑没有用这些合成回包。请求与原始模型输入／输出见 [live-events.jsonl](live-events.jsonl)，元数据、各边界与散列见 [review.json](review.json)。

QA 支持模块复用同日 EVAL-01 新编译的生产模块，其后生产 Swift／Python 源码未变；本次独立原生入口另编译、签名并运行。初始与最终都在独立磁盘库，同一空会话开始；七个日常数据库／附属文件的字节摘要、日常 App 二进制、供应商配置、178 个生产文件及既有工程差异保持。QA 窗口及其托管服务已关闭，请求计数冻结在 13；本轮没有日常 App 更新或最终发布。

原生检查使用 `apple-ui-review` 的 UI Review 契约，证据限本次实际浅色窗口、输入、答题反馈、收起学习安排、滚动及错误邀请。预览基础结构可见，但这个生成标题拼接四个概念，部分要点重复，属于另行内容审阅观察；本轮不据此更换布局或字体。完整 VoiceOver、浅深色／窄窗／减少动态与完成提示的动效、保存详情体验均未运行，不提升为体验验收通过。

## 建议下一步范围

只修本次普通题漏答误判：按题面明确询问的内容核对独立作答；必要内容缺失时保持待补答，不把完整绑定范围记为已通过，也不触发通过后的知识卡邀请。保留已答对部分的反馈、补充问题、主动保存入口、整节综合规则及现有模型配置，不新增独立评分调用。**这是待对齐建议，本轮没有实施。** 修复后先用本次冻结失败输出做受控回归；若另获授权，真实复验仅在原 30 请求总上限剩余的最多 17 次内针对该缺口运行，失败或到限即停，不覆盖未运行的完整保存链。旧失败保持不改，后续未验阶段继续开放。

授权和续接位置见[工作状态](../../work-status.md#eval-02)。
