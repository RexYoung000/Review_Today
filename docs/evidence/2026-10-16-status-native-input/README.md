## 实际操作与证据

- 从真实保存四卡的原生数据库和后台检查点各复制一份，保留原迁移标记、附件、回执、历史和事件位置 130，不伪造保存结果。生产 Swift 源码和此前支持模块散列一致，独立原生入口编译、签名校验通过。
- 本地服务由正式 `AgentServiceMonitor` 托管，正式 `LearningWorkspace` 输入框输入原句、按 Return 发送；`ConversationSync`、本机处理循环和服务 Harness 正常运行。不是向原生直接注入新事件页。
- 模型路由只冻结原真实输出。健康状态的可用标识由测试入口提供，凭证仅为本进程无权限占位值，不代表真实模型可用性；探测关闭、SDK 客户端和外部连接均被禁止。两个防护入口在独立自检中均于请求前阻断，见 [防护自检](guard-selftest.json)。实际服务没有触发禁止入口。
- 后台仅收到一次消息 POST、一次冻结路由；形成一条新用户消息、一个 completed Run 和一条正确四卡回复。原生输入框清空且保留焦点；界面与新进程磁盘中的用户身份、客户端身份、Run、回复身份与后台一致，无重复消息。
- 新进程磁盘读取确认用户输入已 `accepted`，回复 `received`／`complete`；原四卡身份、内容、题目、来源身份和复习开关与原真实保存结果完全一致。原任务、邀请、草稿、待处理与旧历史保持，没有新保存回执。

完整断言见 [结果](result.json)、[收尾核对](finalize.py)与[日志](finalize.log)；实际原生输入和回复见 [输入状态](phase-02-input.txt)、[完成状态](phase-04-completed.txt)、[截图](phase-04-completed.png)，服务接收见 [本地 HTTP 记录](service-audit.jsonl)，持久化见 [新进程读取](native-disk-read.json)。
