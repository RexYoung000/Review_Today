## 失败定位与证据边界

[实际原生截图](native-preview-failure.png)及[可访问文字](native-preview-failure.txt)显示：答题反馈准确，邀请题名为“生成不忠实于依据资料、来源与适用条件核对”，正文仅一句范围说明及“未保存”，要点／总结缺失。服务 [complete-answer-final.json](complete-answer-final.json)同样只有范围说明，邀请 v1 没有 `preview_points`／`preview_summary`，Run 的 `capture_preview=null`；不是前端收到了完整结构却漏画。

保留的真实**解析后** MasteryEvaluation 为 passed=true、capture_preview=null，已选讲解引文两条、反馈引文一条全部有效。零新增请求的[组件回放](preview-diagnosis.json)确认：原输出通过现有请求校验；空预览进入邀请后产生空结构字段，原生按既有兼容行为退回范围说明，没有进入一次自动修复。使用同一真实片段构造的两要点／总结能通过来源检查，但这只是对照数据，不能当作模型实际生成成功。

当前提示规则已经要求“有可靠片段时同时给出预览”，类型和校验仍允许空值；字段结构无效时也会归一化为空。观察层只保留解析后对象，没有供应商原始 JSON，**不能断言原始回包究竟是 null、遗漏字段还是格式无效**。可以确定的是：这次程序把空结构直接当作兼容降级，没有补齐用户约定的基本呈现。实际源码链见 `schemas.py:MasteryEvaluation.safe_capture_preview/validate_request`、`capture_preview.py:optional_preview/replace`、`conversation.py:_evaluate` 与 `knowledge_invitation.py:published`，源码未修改。

这与 KT-04 已修的“同点更新返回了预览但引文越界”不同：本次是首次答题通过邀请，进入邀请前结构已经为空。未运行新的产品测试或扩大实现。
