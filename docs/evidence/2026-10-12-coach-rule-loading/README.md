## 四次真实模型组件对照

仅用合成 RAG 材料，以现有 DeepSeek 教练配置、`none` 执行强度分别生成旧／新普通回答和旧／新教学，各一次真实传输。输入相同，未调用网页、卡片生成／保存或原生 App；两次教学共用原有非空检查绑定附加规则。输出、字段检查与实际用量见 [原始样本](real-samples.json)，人工复核见 [样本复核](sample-review.json)。

- 普通回答新旧均为一句定义，没有课程或检查题，内容忠于材料；该样本不能证明原来普通回答一定跑偏。
- 新教学先定义，再给地图和第一步讲解；题目、第一步标题、概念和讲义引文通过既有结构／绑定检查。
- 旧教学一次在 `check_binding` 依据核对失败，诊断为 `teaching_check_grounding`。这是单次生成组件，没有执行 Harness 既有修复流程；不能因此推算实际产品旧版失败率或新版稳定率。
- 新教学把题目范围标为 `step`，但题目未明确逐项要求第一步条件中的三个模型限制。因此不能把结构检查通过写成“完整覆盖整节”或教学质量全部通过；本轮没有评价用户作答或建立掌握证据，评分契约未改变。
- 初次记录脚本在验证后才保存完整输出，旧版失败的完整对象未写入；字段诊断与用量保留。脚本已改为先记录输出，没有为了得到通过结果重跑模型。

新版两个固定场景的结构检查通过，不宣称一般回答质量、延迟或费用改善；整理、澄清、评分实验和邀请更新只做了受控请求检查，完整原生链路仍未验证。
