# 切页性能与代码健康检查

状态：代码已实现，原生 19 组契约、服务 288 项受控测试与 Debug／Release 构建通过。原生日历版已完成小／压力样本前台采样与菜单、草稿、日期跳转、深色和窄窗口检查。压力采样进一步发现活动 Query 随切页重复读取，已改为数据观察器；此最后增量的真实界面复测再次被 Mac 锁屏阻塞，本机日常应用文件已更新并严格验签，旧构建已备份；尚未启动验收。

## 发现与处理

- 应用内存在明确的重复工作：Today 多套候选网格反复计算日期／活动，切页重复补录与通知调度，编辑器无变化时重新测量和保存，后台同步按每个会话重复全表查询。
- 活动改为窗口内独立观察、数据变化时投影、按日期／时区／语言缓存一份值快照；最终观察器使用同一 ModelContext 的保存通知处理集合变化，并跟踪已投影模型的相关字段，普通切页和草稿保存不重新读取活动；固定 26 周原生日历按钮保留日期提示、可用性、无障碍角色和准确跳转。全部历史的连续学习统计保留。
- 当前 Agent 与侧栏／最近学习状态使用会话范围查询；同步每次唤醒共用索引，只启动有实际待办的发送与控制任务。草稿跳过无变化写入，失败保留原归属并允许重试；编辑器焦点与高度局部更新。
- 工具栏采用一组控件的自适应布局；菜单显示状态用无动画事务。并未以延长动画掩盖计算，也不保留隐藏业务页面改变原卸载规则。

机器实查为 Apple M5、10 个逻辑核心、32 GiB 内存，`memory_pressure -Q` 报告可用比例 58%。采样期间另有较高 CPU／WindowServer 负载，不能根据绿色内存压力排除调度或绘制竞争，也不能计算这些负载各自对卡顿的贡献。原生调用栈中仍有 SwiftUI／AppKit 布局与类型处理，见 [调用栈摘录](native-profile-excerpt.txt)。
