# KT-05：首次知识邀请缺结构预览修复

决定 **253** 已获 Rex 明确确认；本批只实施缺失预览与既有一次修复的交接，先离线复验。原真实验收决定 252 的 **15／40 模型、0／16 网页、STOP、余 25 冻结**保持。当前完成的是程序修复和受控检查，尚无新真实模型或原生结果，不关闭 M1／完整连续链。

## 修了什么

原[真实失败](../2026-10-21-continuous-learning-real/README.md)中，完整补答实际通过，有两条讲解选段和一条反馈选段，但解析后的 `capture_preview=null` 被静默接受，首次邀请只显示题名和范围。原 SDK JSON 未留存，无法区分原始缺失和格式异常后归一化为空；本修复针对可确定的程序交接缺口。

- 当前答题实际通过、题目有效、无提示、绑定当前检查，仍有未邀请概念且显式选出可靠讲解片段时，首次预览须同时有要点和总结。缺失、null 或格式异常归一化为空，返回固定字段诊断，交给现有一次修复。
- 修后逐项核对要点／总结的引文属于本次所选讲解或反馈片段，并排除重复要点；不能借用全文其他段落，也不能撤掉讲解选段绕过检查。
- 所有格式错误共用同一步一次修复上限。第二次仍缺结构、来源越界或来源消失时，沿用回复未完成处理，不发布邀请、不保存、不尝试第三次。
- 普通／评分评价沿用程序既有通过门槛；Jev 反馈使用程序的有效通过结果。未通过、提示、无当前绑定、无新概念、旧数据或没有明确可靠选段不因本修复增加请求。初次已有合法结构但引用失败的原降级规则、同点更新、版本、保存确认和真实回执规则保持。

四份生产 Python 变更：`capture_preview.py` 校验、`schemas.py` 普通／评分接入、`judgment_grading.py` Jev 反馈接入、`conversation_model_call.py` 在原修复内传递上下文。没有新增模型节点、改变供应商或修改原生 UI／字体。规范在 [Harness](../../agent-harness-v2.md#initial-preview-repair)及 [DESIGN](../../../DESIGN.md#knowledge-save-invitation)，进度在 [KT-05](../../work-status.md#kt-05)。

回放从真实 `partial-complete.json` 的补答前状态恢复到新临时数据库，输入同句真实完整补答。意图采用原真实判断，第一次评价返回原真实空预览，第二次是明确标记的受控输出；不是新模型生成，也不是把原真实失败改成成功。四组分别为：

1. 有效修复：HTTP 输入／事件均 200，原反馈正文与四条旧消息保持；当前 v1 邀请与反馈同锚点、两要点与总结来源有效，只发布一次，完整卡生成未调用。
2. 第二次仍缺预览：原一次修复耗尽后失败，无第三次请求槽、无邀请。
3. 第二次引用全文中未选的段落：固定到具体引文字段，失败后无邀请。
4. 第二次撤掉所选讲解片段：固定到来源字段，失败后无邀请，不通过绑定回退产生假完整预览。

四份 `*-events.json` 是本机 TestClient 返回的生产公开事件页，含恢复现场的旧真实历史及新增受控记录；不能将其中调用槽或预算估计当作新上游用量。`replay.log` 和 `replay-result.json` 明确分开受控调用与实际模型请求。

检查时清空模型／网页凭据，禁用检索与启动探测，外部连接和非临时 SQLite 受审计保护；没有启动 App／日常服务。本批实际新增模型 **0**、供应商网页 **0**。

## 执行修正与限制

首次定向命令误用了不存在的测试文件名，未运行测试，改用现有文件。随后三项旧测试失败，来自两处模拟评分样本：已选可靠来源，却没有提供新规则要求的预览；补齐有效预览样本后，原范围和调用次数断言保持。留存回放第一次误按事件顶层取邀请，断言失败，改为实际 `payload.capture_offer` 后通过，没有修改产品事件结构。补充来源撤掉边界时主动中断前一轮全量检查（336 passed／4 skipped／89 subtests，不作为完整通过），保留在 `interrupted-*`；最终全量重新执行。

本批没有新真实模型生成、真实异常修复、原生新输入／显示／保存、日常服务加载或完整链验收。引用检查只能证明连续引文位于所选片段，不能替代语义忠实或外部事实核验。旧缺预览记录不会被重写，也未尝试改善旧数据的字体／排版。
