# 保存查询与来源标签：展示修正（2026-10-21）

**决定 256 已实现，离线与原生组件复验通过，日常 App 未更新。** 本轮真实模型／网页请求均为 0，所有原 STOP 和冻结余量保持；没有新增知识、复习、来源迁移或保存授权。用户在前轮建议收简状态回复、修正来源标签后回复「继续」，本次按既有简洁表达与真实来源原则作最小修正。

## 用户看到的变化

明确查“这次保存了几张、分别叫什么”，且程序已选中本次操作并核对真实回执时，回复从 166 字收简为 57 字：

```text
这次已成功写入 4 张知识卡。

1. 检索相似度
2. 生成不忠实
3. 核对来源与适用条件
4. 适用边界丢失
```

不再固定追加范围、旧卡参考和覆盖备注。原先的数量／名称已正确，本次只改变对应成功分支的表达；未确认、失败、失效和“刚才讲过的内容是否全保存”仍按原守卫处理。现有最多八个名称的投影保持，名称不足时明确剩余张数及到知识库查看，不把可见部分当成全部。

详情没有可打开的来源链接时，原来的“来自你提交的原文”改为“来源摘录”。没有 URL 不能证明作者是谁；本次使用中性标签，没有新增作者推断或来源元数据。实际链接、引文内容、知识库数据及字体布局保持。

原生复验发现，编号列表视觉正常，但辅助功能树漏了四个名称；在现有正文渲染器的列表项补充实际编号和内容的明确标签后，四项均进入 AX。这是本次列表展示的可访问性补修，不新增字体或交互。

## 测试壳的问题与修正

初次 QA 应用标识缺少既有 `.NativeQA` 后缀且端口不在隔离范围，被原运行守卫拒绝，日常库未打开；随后副本未带原迁移标记，初始化失败。修正测试壳参数并随已迁移的库复制现有标记后，命令行 `--check` 确认四卡和正文可读，再进行 UI 操作。相关 [首次守卫记录](native-initial-failure.json)、[副本修订记录](native-copy-initial-failure.json)保留，没有改产品守卫或绕过权限。

最初受控回放把导入前任务与经过既有 Store 归一化后的任务直接比较，断言失败；改为比较同一隔离 Store 导入后的操作前／后，数据保持通过。原日志见 [replay-initial.log](replay-initial.log)。原生合同脚本首次缺执行位，改用 `bash` 执行，未改变文件权限；日志另留。初版 QA 的外观和缩窗按钮没有实际改变内容，最终改为本测试壳局部环境与自有窗口尺寸；初版画面不计作深色／窄窗证据，最终截图尺寸与显示另核。
