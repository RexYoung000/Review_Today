# A014–A016 运行控制、资源边界与用量

## 原始现象与证据范围

2026-09-17 用户报告运行中切换思考强度后卡住，以及找下载资源偏离学习教练。只读核对日常数据库与客户端完整 194 条事件：找链接一轮 156.554 秒；深入→智能后约 61 秒才重新开始；共 10 次模型调用尝试。本地估算输入 185,837，整会话 22 次 / 299,020；均不是实际计费 token。原记录没有供应商 usage。最终返回百科/书评链接，并产生 explained 学习记录。

原始聊天保留在用户本机，不复制整份会话或改写历史。案例使用书目推荐→询问代找/下载→仅给链接→继续的最小合成上下文。运行并发使用可控挂起传输，不以普通文本回放冒充并发验证。

## 已实现

- **运行控制**：强度在第一次执行时固定；切换只影响下一轮，不递增本轮版本或取消重跑。停止/补充的失效版本及时释放调度，迟到正文被拦截。后台传输最多全局 8 个、每轮 2 个，槽位保留到真实退出；占满时暂停并允许稍后重试。
- **范围**：已有意图调用区分资源获取与知识理解。纯下载资源代办短回复，无网页、目标、录入、学习证据。保留引文、否定代办、知识解释及明确操作；混合请求只使用本轮明确知识片段。旧助手承诺不能成为本轮代办授权。
- **用量**：逐模型步骤记录供应商 input/output/cache/reasoning usage；未知与部分返回分别标记。迟到用量仍可记账，不发布旧内容或复活删除会话；事件 ACK 不删除账本。界面未新增费用展示。
- **预算**：整轮最多 12 次调用尝试、累计估算输入 512,000、等待 180 秒；各步骤及网页原有限制同时生效。补充不清空预算；显式重试开启新预算段，旧账本保留。后台摘要另用维护预算。
- **证据输入**：普通核验最多两份有效来源，交叉核验最多三份，最多两次评估并在够用时停止；可选 Context 片段同样限定纳入数量。回答的公开正文节选每页最多 4,000 字符、合计 12,000，标记节选，原文与用户材料保留。

真实固定场景包括能力询问、助手曾承诺后只要链接、继续代办、下载与流式原理、引用“找下载链接”、否定代办后问知识、资源+知识混合请求。混合场景额外断言实际进入范围处理，避免仅看最终 intent=none 而误判通过。

初轮人工阅读发现混合回复把正常书目推荐也写成不支持，已收窄回答约束并复测。仍有知识解释过度概括的样本（如把“下载”笼统等同于收完才使用）；本轮通过的是范围路由与执行断言，不是逐句事实正确率，保留原输出供后续质量评审。

纯资源请求实际各只有 1 次意图调用：6,352–6,493 输入、324–350 输出 token（复测，供应商 usage）。合法学习检索单样本 22.790 秒、5 次模型调用、17,134 输入 / 1,198 输出；追问 4.494 秒、3 次调用、12,238 输入 / 645 输出。输入含缓存部分，缓存/思考明细见原记录；这里不换算价格，不将不同问题或上下文的数值当成节省率。

[初次](controlled-initial.txt)和[第二次](controlled-second.txt)受控失败记录保留。全量测试初次发现长上下文摘要失败场景会触发新整轮上限：摘要失败后的原文 fallback 不得绕过预算。原“发布后不重复回答”专项仅在测试中放宽整轮输入上限以单独验证该契约，默认预算拦截另有测试。第二个失败来自同一测试连续回放命中已有来源缓存，已拆开独立场景；没有移除实际读取与评估次数断言。
