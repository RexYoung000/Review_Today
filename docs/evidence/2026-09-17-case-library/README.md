## 核对发现与处理

| 缺口 | 本轮处理 | 边界 |
| --- | --- | --- |
| 文档要求完整案例，但没有入库校验 | 严格结构和文档编号/实际测试符号核对，加入日常受控回归入口 | 结构通过不能证明语义正确 |
| 截图、合成状态和原始上下文混在一起 | 13 条逐项注明已知信息、未知信息、来源和验收状态 | 不补造已经丢失的原始历史 |
| 合成任务状态和讲解前文可能互相矛盾 | 当前任务必须关联到具体消息，补足与已讲步骤一致的前文 | 自动检查引用存在，语义一致性仍需维护者审阅 |
| 真实回放每次重新生成前文 | 19 个静态场景，给定前文与任务状态后才调用真实模型；每个场景独立数据库 | 固定语义基线不替代多轮体验或原生测试 |
| 只检查无异常/不建任务，容易漏掉答非所问 | 固定场景强制正向行为断言；实际状态、回复和人工评审项同时入报告 | 自然度和知识准确度仍需人工判断 |
| 结果缺代码/提示词/模型版本与实际输入 | 新报告记录文件摘要、模型名、实际提示词摘要、完整模型输入/结构化输出及前后状态 | 服务方模型权重版本不可控；不是逐字输出保证 |
| 缺结果、异常中断或误选案例可能被当通过 | 未执行/未知/重复/空选择失败；每轮写盘、结果不覆盖；异常保留缺失清单 | 中断而没有末尾 summary 的文件也不是通过证据 |
| 受控、真实路由、固定路由回答、原生与用户验收混用 | 固定与生成式报告分层，A012/A013 多轮脚本接入同一记录器；全部保留待 Rex 验收 | 其余历史脚本仍为旧格式，不倒填元数据 |

## 运行方式

离线门槛（不调用模型、不导入服务、不打开数据库）：

```sh
cd agent-service
.venv/bin/python tests/run_case_library.py
```

常规受控测试入口保持 `bash agent-service/run-controlled.sh`，已先执行该门槛。本机 pytest 安装位置沿用之前的临时依赖，可通过 `PYTHONPATH=/tmp/review-today-topic-test-deps-20260915` 运行。

固定场景真实回放：

```sh
cd agent-service
.venv/bin/python tests/run_case_library.py --live \
  --cases A013 A012-history-to-companion \
  --output /tmp/review-fixed-new-run.jsonl
```

`--cases` 接受可回放的案例或场景编号，输出必须是新文件。A002/A003/A004/A008/A009 的专项场景尚未接入此简化对话执行器，不能用这些编号获得“空通过”。它们的受控、网页、事务或原生检查仍在目录中逐项映射。待保存稿、绑定操作不支持时会拒绝字段，不会悄悄忽略。

重新生成前文的多轮流程：

```sh
cd agent-service
.venv/bin/python -m tests.topic_transition_real_smoke --live \
  --output /tmp/review-transition-flow-new-run.jsonl
.venv/bin/python -m tests.social_dialogue_real_smoke --live \
  --output /tmp/review-social-flow-new-run.jsonl
```

两类回放均使用临时数据库和合成/脱敏输入；模型路由与回答真实，网页搜索、正文读取和知识写入被阻断并计入失败，不能拿此结果宣称外部工具成功。新报告逐轮保存，`automatic_result` 与 `language_review`、`rex_acceptance` 分开。

结果复查也可离线执行。失败返回非零；空文件、截断、漏跑、重复记录、缺元数据或结论与实际执行不一致都会拒绝：

```sh
cd agent-service
.venv/bin/python tests/run_case_library.py --report /tmp/review-fixed-new-run.jsonl
```

新增案例：先在迭代文档登记并对齐预期，再在 `catalog.json` 写清现场已知/未知信息、预期与禁止行为、现有测试位置和未覆盖部分。可回放的对话追加到 `scenarios.json`，明确是原始脱敏还是合成、逐字前文、本轮输入和初始状态；当前任务须填写 `task_history_index`，人工核对这条消息真的包含所声明的计划/讲解。使用结构门槛检查后再运行对应受控和真实回放，不修改旧结果。当前数据全部为合成回归场景，来源缺失的信息没有被伪装成已还原。

初轮问题：`A013-current-plan-next` 的任务状态写着“资料切分与建立索引已讲完”，前文却只解释 RAG 定义。模型虽看到了计划，仍反问下一内容。不能据此断言产品回归。修正夹具，使前文包含明确学习请求及第一步讲解，关联原消息、任务和步骤后，该场景真实输出“接着看第二步：检索与重排”，暂缓与学习支持场景也通过。未改产品路由或提示词，未放宽原断言；初轮失败保留供审计。

人工抽查：陪聊转场没有重提记忆限制；无计划转场只问下个主题；有计划进入第二步；明确恢复旧目标与无记录情形分开。这里检查的是行为是否符合案例。知识准确性和话术自然度未获得完整人工验收：例如生成式第1轮仍把生成过程粗略表述为“一个字一个字地猜下一个最可能的词”，不能用行为断言的 PASS 代替教学内容质量结论。

所有新报告保留实际 provider/model、输入与状态、场景摘要、提示词摘要、模型结构化结果及代码文件摘要。测试在提交前运行，因此报告中的 commit 是父提交且 dirty=true；文件摘要才是当次测试工作树的准确依据。报告没有声称服务端模型权重固定，复测输出仍可能变化。

受控控制台日志仅清理行尾空白；JSONL 回放记录保留原输出。
