# Review Today 最小闭环与渐进式里程碑

> 文档状态：当前执行基线
> 当前原则：先验证最小命题，再逐层向外叠加；长期愿景不等于当前施工范围

## 1. 当前只验证什么

里程碑一只回答一个问题：

> 用户给出一段知识内容后，系统能否形成一张忠于原文、可以被提问和判断的知识卡，并正确区分用户的正确与错误回答？

首轮采用**纯文字闭环**：文字知识输入、文字问题、文字回答。语音、排期、通知、网页核验、复杂 Harness 和 Agent 动画都不能成为本轮通过的前置条件。

最小路径为：

```text
输入一段知识内容
→ AI 提取知识卡、问题和评分关键点
→ 系统展示一个问题
→ 用户用文字回答
→ 评分模型根据原文证据与评分关键点判断
→ 返回判断和简短原因
→ 用户可再答一题或重试
```

## 2. 项目当前真实基线

当前仓库已经超过“只有框架”的阶段：

- SwiftUI Mac App 已包含文字／链接／语音采集入口、知识库、待处理、复习、通知、FSRS 和吉祥物相关界面或 POC；
- 本机 FastAPI 服务已接入 OpenAI，并用 LangGraph 实现采集整理图；
- 文字内容可以被整理成知识卡、问题和评分规格；
- 文字回答可以连同评分规格提交给独立评分调用，返回 `again`、`hard` 或 `good`；
- SwiftData 已有来源、知识、问题、采集任务、复习会话和复习记录模型；
- macOS Debug 构建可以通过，本机服务健康检查正常；
- 已用真实模型跑通一次服务级最小链路：生成 1 张知识卡，正确回答判为 `good`，错误回答判为 `again`。

但这还不能说明里程碑一已经完成：

- 真实模型只验证了一个样本，尚不能证明知识卡和判断质量稳定；
- 还没有自动化测试或固定评测样本；
- 尚未从真实 Mac App 入口完整验收“输入 → 卡片 → 提问 → 回答 → 判断”；
- 当前实现包含大量不属于首轮命题的外围能力，容易让调试目标失焦；
- 部分文档曾把目标架构写成已完成状态，与真实代码不一致；
- 当前服务任务和评分 ACK 主要保存在内存中，重启恢复、持久化 checkpoint 和严格事务仍未完成；
- 当前复习不是 OpenAI Realtime 语音闭环，主要是系统朗读加文字回答；
- 现有 Agent 运行记录只是基础事件摘要，还不是完整、可回放的 Harness。

因此，当前最合理的工作不是继续扩功能，而是把已有能力收口成一个可重复验证的文字 Demo。

## 3. 里程碑一：纯文字最小闭环

### 3.1 本轮必须保留

1. **单一知识输入**
   - 用户粘贴或输入一段已有知识内容；
   - 首轮以一段稳定概念为主，不要求网页、文件或语音。

2. **知识卡生成**
   - 标题；
   - 简短解释；
   - 来自原文的证据；
   - 一个可判断的问题；
   - 评分关键点与可接受同义表达。

3. **提问与回答**
   - 系统展示一个问题；
   - 用户直接输入自然语言回答；
   - 不要求用户按固定格式作答。

4. **反向判断**
   - 评分模型同时看到问题、原文证据、评分关键点和用户原始回答；
   - 返回结构化等级和简短原因；
   - 评分失败时不得把本题标成已掌握。

5. **基础循环**
   - 用户能在结果后重试或继续下一题；
   - 首轮不要求自动排期或每日提醒。

### 3.2 用户回答是否需要先结构化

当前决定：**不增加独立的“用户话术结构化”步骤。**

原因：

- 本轮要验证的是模型能否理解自然语言回答，而不是用户能否按 schema 作答；
- 预先结构化会多一次模型调用，并引入新的误差来源；
- 当前代码已经采用合适的最小方式：保留用户原始回答，同时把问题对应的评分规格结构化，再让评分模型输出结构化判断；
- 即使以后改成语音，语音转写也先作为自然语言原文进入同一评分链路。

首轮只保存必要上下文：`knowledge_id`、知识版本、问题、原始回答、是否使用提示、模型判断和简短反馈。

只有后续评测证明以下问题真实存在，才考虑加入轻量抽取：回答非常长且跑题、需要逐项显示关键点覆盖情况、评分成本或延迟明显过高、多个模型之间必须传递稳定字段。即使加入，也应保留原始回答，结构化结果只能作为辅助证据。

### 3.3 本轮明确不作为验收项

- 语音输入、Realtime、VAD、打断和转写纠错；
- 网页抓取、联网核验和冲突处理；
- FSRS、每日通知、菜单栏和五分钟正式会话；
- 完整知识库管理与复杂待处理流程；
- 通用多 Agent、工具市场或可配置工作台；
- Harness 扩展、完整回放系统和复杂流程可视化；
- 吉祥物全状态动画、口型系统和 Spine Rig；
- iOS、同步、登录、远程部署和商业化。

这些已有代码或 POC 不必立即删除，但在里程碑一完成前冻结，不继续投入，也不计入是否通过。

### 3.4 通过标准

以下条件同时满足，里程碑一才通过：

1. 从真实 Mac App 输入一段知识内容，服务返回至少一张可查看的知识卡；
2. 卡片的标题、解释、证据、问题和评分关键点都能对回原文；
3. 从卡片进入一题文字问答，不需要手工拼接口数据；
4. 对同一题分别提交一个正确回答和一个明显错误回答，得到符合预期的判断；
5. 判断结果包含简短、可理解的原因，模型失败时不产生错误的成功记录；
6. 用户可以重试或继续，形成最基础循环；
7. Rex 在真实 App 中完成一次视觉和交互验收。

部分正确、同义表达、遗漏限定和常见误解等边界质量进入里程碑二，不阻塞第一条纵向链路。

## 4. 后续里程碑建议

### 里程碑二：知识与判断质量验证

目标不是扩页面，而是回答“这个闭环是否值得信任”。

- 建立小型固定评测集，覆盖事实、概念、程序三类知识；
- 每题准备正确、部分正确、错误和常见误解回答；
- 评估知识拆分、问题可答性、关键点覆盖和评分一致性；
- 优化提示词与结构化契约，形成可重复运行的 evaluation harness；
- 明确失败样本和质量门槛，再决定是否进入语音与长期使用。

**完成门槛：**同一批固定样本可重复运行，主要误判有归因，核心质量达到 Rex 愿意用于真实知识测试的水平。

### 里程碑三：架构与 Agent Harness 收口

当前不建议“扩大架构”，而应先让架构服从已经验证的真实流程。

- 画出实际运行而非愿景中的采集、提问和评分流程；
- 明确哪些步骤由 LangGraph 编排，哪些步骤应是普通确定性程序；
- 补齐稳定状态、错误码、幂等、持久化 checkpoint、事件记录和恢复；
- 让产品进度与开发运行记录读取同一事实来源；
- 为固定评测、故障重放和工具调用建立最小 Harness；
- 不建设通用多 Agent、插件系统或未经需求验证的扩展层。

**完成门槛：**关键路径可以解释、重试和恢复，流程图与代码一致，服务重启不会静默丢失进行中的任务。

### 里程碑四：语音闭环验证

在文字评分可信后，再单独验证语音是否提高体验而不是制造噪声。

- Agent 播报问题；
- 用户语音回答并得到可纠正的转写；
- 转写文本复用已经验证的评分链路；
- 提供文字降级；
- 记录延迟、转写错误和语音是否真的降低操作成本；
- 界面只需“聆听／思考／反馈”等最小状态，不要求完整 Spine 动画。

**完成门槛：**语音链路不会明显降低评分正确性，失败可回退，Rex 认为语音比纯文字更适合核心场景。

### 里程碑五：短周期真实自用 POC

先做短周期试用，再决定是否直接进入原计划的 21 天验证。

- 使用真实学习内容，而不是专门制作的演示材料；
- 观察输入意愿、复习完成、知识卡修改和评分改判；
- 区分内容质量、交互负担和技术故障；
- 短周期通过后，再启动 `poc-validation.md` 中的 21 天验证。

**完成门槛：**Rex 愿意持续使用，且主要问题可通过产品迭代解决，而不是核心机制本身无价值。

### 里程碑六：Agent 表现层与 Spine

吉祥物和动画属于体验放大器，不是核心正确性的证明。

- 先定义 Agent 在不同状态下需要传达什么；
- 先用静态状态或低成本动画验证可读性；
- 再决定是否投入完整 Spine Rig、嘴型、打断和情绪反馈；
- 动画只读取真实系统状态，不能维护另一套假状态。

**完成门槛：**动画能提高状态理解、陪伴感或使用意愿，而不是只增加制作与维护成本。

### 里程碑七：整体优化、载体与 UI 重整

- 根据真实使用路径删掉低价值入口和状态；
- 重新判断“今天、知识库、待处理、复习窗口”是否仍是最佳信息架构；
- 决定继续以 macOS 为主，还是需要 iOS、菜单栏或其他载体；
- 优化视觉层级、响应速度、无障碍和输入成本。

**完成门槛：**界面结构来自真实使用证据，而不是在验证前提前设计完整产品。

### 里程碑八：产品化与发布准备（条件性）

仅在真实自用验证通过后启动：

- 远程部署、账户、同步与数据迁移；
- 隐私、安全、日志和模型成本控制；
- 发布质量、崩溃与性能监控；
- Onboarding、定价和商业化验证；
- iOS 或其他平台版本。

这不是当前承诺范围，只是核心价值成立后的候选阶段。

## 5. 推荐推进顺序

```text
M1 纯文字最小闭环
→ M2 知识与判断质量
→ M3 Harness 收口
→ M4 语音闭环
→ M5 真实自用 POC
→ M6 Agent / Spine 表现层
→ M7 UI 与产品载体
→ M8 产品化（条件性）
```

两个关键门禁：

- M2 不通过，不扩语音、动画和复杂架构；
- M5 不通过，不进入大规模 UI 重整、跨端和商业化。

## 6. 下一步实施焦点

1. 把现有 App 中最短的文字入口、知识卡和文字答题入口串成唯一验收路径；
2. 用一个稳定概念完成真实 App 端到端演示；
3. 对同一题提交正确与错误回答并保存结果；
4. 记录链路中实际失败的位置；
5. 通过后再建立里程碑二的固定评测集。
