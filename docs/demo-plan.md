# Review Today 本机 Demo 实施与验收

> 文档状态：范围已确认，待实施

## 1. Demo 目的

本机 Demo 不是 21 天 POC，也不是可公开分发的 MVP。它先回答一个更基础的问题：

> 在同一台 Mac 上，Review Today 能否用真实 AI 服务把“记录 → 整理 → 提问 → 语音作答 → 判断 → 排期 → 主动提醒”完整跑通，并让 Rex 看懂 Agent 为什么这样运行？

Demo 通过后才开始 21 天真实行为验证；Demo 的一次成功演示不能替代持续使用数据。

## 2. 必须完成的能力

### 2.1 三类输入

- 文字：在主窗口或菜单栏直接输入。
- 公开网页：提交无需登录的 URL，读取正文并保留来源定位。
- 语音随记：录制后批量转写，再进入统一整理流程。

三类输入都属于 Demo 验收范围。实施顺序固定为文字 → 网页 → 语音，以便逐层定位问题，但不能用只完成文字输入宣称 Demo 完成。

### 2.2 真实 Agent 整理

- 使用真实 OpenAI Responses 调用完成结构化理解、知识拆分、题目与评分规格生成。
- 使用真实风险分类和联网核验分支，不用写死的假结果模拟。
- 至少展示一次不需核验的稳定知识、一次成功核验和一次证据不足或冲突进入待处理。
- 输出经过结构校验和独立语义校验；最多修复一次。
- 结果必须在 SwiftData 完整提交后才显示为完成。

### 2.3 两种试题路径

**立即试一题**

- 整理完成后可以立刻体验一个真实 Realtime 问题和 Responses 评分。
- 会话标记为 `preview`。
- 不受新知识两小时等待限制。
- 不更新 FSRS，不写入正式复习完成率和 21 天 POC 指标。

**正式复习**

- 使用 Mac 生成的固定候选快照。
- 新知识至少等待两小时。
- Realtime 负责语音交互，Responses 负责结构化评分，Swift 客户端负责 FSRS。
- 每题保存成功并返回确认后才进入下一题。

### 2.4 主动通知

- 用户设置每日提醒时间。
- 通知提供现在开始、15 分钟后、1 小时后和今日跳过。
- 每天最多稍后两次。
- 没有候选时不发通知并记录“无需复习”。
- 点击“现在开始”打开独立复习窗口；Python 服务不可用时要显示可恢复错误，不能丢失通知动作。

### 2.5 两种 Agent 状态表达

- 普通产品界面显示“读取网页”“正在核验”“整理完成”“需要处理”等用户状态。
- 开发模式的“Agent 运行记录”显示实际节点、分支依据、耗时、重试和失败点。
- 两者读取同一任务状态，不能分别维护两套真假不一的进度。

## 3. 本机运行边界

### 3.1 组成

| 组件 | Demo 职责 |
|---|---|
| SwiftUI Mac App | 界面、菜单栏、通知、录音、SwiftData、候选选择、FSRS 和最终写入 |
| 本机 Python 服务 | FastAPI、LangGraph、网页读取、风险核验、OpenAI 调用和短期 checkpoint |
| OpenAI Realtime | 实时语音提问、播报、VAD 和打断 |
| OpenAI Responses | 整理、风险分类、问题生成、语义校验和答案评分 |
| OpenAI Web Search | 风险触发后的联网核验 |

### 3.2 启动和网络

- Python 服务由 Rex 在终端手动启动，App 不负责安装、拉起或后台守护。
- 服务只绑定 `127.0.0.1:8742`，不监听局域网或公网地址。
- SwiftUI App 通过 `http://127.0.0.1:8742` 和同一主机上的 WebSocket 与其通信。Demo 不启用 TLS。
- 健康检查为 `GET /healthz`。
- App 必须显示服务不可用、连接中和就绪三种状态。
- 当前 Demo 不做登录或设备配对；如果未来迁移到远程服务，再单独设计鉴权。

首次启动预检按第 78 项执行：不做独立引导页；服务、Key 是否可用（不显示真实值）、麦克风和通知呈现在今天页顶部状态行。不含真实学习内容的模型链路测试只在开发模式提供。

### 3.3 密钥

- 标准 `OPENAI_API_KEY` 只存在 Python 服务的本地 `.env`。
- `.env` 必须被 Git 忽略；仓库只提交不含真实值的 `.env.example`。
- Swift 客户端不能读取、保存或打印标准 Key。
- Python 服务为 Realtime 会话签发短时客户端凭证；Swift 只接触短时凭证。
- 日志必须屏蔽密钥、Authorization 头和短时凭证。

### 3.4 数据

- SwiftData 是完整知识、版本、来源、复习历史和 FSRS 的唯一长期事实来源。
- Python 使用普通 SQLite 保存带 TTL（默认 24 小时）的短期 LangGraph checkpoint；任务完成或超时后删除内容。Demo 不加密该文件；加密留到部署阶段。
- Demo 不建立云端知识主库。
- Responses 请求禁用非必要的应用状态保存；外部平台仍可能按其数据政策保存安全日志，产品文案不得承诺第三方零留存。

## 4. Demo 界面范围

### 主窗口

- 侧边栏：今天、知识库、待处理。
- 今日记忆跑道：顶部服务与权限状态行、今日复习、快速采集、正在形成记忆、今天新增、今日复习结果。
- 知识库：按主题浏览、按掌握状态筛选、详情中纠错和管理。
- 待处理：冲突、校验失败和转写异常的统一队列，侧边栏显示未处理数量。

### 设置

- 独立 Settings 窗口，不是第四个侧边栏项。
- 一般：每日提醒时间、复习语言覆盖。
- 开发：开发模式开关、Agent 运行记录入口；开发模式可将知识标为到期或跳过两小时等待。

### 菜单栏

- 快速文字输入；
- 粘贴公开链接；
- 开始和结束语音随记；
- 查看最近任务状态并打开主窗口；没有最近任务时显示“还没有采集”。

### 独立复习窗口

- 正式复习与“立即试一题”共用同一单栏窗口，用标题区分是否计入排期。
- 当前问题；
- 聆听／思考／评分／反馈状态；
- “我答完了”、提示、跳过和文字回答；
- 答完后的转写、转写不对、掌握等级和用户改判；
- 暂停与恢复。
- 预览不显示 FSRS 或下次日期。

### 开发模式

- 从 Settings 或窗口菜单打开 Agent 运行记录，不进入侧边栏；
- 运行记录列表与单次轨迹；
- 节点、分支原因、耗时、重试、失败位置和结构化摘要；
- 不展示隐藏思维链或完整密钥。

## 5. Demo 明确不做

- 公共服务器部署、生产域名、正式账户登录或设备配对；
- iOS、同步、订阅、付费墙或商业指标；
- 全局快捷键、自动启动 Python 服务或安装器；
- PDF、图片、音视频文件导入和需要登录的网页；
- 本地大模型、离线 AI 或持续屏幕监听；
- 通用聊天、多角色 Agent 工作台和复杂知识管理；
- 21 天 POC 结论。

## 6. 端到端验收

### 测试证据层级

Demo 实施时同时建立三层证据，不能用其中一层代替另外两层：

1. **无密钥回放与快照**：用固定的 Responses、Realtime 和工具事件重放采集与复习路径，检查事件顺序、分支、结构化结果、失败恢复和脱敏记录；模型可见协议或用户可见结果发生变化时评审快照差异。
2. **真实本机入口测试**：从实际 App／FastAPI／LangGraph 入口启动组装后的系统，只替换外部模型或不可控网络，验证 SwiftData 写入、任务状态、重启恢复、重复请求和音频生命周期。手工调用某个内部函数不能替代真实入口。
3. **真实服务冒烟与体验验收**：用真实 OpenAI 和网页核验跑最小代表链路，再由 Rex 在原生 Mac App 完成视觉、语音、通知和恢复体验验收。

自动化断言必须重新读取 SwiftData、文件、任务事件或外部服务结果，不能只检查 Agent 回复中是否声称成功。每条关键运行时不变式至少包含一个会真实触发违规并预期失败的反向测试。

### 场景 A：文字到立即试题

1. 输入一段稳定概念。
2. 观察本地排队、Agent 整理和理解回执。
3. 展开知识点、来源证据、主问题和评分规格。
4. 点击“立即试一题”，完成语音回答和评分。
5. 验证这次预览没有创建 FSRS 复习记录。

### 场景 B：网页核验与冲突

1. 提交包含时效信息或精确数字的公开网页。
2. 验证风险触发原因可见，系统确实执行联网核验。
3. 成功核验时保留原来源和核验来源。
4. 证据不足或冲突时，仅相关知识进入待处理。
5. 采用限定版本或来源观点后，知识才能重新进入复习。

### 场景 C：语音随记与恢复

1. 录制一段语音学习内容。
2. 验证批量转写并自动整理。
3. 模拟断网或服务中断，确认原音频和任务状态仍在本机。
4. 恢复服务后重试，成功提交后删除采集音频。
5. 重启 App，确认不会产生重复知识点。

### 场景 D：正式语音复习

1. 准备至少一个符合两小时条件的到期知识点。开发模式下允许把知识标为到期或跳过等待，以便验收；正式模式与 POC 禁止。
2. 启动正式复习，验证固定候选快照和独立窗口。
3. 完成一次正常回答、一次提示后重答和一次转写错误免费重录。
4. 验证 Again／Hard／Good、用户 Easy 升级和任意等级改判。
5. 验证每题在 Mac 原子写入并 ACK 后才进入下一题。
6. 五分钟到达后自然完成当前题，不再开始新题。

### 场景 E：通知闭环

1. 设置测试提醒时间并收到本地通知。
2. 分别验证现在开始、15 分钟后、1 小时后和今日跳过。
3. 验证每天最多稍后两次。
4. 无候选日不发通知，并记录“无需复习”。

### 场景 F：故障降级

1. Realtime 中断后改用 macOS 系统语音朗读，再验证纯文字路径。
2. Responses 评分失败时不更新 FSRS，并允许重试。
3. 关闭复习窗口后重新打开，已完成题不重复，未完成题重新提问。
4. Agent 运行记录能够定位故障节点，但不泄露知识全文或密钥。

## 7. Demo 通过标准

以下条件同时满足才可进入 21 天 POC。切片 0–6 都必须完成，不能用只完成文字链路宣称 Demo 通过：

- 三类输入的真实端到端链路均通过；
- 风险核验的成功和冲突分支均真实通过；
- 立即试一题与正式复习的数据口径没有混淆；
- Realtime、Responses、用户改判和 FSRS 形成可恢复的一题一事务；
- 通知闭环、暂停恢复、重启恢复和防重复写入均通过；
- 运行事件能够重建实际路径，产品状态与开发记录不存在两套相互矛盾的进度；
- 关键不变式的正向与反向测试通过，自动化结果由外部数据状态而非 Agent 自我报告证明；
- 开发记录能解释实际 Agent 路径，普通界面仍保持产品语言；
- Rex 在原生 Mac App 中完成视觉与真实交互验收。
