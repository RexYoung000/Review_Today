# Review Today 21 天 POC 验证方案

> 验证对象：持续复习闭环
> 前置条件：纯文字闭环、质量评测、Harness 收口和语音闭环已通过；短周期真实自用值得继续
> 验证用户：Rex
> 验证周期：连续 21 天

## 1. Demo 与 POC 的区别

前序里程碑依次验证纯文字核心闭环、知识与判断质量、运行 Harness、语音交互和短周期自用，具体见[最小闭环与渐进式里程碑](demo-plan.md)。这些阶段通过后，才开始 21 天持续行为验证。

21 天 POC 验证的是另一个问题：

> 当记录、整理、提问、判断和再排期连成一条低摩擦闭环后，用户是否愿意持续把它放进每天的真实学习流程？

Demo 通过不计入 21 天输入或复习次数；用于调试的假样本、预览题和重复演示也不计入 POC。

## 2. 测试样本

- 21 天内至少完成 20 次真实输入。
- 输入至少覆盖三类不同主题或知识形态，例如事实、概念、程序或目标语言内容。
- 输入必须来自真实学习过程，不为凑数量专门制作测试文本。
- POC 不录入敏感信息，也不把无法发送给外部 AI 服务的内容计入样本。
- “立即试一题”只用于体验新知识，不计入正式复习次数或掌握度。

## 3. 核心通过门槛

以下条件需要同时满足：

| 指标 | 通过门槛 |
|---|---:|
| 完成的正式复习日 | 至少 15 天 |
| 其中语音为主的复习日 | 至少 10 天 |
| 真实输入 | 至少 20 次 |
| 覆盖的知识类别 | 至少 3 类 |
| 自动整理纠错率 | 不高于 20% |
| Agent 判断纠错率 | 不高于 20% |

达到门槛表示“持续复习闭环值得继续验证”，不等于已经科学证明长期记忆效果提升。

## 4. 指标口径

### 4.1 可用日

以下任一情况计为一个可用日：

- 当天存在符合条件的正式复习候选；
- 当天没有候选，系统正确记录“无需复习”。

系统故障导致无法生成候选或无法开始会话的日期不算“无需复习”，而是技术不可用日。

```text
可用日完成率
= 完成正式复习或正确无需复习的日期数 ÷ 可用日总数
```

该指标用于区分“产品没有安排任务”与“用户有任务但没完成”，不替代 15 天核心门槛。

### 4.2 完成一次正式复习

- 用户从通知或 App 进入正式复习，并完成候选用尽或五分钟窗口后的自然收尾，记为当天完成。
- 五分钟到点后完成当前题的自然延长属于同一次复习。
- 只收到通知、打开后立即退出、稍后或今日跳过，不计为完成。
- 因系统故障中断的会话单独记录，不计为用户主动放弃。
- 同一天额外完成会话只算行为数据，不把“完成日”重复加一。

### 4.3 语音为主

- 当天正式复习中，超过一半已完成题目通过 Realtime 语音或 macOS 语音降级链路回答，记为语音为主。
- 纯文字会话可以算正式复习完成，但不算语音为主。
- Realtime 失败后使用 macOS TTS 提问、用户仍以语音回答，可以计为语音为主，但必须标记降级方式。

### 4.4 自动整理纠错率

```text
需要修改或删除的自动知识点数 ÷ 被抽查的自动知识点总数
```

- 每周至少抽查十个自动知识点；当周不足十个时检查全部。
- 标题润色、纯风格偏好或主动补充不计为错误。
- 核心含义错误、遗漏关键限定、来源错配、错误拆分、不值得复习、知识类型错误或问题无法判断均计为需要纠正。
- 核验冲突被系统正确暂停不算整理错误；应核验却没有核验则计为错误。

### 4.5 Agent 判断纠错率

```text
用户改变有效掌握等级的回答次数 ÷ Agent 给出掌握等级的回答总次数
```

- 只统计 Agent 已经给出 Again、Hard 或 Good 的正式回答。
- 用户将 Good 主动升级为 Easy 仍计为一次等级改判，以反映 Agent 无权自动给 Easy 的产品规则；复盘时单独区分“产品约束升级”和“错误判断纠正”。
- 修改反馈文字但不改变等级不计为改判。
- 转写错误后免费重录不计为评分改判；如果用户没有机会纠正转写而导致误判，则计入判断错误。
- 同时保留 Agent 原始等级和用户生效等级，纠错率以实际改判行为为准。

### 4.6 提前复习

- 未来 24 小时内到期且用于补足会话的题目标记 `early_review`。
- 每次最多两题。
- 提前复习结果正常进入 FSRS，但必须与真正到期题分开统计，避免误判系统供给是否充足。

### 4.7 技术中断

技术中断至少分为：

- Python 服务不可用；
- 网页读取或核验失败；
- Realtime 连接或音频中断；
- Responses 整理或评分失败；
- SwiftData 写入或 ACK 失败；
- App 崩溃或恢复失败。

技术中断导致的未完成不计为用户跳过。成功降级完成的会话仍计为完成，但记录降级方式。

## 5. 自动记录数据

- 每日采集次数、输入类型和生成知识点数量；
- 任务状态、解析失败、核验触发原因、冲突和重试结果；
- 整理回执是否展开，以及知识被修改、暂停、软删除或永久删除；
- 通知时间和立即开始、15 分钟后、1 小时后、今日跳过；
- 当天候选数量、无需复习、提前复习题数和是否为额外会话；
- 每次会话开始、结束、五分钟窗口、自然延长、完成状态和中断原因；
- 每题使用的问题变体、提示、转写重录、Agent 等级、用户生效等级和新排期；
- Realtime、TTS 或纯文字路径，以及语音为主判断；
- Agent 节点错误、恢复和本地写入失败，但日志不保存不必要的完整知识正文；
- FSRS 算法与参数版本。

## 6. 质性观察

出现明显感受时补充一句简短记录：

- “Agent 真的理解了我”的 Aha moment；
- 整理结果反复修改的原因；
- 不想开始、稍后或中途退出的原因；
- 问题过于简单、模糊、重复或偏离学习意图；
- 一分钟轻提示是否打扰，五分钟窗口是否自然；
- Realtime 语音、转写、反馈和改判是否建立信任；
- 提醒出现得恰当或打扰的具体原因；
- 如果没有开发运行记录，某次故障是否难以理解。

质性记录用于解释指标，不替代通过门槛。

## 7. POC 开始前检查

- 本机 Demo 的三类输入、真实核验和正式复习场景全部通过；
- 固定 OpenAI 模型配置和 FSRS 版本，实验中变更必须记录日期与原因；
- 设置 21 天开始日期和每日提醒时间；
- 清理 Demo 假样本和预览指标；
- 确认音频七天滚动删除和 POC 结束全量删除可执行；
- 确认断网、服务重启、Realtime 降级和重复提交不会丢数据或重复记账；
- 确认指标可以从本地记录计算，而不是依赖人工回忆。

## 8. 21 天复盘

复盘至少回答：

1. 是否达到六项核心门槛和可用日完成率；
2. 没有完成复习的主要原因是时机、负担、内容质量、语音体验还是技术不可用；
3. 自动整理与 Agent 判断的主要错误模式分别是什么；
4. 哪些知识类型、主题和语言最适合当前机制，哪些不适合；
5. 提前复习和额外会话是否说明供给或排期设计有问题；
6. 如果明天停用，Rex 是否会明显失去一种有价值的学习能力；
7. 下一阶段应继续核心闭环、针对问题调整后重测，还是暂停该方向。

未达到指标时先根据错误、技术中断和行为数据定位原因，不把所有结果简单归因于“用户没有坚持”。

## 9. 待确认

- 21 天测试的具体开始日期；
- 每日默认提醒时间；
- 每日质性记录入口和最终复盘载体；
- 模型与 FSRS 的实验冻结版本。
