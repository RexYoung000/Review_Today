# Review Today 21 天 POC 验证方案

> 验证对象：持续复习闭环
> 验证用户：Rex
> 验证周期：连续 21 天

## 1. 要验证的核心问题

POC 不是判断“AI 能否生成几张知识卡”，而是验证：

> 当记录、整理、提问、判断和再排期连成一条低摩擦闭环后，用户是否愿意持续把它放进每天的真实学习流程。

自动整理的 Aha moment、回答判断准确性和提醒方式都服务于这一个核心问题。

## 2. 测试样本

- 21 天内至少完成 20 次真实输入。
- 输入至少覆盖三类不同主题或知识形态，例如事实知识、概念或方法、目标语言内容。
- 输入必须来自真实学习过程，不为凑数量专门制作测试文本。
- POC 不录入敏感信息，也不把无法发送给外部 AI 服务的内容计入样本。

## 3. 核心通过门槛

以下条件需要同时满足：

| 指标 | 通过门槛 |
|---|---:|
| 完成的五分钟复习 | 至少 15 次 |
| 真实输入 | 至少 20 次 |
| 覆盖的知识类别 | 至少 3 类 |
| 自动整理纠错率 | 不高于 20% |
| Agent 判断纠错率 | 不高于 20% |

达到门槛表示“持续复习闭环值得继续验证”，不等于已经科学证明长期记忆效果提升。

## 4. 指标口径

### 4.1 完成一次复习

- 用户从通知或应用进入复习，并完成系统的自然收尾，记为一次完成。
- 只收到通知、打开后立即退出或选择“稍后／今日跳过”，不计为完成。
- 因系统故障中断的会话单独记录，不计入用户主动放弃。

### 4.2 自动整理纠错率

```text
需要修改或删除的自动知识点数 ÷ 被抽查的自动知识点总数
```

- 每周至少抽查十个自动知识点；当周不足十个时检查全部。
- 标题润色或纯风格偏好不计为错误。
- 核心含义错误、遗漏关键限定、来源错配、错误拆分或不值得复习计为需要纠正。

### 4.3 Agent 判断纠错率

```text
用户主动改判的回答次数 ÷ Agent 完成判断的回答总次数
```

- 只统计 Agent 已经给出掌握等级的回答。
- 用户因主观偏好修改反馈文字但不改变等级，不计为改判。
- 转写错误导致的误判仍计入，因为用户体验上同样属于 Agent 判断失败。

## 5. POC 需要自动记录的数据

- 每日采集次数、输入类型和生成知识点数量；
- 待处理、解析失败、核验冲突和重试结果；
- 整理回执是否被展开，以及知识点被修改、暂停或删除的情况；
- 通知时间和用户选择的立即开始、稍后或跳过；
- 每次复习的开始时间、结束时间、实际时长、完成状态和中断原因；
- 每题的 Agent 等级、是否提示重答、用户是否改判和更新后的下次复习时间；
- 服务错误、语音中断和排期失败，但不在日志中保存不必要的完整知识正文。

## 6. 质性观察

每次出现明显感受时，可补充一句简短记录：

- “Agent 真的理解了我”的 Aha moment；
- 整理结果需要反复修正的原因；
- 不想开始复习或中途退出的原因；
- 提问过于简单、模糊、重复或不符合学习意图的情况；
- 五分钟感觉过长、过短或刚好的具体场景；
- 提醒出现得恰当或打扰的具体原因。

质性记录用于解释指标，不替代通过门槛。

## 7. 21 天结束后的复盘

复盘至少回答：

1. 是否达到五项核心门槛；
2. 用户没有完成复习的主要原因是时机、负担、内容质量还是语音体验；
3. 自动整理和 Agent 判断的主要错误模式分别是什么；
4. 哪三类知识最适合当前机制，哪些内容不适合；
5. 如果明天停用，用户是否会明显失去一种有价值的学习能力；
6. 下一阶段应该继续核心闭环、针对问题调整后重测，还是暂停该方向。

未达到某一指标时，先结合错误与行为数据定位原因，不把所有未通过结果都简单归因于“用户没有坚持”。
