### KT-01：有效答题后出现“新增知识”提示

确认来源：2026-10-04 本轮讨论。Rex 指出学习中不清楚何时可以生成知识卡，提出答对后给出明确入口，并确认对话内提示方案。

**确认内容：** 知识点首次通过有效检查后，在答题反馈下显示本题主题与保存范围；用户点击“新增知识”后才生成、核验和保存。同一内容避免重复提示；可稍后录入、继续追问；提示不代表整节掌握、话题结束或自动进入下一节。实际保存成功后显示结果和查看入口；保留原有主动整理入口，保存与正式复习参与选择分开。

**续接确认（2026-10-04）：** 尚未点击时，同一知识点的有效补充／纠正更新原邀请及可见保存范围；其他新知识点不自动合并。点击按当时显示的范围保存，后续已推翻的旧错误不得进入结果。该选择已确认，不再作为待选产品方案；没有授权预生成、自动改写旧卡或扩大理解证明。见决策 215。

**现有实现：** 有效独立答题后，在对应反馈下显示知识名、一句具体保存内容和“新增知识／稍后”。同知识补充更新原邀请，纠正剔除旧错；点击才启动原有生成、核验和保存。复习选择独立且默认关闭。旧主动整理和收尾入口继续可用。

规则详情见 [DESIGN 新邀请规则](../DESIGN.md#knowledge-save-invitation)和 [Harness 契约](agent-harness-v2.md#knowledge-save-invitation-contract)；确认记录见[决策日志](decision-log.md)。主要实现入口为 [TopicCapture.swift](../Review_Today/TopicCapture.swift)、[topic_capture.py](../agent-service/agent_service/topic_capture.py)、[conversation.py](../agent-service/agent_service/conversation.py)。

回归覆盖：概念重叠去重、较早邀请更新、稍后再进入、保存失败后的纠正、重试中断恢复、点击版本与回执。不因一道题通过而升级整节掌握，不将后续新知识自动合并。

### QA-01：验证用户能发现并完成保存

以下为本轮验收契约；各层实际执行结果见[本批证据](evidence/2026-10-04-knowledge-invitation/README.md)，不以历史测试代替：

| 场景 | 应看到的结果 |
|---|---|
| 没有相关卡，开始学习并追问 | 教学与学习记录正常推进，不以已有卡片为前提 |
| 本知识点首次有效检查通过 | 对应反馈下出现范围明确的提示；不夸大为整节掌握 |
| 重复回答同一内容／继续追问 | 不重复催促、不自动换节；保存范围不被旧题覆盖 |
| 邀请出现后补充同一知识点 | 原邀请的可见范围更新；点击才整理，保存内容与点击时范围一致 |
| 后续纠正推翻原结论 | 邀请范围及有效来源更新，保存结果不含已推翻的旧错误；不自动升级掌握 |
| 转而讨论其他新知识点 | 不悄悄并入原邀请或扩大原有保存范围 |
| 稍后录入 | 保留来源并进入待处理，继续学习不受阻 |
| 点击新增知识 | 才执行生成／核验／保存；状态与实际阶段一致 |
| 失败、重试、重复点击 | 不误报成功、不生成重复副本；保留恢复入口 |
| 本机写入成功后查状态 | 实际卡片、来源与回执对应，显示结果和查看入口 |
| 原失败双主题输出与重复查询 | 不因部分过滤退回旧主题，不反复长篇纠错 |

受控回归验证程序约束；真实模型验证连续语义；原生检查验证提示可见、可操作与实际落盘。临时 SQLite 加模拟 Mac 回执不能证明原生完整链路。Rex 最终体验验收独立记录。
