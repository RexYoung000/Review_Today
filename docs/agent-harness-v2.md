# Review Today Agent Harness V2 主规格

> 状态：M1 阻塞性重构的实施基线  
> 决策日期：2026-09-02  
> 适用范围：开发 Mac 上的文字与公开链接 POC  
> 关系：本文定义跨产品、交互与系统边界的 Harness 契约；产品语义见 `product-requirements.md`，界面语义见 `../DESIGN.md`，工程契约见 `architecture.md`，验收门槛见 `m1-acceptance.md`。

## 1. 为什么需要 V2

当前实现是一条批量任务链：Mac 保存采集内容，Python 服务运行整张采集图，结束后客户端才能取得结果。服务不可用时界面只显示“等待服务恢复”，任务事件没有进入主要体验，所谓“思考过程”实际只是本地状态历史。

这不能满足学习教练的核心体验：用户输入后应立即得到接收反馈，知道 Agent 当前在做什么、为什么需要自己参与、如何恢复，并能在同一上下文中继续学习。

V2 把产品从“一次采集对应一次模型任务”改为：

```text
学习 Session（持续对话与上下文容器）
└── Learning Task（一次可暂停、恢复和完成的学习目标）
    ├── Message（用户与教练的可见对话）
    ├── Task Event（可回放的工作过程）
    ├── Source / Evidence（资料与证据）
    └── Knowledge Link（形成的长期记忆）
```

V2 不是通用聊天或多 Agent 平台。用户只面对一个专门的学习教练，内部根据学习目标选择受控工作流。

## 2. 产品对象与生命周期

### 2.1 Agent Session

Session 是一段连续学习对话的上下文容器：

- 新 Session 默认使用“自动”模式，也可由用户预设一个模式；
- 保存完整可见对话、结构化摘要、当前与历史任务、资料引用和知识引用；
- 一个 Session 可以连续完成多个相关 Learning Task；
- Task 完成不会自动关闭 Session；用户可以继续学习或手动归档；
- 归档只从活跃列表移除，不删除对话、任务、资料或知识关联；
- Session 之间默认隔离，不把其他 Session 全部历史注入当前任务。

Session 状态：

```text
active → archived
archived → active
```

删除 Session 不属于 M1。后续若增加删除，必须单独定义知识引用、来源引用和不可恢复确认。

### 2.2 Learning Task

Task 是 Session 内一个可执行学习目标，不等同于一次输入或一次模型调用。一次 Task 可以跨多轮对话、等待用户选择、暂停、重试并恢复。

统一状态：

```text
accepted
→ queued
→ running
↔ awaiting_user
→ committing
→ completed
```

异常与终止状态：

- `retryable_failed`：外部服务、超时或可恢复结构错误；保留输入并允许自动或手动重试；
- `needs_attention`：证据冲突、内容风险或必须由用户决定；
- `cancelled`：用户取消当前任务，Session 与已有消息仍保留；
- `terminal_failed`：无法在当前约束下继续，显示原因和可行下一步。

`completed` 只表示该 Task 的完成条件满足，不代表 Session 已归档，也不代表产生了长期记忆。

### 2.3 Message 与 Task Event

Message 是用户应该阅读的对话内容；Task Event 是可回放的执行事实。两者不能混为模型思维链。

- 用户发送后，Mac 必须先保存用户 Message 并立即显示；
- 服务接受任务后，可以产生教练 Message、选择卡片或问题；
- Event 记录阶段、状态、路由依据摘要、耗时、重试、错误和恢复；
- Event 不保存或展示隐藏思维链、密钥、Authorization、无关完整正文；
- 重启后客户端按事件顺序号恢复，不能重复插入消息或知识。

## 3. 模式与路由

### 3.1 模式列表

Session 模式预设：

| 模式 | 适用输入 | 默认完成条件 |
|---|---|---|
| `auto` 自动 | 用户不想先分类 | Harness 判断最合适工作流；高影响切换由用户确认 |
| `memory_organization` 记忆整理 | 用户已经理解的材料 | 形成并验证可复习记忆，完成原子写入 |
| `source_learning` 资料学习 | 用户有资料但尚未理解 | 用户确认理解；是否形成记忆另行确认 |
| `topic_exploration` 主题探索 | 用户只有主题、没有可靠资料 | 用户确认一个小型资料包并转入资料学习 |
| `problem_solving` 问题攻克 | 具体问题、面试题、面经或 JD | 用户能够脱离参考答案独立作答或解决同类问题 |

模式是同一个学习教练背后的工作流，不是四个角色或四次并行模型调用。

### 3.2 自动判断

路由器根据当前输入、Session 近期消息、结构化摘要、当前 Task 和相关知识输出 `ModeDecision`：

- 推荐模式；
- 置信度；
- 面向用户的简短理由；
- 是否建议切换；
- 输入与当前 Session 的关系。

主题关系只允许：

- `continuation`：当前任务的直接继续；
- `related_subtopic`：相关子题，可留在当前 Session；
- `new_topic`：明显无关主题；
- `uncertain`：无法可靠判断，留在当前 Session。

只有高置信 `new_topic` 才显示“建议新建 Session”卡片。用户可以选择继续当前 Session 或新建；Harness 不自动分割会话。

### 3.3 模式切换

- Session 预设模式优先于自动建议，但不禁止 Harness 发现明显不匹配；
- 中途切换必须说明原因并由用户确认；
- 切换时保留同一 Task、已确认目标、资料、用户回答和证据状态；
- 不重复创建来源、消息或知识；
- 记忆整理发现用户不理解或证据冲突时，可建议资料学习；
- 资料学习发现资料不足时，可建议主题探索；
- 主题探索确认来源后进入资料学习；
- 资料学习或问题攻克只有在用户确认后才能进入记忆生成。

## 4. 四种受控工作流

### 4.1 记忆整理

进入条件：用户提供已经理解、希望记住的文字或公开链接内容。

```text
关联 Session 上下文
→ 判断来源、主题、语言、知识类型与风险
→ 拆分原子学习目标
→ 生成卡片、评分规格与问题
→ 确定性结构校验
→ 独立语义忠实性校验
→ 风险与证据评估
→ Mac 原子写入
→ 返回形成记忆回执
```

规则：

- 默认不联网；稳定、低风险内容直接依赖用户材料；
- 时效、医学、法律、金融、精确数字、争议或低置信内容触发查证；
- 内容可信度是独立证据轴，不能用模式判断代替；
- 证据状态为 `unverified`、`supported`、`conflicting`、`insufficient`、`outdated`、`scoped`；
- 冲突只暂停受影响知识，其他知识可以继续；
- 冲突时等待用户选择：重新学习、保留为来源观点、按地区或版本拆分、继续暂停；
- 记忆写入保持现有知识卡、问题、评分规格和 ACK 幂等契约。

### 4.2 资料学习

进入条件：用户有资料，但尚未理解或明确表示需要学习。

```text
确认学习目标
→ 检查资料边界、来源和质量
→ 生成学习地图
→ 分段讲解
→ 接受用户追问
→ 小型理解检查
→ 用户确认理解
→ 询问是否形成记忆
```

规则：

- 默认采用“分段讲解并检查”，避免一次性倾倒整份课程；
- 每段展示来源名称与定位，可展开查看相应摘录；
- 用户的追问继续使用当前资料和已建立的学习地图；
- 理解检查只服务教学，不更新 FSRS 或正式复习分数；
- 用户确认“形成记忆”后才进入共享记忆生成器。

### 4.3 主题探索

进入条件：用户表达学习主题，但没有可靠材料。

```text
每次只追问一个关键问题以收窄目标
→ 让用户选择：粘贴材料 / 提供链接 / Agent 查找资料
→ 必要时检索
→ 生成 2–4 个互补来源的小型资料包
→ 用户确认资料包
→ 转入资料学习
```

资料包每项必须包含来源名称、用途、日期、地区或版本范围、定位或 URL、证据状态。模型常识不能伪装成用户原文或已确认来源。

### 4.4 问题攻克

进入条件：具体问题、面试题、面经问题、工作难题或完整 JD。

具体问题采用“先答再校准”：

```text
识别问题类型、目标和风险
→ 立即给一版可使用的基础答案
→ 标出关键假设、置信度和证据状态
→ 询问一个最影响深度的背景问题
→ 建立知识依赖与缺口地图
→ 给出针对性学习路径
→ 针对缺口讲解与练习
→ 用户独立作答
→ Agent 评价并追问
→ 达到独立作答标准
→ 询问是否形成记忆
```

首轮答案至少包括：

1. 结论或参考答案；
2. 相关知识点及其依赖关系；
3. 当前可能存在的认知缺口；
4. 针对性学习顺序；
5. 下一步校准问题。

面试类问题额外提供可口头表达的回答结构；一般问题提供可执行解法。稳定基础知识先直接回答；时效、高风险、争议或低置信内容自动查证，完成查证前明确标记为暂定答案。

完成判断：

- 用户必须先独立作答；
- Agent 从正确性、完整性、表达和迁移能力反馈；
- 根据薄弱点追问或补教，不重复整份答案；
- 能脱离参考内容回答当前题并处理合理变式后，Task 才可完成；
- 练习结果不直接写入正式复习评分；
- 完成后由用户确认是否形成长期记忆。

JD 入口先执行：

```text
解析岗位目标与职责
→ 生成能力地图
→ 标记高风险与高频要求
→ 生成按优先级排列的问题清单
→ 用户选择一题
→ 进入具体问题攻克
```

JD 不一次性生成整份答案，也不未经用户选择自动展开所有题。

## 5. 主界面反馈契约

### 5.1 即时反馈

提交一轮输入时：

1. Mac 生成稳定 `client_message_id`，先本地保存并立即显示用户消息；
2. 本地创建 `accepted` Task；
3. 服务尚未就绪时显示“正在启动学习服务”，而不是沉默或伪装成处理中；
4. 服务接受后显示第一个真实工作阶段；
5. 无法启动时显示具体原因、重试和打开设置／运行详情入口；原始输入仍保留。

### 5.2 工作过程

主界面使用用户语言展示：

- 正在理解你的目标；
- 正在检查资料；
- 正在整理答案；
- 等你选择资料；
- 等你回答；
- 正在形成记忆；
- 已完成；
- 需要处理。

这些文案必须来自真实 Task Event，不得用循环动画假装模型仍在工作。

### 5.3 运行详情

每个 Task 卡片可展开“运行详情”，展示：

- 节点与阶段；
- 路由依据摘要；
- 开始时间、结束时间和耗时；
- 尝试次数与重试原因；
- 错误码、失败节点和恢复动作；
- 脱敏后的结构化摘要。

运行详情仍不展示隐藏思维链。开发模式中的全局运行记录继续存在，用于跨 Task 排查。

## 6. macOS 信息架构

主窗口侧边栏正式入口调整为：

1. **今天**：复习计划、学习活动指标、待处理和最近结果的数据看板；不提供输入；
2. **学习**：Session 列表与完整学习对话，是所有文字和链接输入的主入口；
3. **知识库**：查看、纠错、暂停和管理长期知识；
4. **待处理**：证据冲突、结构错误和需要人工决定的任务。

学习工作区：

```text
Session 列表        当前 Session
────────────────────────────────────
新建学习            标题 / 模式 / 归档
活跃 Session         完整对话
已归档               Task 工作过程与操作卡片
                     输入框 / 模式选择
```

- 默认打开最近活跃 Session；没有 Session 时显示创建入口和四种模式说明；
- 用户可新建、继续、归档和恢复 Session；
- 模式选择作用于 Session，默认“自动”；
- 输入支持文字和公开链接；M1 不提供语音按钮；
- 键盘提交、焦点、长内容、窗口缩放和中英混排必须可用；
- 状态不能只依赖颜色或动画；Reduce Motion 下保持同等因果反馈。

## 7. 本地服务与恢复

### 7.1 App 托管服务

开发 Mac POC 由 App 管理本机 Python 服务：

- App 启动后在后台检查 `127.0.0.1:8742/health`；
- 未就绪时使用项目已配置的本地 Python 环境启动服务；
- 监控进程退出和健康状态，采用有限退避自动恢复；
- 同一 App 生命周期只允许一个受托管实例；
- App 退出时终止自己启动的子进程，不终止外部手动启动的兼容实例；
- 环境、解释器或配置缺失时展示可操作诊断，不显示密钥；
- Release 分发、自启动代理、签名和安装包不在 M1。

### 7.2 数据事实来源

Mac 本地数据库是长期事实来源，保存：

- Session 与归档状态；
- 用户和教练 Message；
- Task 及最后消费事件序号；
- Event 的用户可见与诊断字段；
- Source、Knowledge 和关联；
- 结构化 Session 摘要。

Python 只保存未完成 Task 的短期 checkpoint 与事件窗口，使用 TTL 清理。服务重新取得 Task 时必须依赖稳定 ID 保持幂等。

### 7.3 上下文预算

每轮上下文由以下部分组成：

- 当前 Task 目标和状态；
- 当前 Session 近期消息；
- 结构化 Session 摘要；
- 当前资料相关片段；
- 最多 5 条相关既有知识。

默认预算：路由、关系判断和摘要约 3k tokens；教学、资料学习与问题攻克单轮约 16k tokens。达到预算前更新结构化摘要，不盲目发送全部历史。

跨 Session 只通过检索到的相关知识或用户确认的交接包引用，不能读取全部对话。

### 7.4 新 Session 交接包

用户确认新建 Session 后生成：

- 最新输入；
- 推断学习目标；
- 相关已确认决定；
- 来源与知识引用；
- 未解决问题；
- 来源 Session ID。

不复制完整聊天记录。交接包以系统摘要形式显示，用户可以返回来源 Session。

## 8. API 与结构化契约

### 8.1 HTTP API

`POST /v2/sessions/{session_id}/turns`

- 输入：`client_message_id`、`content`、`content_type`、Session 模式预设、客户端已知任务状态；
- 行为：幂等接受一轮输入，立即返回；
- 输出：`message_id`、`task_id`、`status=accepted|queued`、`next_event_seq`。

`GET /v2/tasks/{task_id}`

- 返回 Task 当前状态、模式、当前阶段、等待动作、错误和最终摘要。

`GET /v2/tasks/{task_id}/events?after_seq={seq}`

- 按序返回尚未消费的事件；重复读取结果稳定；事件窗口丢失时返回需要任务快照恢复的明确错误。

`POST /v2/tasks/{task_id}/actions`

- 输入：稳定 `action_id`、动作类型和结构化 payload；
- 支持用户选择、确认、回答、重试、取消、建议切换模式、创建交接包；
- 同一 `action_id` 幂等。

`POST /v2/tasks/{task_id}/ack`

- 输入：最后持久化事件序号以及需要确认的知识 ID；
- 只有 Mac 已可靠保存结果后才 ACK；重复 ACK 幂等。

v1 capture 与 review API 在 V2 真实体验验收通过前保留。

### 8.2 Task Event

每条事件必须包含：

- `event_id`、`session_id`、`task_id`、`seq`；
- `occurred_at`、`stage`、`state`、`node`；
- `user_summary`、可选 `detail_summary`；
- `attempt`、可选 `duration_ms`；
- 可选 `error_code`、`recovery_action`、`required_action`；
- 可选 `message` 或结构化结果引用。

事件顺序号在单 Task 内严格递增。客户端按 `event_id` 和业务对象 ID 去重。

### 8.3 结构化模型输出

必须定义并校验：

- `ModeDecision`
- `SourcePack`
- `EvidenceAssessment`
- `LearningPlan`
- `LessonStep`
- `UnderstandingCheck`
- `QuestionAnalysis`
- `JDAnalysis`
- `ProblemAnswer`
- `KnowledgeGapMap`
- `MemoryPackage`

模型输出结构错误最多自动修复一次；仍失败则进入可重试失败或待处理，不能伪造完成。

## 9. 模型角色

角色配置独立于产品模式：

- **Luna**：模式路由、主题关系判断、Session 摘要；
- **Terra**：教学、问题回答、记忆生成、普通证据评估与语义验证；
- **Sol**：高风险事实和证据冲突判断。

启动时执行能力检查。某角色不可用时：

- 不静默换成另一个模型；
- 受影响 Task 显示明确错误与可恢复动作；
- 不受影响的本地浏览、Session 编辑和历史数据仍可使用。

## 10. 兼容、隐私与非目标

- 已有 Source、Knowledge、Question、评分规格、ReviewAttempt 和 FSRS 数据不得破坏；
- 旧 CaptureTask 可以继续完成或显示在待处理兼容队列；
- 完整对话只保存在 Mac；Python checkpoint 到期删除；
- 长期运行指标不得包含完整对话或知识正文；
- 外部模型仍受对应服务数据政策约束；
- M1 不做语音、Realtime、多模态文件、PDF、图片、登录、跨设备同步、公共部署、正式安装包或商业化；
- M1 不把学习工作区扩成通用助手、开放工具调用或多角色 Agent 导航。

## 11. M1 验收门槛

### 11.1 自动化

- Session 隔离、归档、恢复和结构化交接；
- 模式识别、建议切换、四种工作流和跨模式状态保留；
