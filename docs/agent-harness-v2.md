## A011 按需核验、运行反馈与来源链接（2026-09-17，已实现／受控与真实回放通过／待 Rex 验收）

Rex 确认：稳定概念、基础原理和普通举例优先使用模型已有知识；新知识点或没有网页证据本身不触发联网。用户明确搜索/出处核验、时效问题、高风险实际建议、证据冲突或知识不确定时才检索；指定 URL 继续走正文读取。同主题普通追问可复用适用证据，新主题不继承旧证据。未检索不追加失败提示，也不编造来源。

当前复现：基础问题“harness是什么意思”路由 needs_verification=false，却被 new_knowledge/无 evidence 条件强制搜索；实际首字约 43 秒，三次顺序读取约 22.6 秒。正文已有 Markdown 来源链接，原生全局强调色让链接看起来与正文相同。工具遥测覆盖了真实阶段摘要。

修复范围：移除强制搜索条件；路由语义明确核验需求。普通核验先读取最相关来源并判断支持范围，足够即停止；不足再读，最多三篇。明确交叉核验或高风险强制核验至少检查两个独立域名，来源不足如实说明。普通核验网页累计预算 30 秒、交叉/高风险 60 秒（仅工具等待/执行，不含模型）；不修改现有服务凭证、限流或备用顺序。

运行反馈：吉祥物画布放大到 64×56 pt，与右侧括号内真实阶段文字及轻量动态省略号组合，下方保留详情。阶段不被模型尝试、工具遥测或步骤完成日志覆盖，累计计时连续；减少动态效果时关闭打字与省略号动画。来源统一蓝色下划线，独立参考链接悬停变化并呈现手型，保留原文复制、选取和跳转。

案例：稳定首问/新概念不调用网页；学习目标不自动搜；明确核验会调用；同主题复用与新主题隔离；指定 URL 读取；首篇足够停止/不足扩展/交叉核验；预算与取消；日志不覆盖阶段；真实首字耗时；原生浅深色/窄窗/减弱动态/链接悬停与跳转。实现、受控回归、真实服务与 Rex 验收分别记录，不能把响应预算当最终耗时保证。


验证：431 tests / 71 subtests、原生正文/焦点/会话回放及真实 SSE 通过。真实基础首问首字 3.8 秒，明确官方核验 17.6 秒（1 搜索/1 正文），同主题复用 3.9 秒；均为小样本本机实测。实现、原生自测与未验交互边界见 [A011 验证记录](evidence/2026-09-17-selective-web/README.md)。

## A010 普通问答与学习任务边界（2026-09-17，已修复／待 Rex 验收）

真实复现：Auto 中“你好”→“我不知道”→“harness是什么，它有什么作用”，意图为 question，却同时标记 learning/topic_exploration/answer_only=false，程序误建任务并追问学习目标；搜索未运行。此前举例追问误入学习任务为同类问题。

修复契约：Auto 单纯问题、解释、举例、提示优先局部回答，不能仅凭 scope/workflow 建任务；显式学习目标、继续既有任务及用户选择的学习模式保持原行为。局部问答不要求确定学习用途，不展示新学习任务或录入提示。无证据不擅自把多义术语限定到某领域；先说明通用含义/区别，依据明确上下文解释，必要内容澄清与学习目标澄清分开。网页核验仍走独立工具链。基础首问简短讲定义/作用/一个例子，局部追问不重复背景；用户要一个类比只给一个，不自动展开教程（正文长度为提示目标，不截断模型输出）。

纠错：用户“我只是问它是什么/先回答问题”识别为对话纠错，回到尚未回答的原问题。只撤销可核实为普通问答误建、停在目标澄清且没有学习计划/成果的任务，保留历史；不能撤销用户明确建立的学习目标、其他任务、已学进度或保存数据。普通 Auto 问题即使遇到旧误建任务也应能继续回答。

回归：真实三轮会话；无历史首问；同概念举例；旧误建任务纠错与继续提问；正常显式学习与非 Auto；已有真实任务局部问答保持进度；有实际对象歧义仍可澄清；新主题局部问答不强制会话选择；网页核验与来源复用。419 tests / 69 subtests 通过，真实三轮会话、局部类比及注入旧任务后的真实纠错回放均通过。证据与重跑入口见 [A010 验证记录](evidence/2026-09-17-ordinary-question/README.md)。


## A008 多服务网页工具（2026-09-17，已授权实施）

### Exa 独立 Key 与 Brave 暂停（2026-09-17）

Rex 已填写 Exa/Tavily 独立 Key，因费用暂不启用 Brave。本机搜索/读取均为 Exa → Tavily，Context 关闭；Brave 代码保留。Exa 固定 MCP 端点使用 Authorization 请求头，不将 Key 放 URL 或工具参数；空 Key 保留匿名模式，认证失败直接沿既有冷却/备用链处理，不匿名重试或借用模型凭据。

补充案例：带 Key 的握手、搜索、读取、会话清理；无 Key 匿名兼容；错误不泄露 Key；认证失败转 Tavily；Brave 关闭时无请求；真实 Exa/Tavily 搜索和正文以及故障切换。状态：已实现。411 tests / 69 subtests 通过；Exa/Tavily 带 Key 的真实搜索、正文及模拟 Exa 限额后的真实 Tavily 恢复通过；真实两轮对话 Exa 核验、引用展示和后续来源复用通过。本机已重启生效，Brave 未启用。记录见 [认证验证](evidence/2026-09-17-web-failover/README.md#独立-key-接入补验2026-09-17)。

Rex 确认搜索 Exa → Tavily → Brave，指定 URL 读取 Exa → Tavily；两路正文均不可用时，单独尝试 Brave LLM Context。Brave 片段记录为 `extracted_chunks`，不得冒充指定网页完整读取；实际 URL、官网域名及证据支持范围继续校验。只使用最小公开查询或 URL；不改模型配置，不发送私人对话，不自动登录或购买额度。

- 仓库默认不联网；本机显式启用搜索/读取备用列表及 Tavily keyless。Brave 搜索与 Context 共用独立 BRAVE_API_KEY，未配置时跳过并在健康信息报告，不阻塞其他服务。
- 服务失败后由 Harness 有限切换；搜索无结果最多补充一次其他服务查询。缺凭证直接跳过，认证/限额/瞬态错误进入进程内冷却；有 Retry-After 时遵守恢复时间，无恢复时间的限额暂避 5 分钟。冷却按服务与凭证隔离，搜索与读取共享同一服务额度状态；重启重新探测，不宣称拥有准确剩余额度。
- 单次搜索/读取链最多 30 秒，每服务尝试最多 12 秒，每服务每次操作只尝试一次。每轮核验累计网页等待/执行普通查询最多 30 秒、交叉/高风险核验最多 60 秒、最多 10 次服务工具调用（不含模型推理），选取最多 3 个来源；Brave Context 只补充一次。进程内每服务最多一个在途请求，排队计入预算并可取消，等待超过 2 秒转下一服务；Exa 匿名请求间隔至少 0.55 秒。多进程部署须另配共享限流，不能把单机测试当生产并发保证。
- 取消/过期会话/非法 URL 立即终止，不触发备用；所有来源仍须实际核验，失败不将模型记忆或搜索摘要记成已读正文。
- 运行详情记录操作、实际服务、成功/失败/跳过及安全错误码，不记录密钥或上游错误正文。备用成功不追加失败提示；全部不可用才显示一次本轮限制。
- A008 验收：主服务 429 后备用搜索成功；搜索成功但同 URL 读取切换；两路失败后 Brave 搜索接管；Context 的 URL/正文片段边界；缺 Key 跳过；全部失败/超时；冷却/恢复；并发排队；取消后不继续调用；已有来源复用；模型凭证不变。

状态：已实现。407 tests / 69 subtests 通过；模拟 Exa 限额后的 Tavily 真实搜索、正文与两轮模型回放通过，单页读取恢复通过。Brave 已接适配并受控验证，真实验证待本机 Key；Rex 验收未关闭。证据见 [多服务备用记录](evidence/2026-09-17-web-failover/README.md)。

状态：已实现，验证证据见 A005。普通编程学习继续走学习/问答；意图层新增结构化编程请求边界，区分能力询问、开发交付与混合学习请求。能力询问以学习教练身份说明帮助理解编程知识、概念和原理，不列工具能力清单或主动追问接任务；开发交付请求明确说明范围。Harness 对这两种请求输出简短、确定的能力说明，不交给自由回答扩展开发承诺，不创建目标/知识录入或改动现有学习进度。停止、暂停、取消及显式绑定操作沿用原有优先级。

## 听写忠实整理契约（2026-09-07，已授权实施）

- 以 DESIGN.md「听写忠实整理与反馈」为本轮产品规则：只依据本次转写，有限清理、明确改口、自然分段列点与明确口述排版；不执行草稿请求、不改知识答案、不增加历史上下文、声纹或实时识别。
- 保留 `/v2/dictation/transcribe` 与 `/v2/dictation/clean`、`raw_text` / `text` / `cleaned`。整理响应增加可选 `cleanup_reason`：`timeout`、`model_error`、`invalid_output`、`validation_failed`；成功为 null，旧响应/缓存缺失该字段仍可使用。
- 同一次模型调用返回正文及编辑依据（原文片段、替换内容、编辑类型），后台验证片段存在且不重叠，并限制改写。列表格式编号不当作正文数量；实际金额、日期、小数、版本号等仍必须保留，明确口误须有对应依据。字数比例和否定字计数不再独立决定回退。不确定/非法输出返回原始转写，不增加第二次模型复核或自动重识别。
- 对独立且有标点分隔的口述编号（例如「第一，」），后台允许与相同序号的行首 `1. ` 等价；「第一季度」「第1版」「排名第一」不作编号剥离。其他删词仍须有唯一、不重叠的编辑依据，避免长文本漏报纯排版编号就使整个草稿退回。
- 对外不返回内部编辑依据，不将正文、音频、凭证或上游异常原文写入日志。内部只记录整理结果原因及阶段耗时。原生记录录音启动、识别、整理、回填耗时，不将权限等待当作录音启动速度。
- 成功保存后立即解锁草稿，完成提示与收尾动画不阻塞输入。整理回退使用非阻断提示，不标为需要重录；失败保存、取消、过期响应、会话切换、单次撤销及旧缓存兼容保持。

实施和质量/耗时证据见 m1-acceptance.md；真实体验仍需单独验收。

## Agent 输出可读性增量（2026-09-06）

- 生成侧统一采用正文混排规则：直接回应、短段落、按需小标题/表格/例子/线性流程；保留深度，不强制摘要折叠或缩短每轮教学。问题攻克、JD、评价及系统拼接文本遵守同一规则。检查题使用已有独立字段，正文不重复，学习计划仍用已有字段。
- 保留 message 字符串、SSE 白名单投影、状态/授权守卫和历史原文。展示不调用模型、不重写存量记录。客户端建立纯文本块模型并原生渲染，复制保留完整原文和链接。
- 生成端用 Markdown 无序列表标记并列项、有序列表标记步骤；客户端分别呈现圆点与序号，并保持折行悬挂对齐。不把普通段落自动猜测为列表。
- 流程采用 fenced mermaid 子集：flowchart LR/TD/TB，ASCII 节点 ID、方括号文字标签、单向 --> 组成一个连通无分支无环的链。支持链式声明和分行引用；不支持脚本、样式、点击、HTML、复杂边或分支。未闭合先展示已完整收到的标签；任何无法完整解释的语法保留原文，不丢弃尾部。
- 表格支持表头/分隔行及逐行正文、转义竖线和行内代码；列数不符的未完成行即时按原文保留。窄窗以列名配对的纵向行展示，流程节点按可用宽度转为竖排。块身份基于源文本起点，增量不重建已完成的前文身份。
- 检查题绑定实际任务/回答，在对应回答后呈现一次；后续追问仍按该任务全部已有回答去重，输入框使用简短作答提示，不复印完整题目。既有控制、保存确认、评分和学习进度含义保持。生成内容内的重要限制靠近相应结论；外部证据状态和来源继续由服务事实决定。

## 24. 长学习会话的活动上下文（2026-09-06，已获实施授权）

本节覆盖 §23、§19.4、§18.3 和旧 §7.3 的容量及摘要数字。默认活动输入上限 256,000 token；含系统规则、结构 schema、本轮输入、权威任务/确认状态、历史与资料。有效输入上限取本地上限与模型窗口减 4,096 回答预留的较小值；未知模型仅声明本地输入上限。继续用明确标注的保守估算，不冒充供应商精确计量。

- 圆环改为最近实际输入 / 有效活动输入上限，例如约 55K / 256K；详情分别列模型完整窗口、活动输入上限、整理触发值与回答预留。旧记录沿用其已记录预算，不伪装为新请求。未发送草稿和历史累计大小不计入。

### 19.4 数据、接口与验收接力

记忆排除使用现有 Session 动作入口的 `memory_policy` 兼容动作，携带独立的策略版本、内容版本与允许使用标志，不推进归档生命周期。Mac 保存完整证据与策略，服务只镜像执行所需的版本门禁；策略同步不能创建空会话。排除、纠正后，Mac 立即拦截旧关联输出，服务在同一执行事务锁内失效依赖、待确认稿及未提交知识；已完成的原子提交不回滚。重启重新同步版本门禁，消息/片段/提交均不得借旧引用恢复已失效内容。

失效同时作用于后续上下文，而不只是最后一段输出。Mac 在消息上下文中补充当前会话的 `invalid_memory_run_ids`（例如本机卡片版本已变化），服务保留历史但不再读取这些回答、派生摘要与未确认稿。引用过旧记忆的后续步骤继承其版本依赖；已失效材料所支撑的练习暂停续接，明确请求新的学习依据，不把旧掌握记录清空或自动判错。

容量首版使用包含系统规则、结构 schema、当前输入与实际裁剪后上下文的保守字节估算，并明确标“约”。本地请求预算及整理策略以 §24 为准、回答预留为 4,096；窗口信息按 §23 的供应商/模型映射或明确配置读取，未知模型窗口时仍显示已知的本地活动输入上限，并与模型完整窗口未知明确区分。关键约束超限则保留输入、请用户缩小范围；模型修复提示也重新计量。当前无已批准且验证合格的备用配置，内部名单保持空；每模型步骤共用最多两次／90 秒预算，SDK 不另叠加重试，已流出的答案不拼接新生成。

### 18.4 三层学习记忆

术语约定：旧章节中的「形成记忆」「长期记忆」若指提交动作，均指正式知识卡入库；不代表禁止记录学习经历。学习记录自动维护与正式知识提交是不同事务。

| 层次 | 保存事实 | 使用边界 |
|---|---|---|
| Session 工作记忆 | 当前目标、步骤、追问、纠正、未决问题和本轮理解证据 | 支持连续学习；不能用压缩摘要改写权威任务状态 |
| 跨 Session 学习记录 | 具体概念/范围、讲解与作答事件、是否用提示、评价时间、原 Session/消息/步骤出处 | 默认可用于后续教学，即使未入库；不是永久掌握标签，也不等于新增正式卡片 |
| 知识与复习记忆 | 已保存卡片及版本、来源、正式 ReviewAttempt、排期 | 提供教学锚点与回忆入口；不因调用记忆而改卡片、评分或日期 |

共同规则：

- 区分已讲解、自述理解、独立作答验证，以及正式复习表现；证据保留适用范围和时间。不把「存了卡」「看过」「快到期」分别推断成掌握、验证或遗忘。
- 跨 Session 默认复用与当前目标有关的学习记录和卡片；不得注入其他会话全部历史、未发送草稿或原会话的待确认/入库授权。用户确认的新目标交接与按需记忆检索是不同操作。
- 归档只是收纳与停止执行，不排除学习记忆。提供独立「不用于跨会话记忆」操作，保留历史但排除该 Session 及其派生摘要/索引的跨会话检索。归档只读不阻止用户收紧这项引用策略，改变策略不恢复生成。已明确保存的知识卡独立存在；排除原会话不等于删除卡片或否认其他独立来源。
- 引用必须能定位原卡片/学习记录，附知识版本、理解证据与时间。用户纠正时使不适用的学习推断失效，不篡改正式复习历史；删除/排除/版本更新要使相关检索缓存失效，不能由旧异步结果重新引入。

### 18.5 用旧知识教新知识

执行顺序：识别本轮意图及对象 → 检查目标/工作流/权限 → 检索相关学习事实 → 判断理解证据和关联用途 → 回答/教学并给可追溯引用。

- 检索不仅比较字词，还识别前置知识、相似概念、易混淆概念和迁移应用；先限定同一用户及允许范围，再按相关性、版本与证据选择必要内容。不为每次寒暄运行完整记忆检索。
- 通常只在正文融入一两个有用关联，不硬凑。已验证且近期表现合适的知识可尝试作为教学基础；只讲过的内容使用「之前讲过」，不能说「你已经掌握」。没有可靠记录时正常讲解，不编造个人经历。
- 例：用既有数据库索引知识辅助理解 RAG 检索，同时说明两者不等同，给出可打开的原知识卡。示例只说明目标行为，不证明某个用户已学过索引。
- 近期正式复习暴露误解时可简短补教；临近复习只提供可选回忆，不劫持当前目标。教学提及/随堂练习不更新 FSRS，正式复习仍走原提交流程。
- 关联先作为教学建议，不自动改正式卡片；无需先建设可视化知识图谱或新的常驻面板。学习记录可自动维护，正式入库仍受独立确认和版本守卫约束。

### 17.2 共同权限、接口与快照

- Mac 原子保存归档状态、递增 lifecycle_revision 与待发控制，立即冻结输出，服务同步版本。恢复/撤销只恢复编辑，不恢复旧 Run/队列。
- 新旧 Task、Run、事件及提交 claim/本地知识写入共同检查 active、生命周期、Run revision、确认对象/内容版本。归档禁止发送/改模式/重试/入库，可读历史。
- 新版会话任务由会话处理器执行，旧处理器只适配旧任务，不重复投影新版消息；迟到事件可消费诊断，不恢复内容/成果/知识。已原子完成的知识不回滚，未提交旧版本拒绝。
- Task ACK 与归档使用同一事务锁检查版本并记录完成，新 Mac 的旧/新 Task 保存均先 claim。旧客户端没有 claim 时仅可确认仍 active 且版本有效的任务；已 claim 的本机原子提交允许迟到确认，但不恢复 Session 或生成。
- 新增 `POST /v2/sessions/{id}/actions`（action_id/action/lifecycle_revision）；`GET /v2/sessions/{id}/snapshot` 与 `POST /v2/sessions/{id}/snapshot/restore`（schema_version=1，仅恢复缺失 checkpoint）。冲突返回 409，不静默覆盖。
- messages 兼容增加 `expected_event_seq` 与 `lifecycle_revision`；客户端已有历史、服务检查点却缺失时返回 CHECKPOINT_REQUIRED，不能静默新建空会话。相同恢复快照使用指纹幂等；恢复撤销旧 pending/草稿授权，只导入状态，不触发模型。
- 当前恢复实现只接受覆盖本机已消费游标且事件范围连续的快照。后台快照滞后时保留本机历史并报告 SNAPSHOT_STALE，不猜测重建模型检查点；任意崩溃时刻的增量快照合成仍需补齐验收，不能宣称全量恢复完成。
- 快照包含身份/生命周期/模式/摘要、消息、Run 元数据、Task/计划、来源和待办；恢复旧运行成 interrupted，不调用模型/入库，不把导入当作新授权。
- Mac 长期保存完整记录，Python 仅执行检查点。清理须终态、已 ACK、无活跃引用，不能仅按 TTL。任务/事件兼容增加计划/来源/生命周期，健康结果增加分类/时间/恢复方式；旧接口不删。
- SwiftData 增量字段可空或安全默认；只有有证据的旧记录回填，缺失来源、步骤、掌握不猜测。

### 17.3 五模式与成果

- Auto 普通问题只完成本轮，寒暄不建 Task，无用途资料轻整理；知识整理交付版本化结果即完成；资料学习按范围讲解完成，不以跳过检查证明掌握；探索收窄/地图/自动检索核对后教学（§25）；攻克独立作答与合理迁移追问通过才完成。JD 先拆解再由用户选题。
- LearningPlan/步骤保存稳定 ID、版本、顺序、当前步骤、完成条件、讲解/理解状态及消息/来源引用。调整保留未受影响进度，追问/补学不重跑整条流程。
- Task 完成、理解（unknown/self_reported/verified）、知识提交分别记录。攻克通过即完成目标，保存独立；拒绝保存清除 pending/required_action，不重挂或催促。条件确认/纠正使旧授权失效。
- 小结来自已有评价/步骤：达成能力、仍需练习、入库状态，不额外调用模型、不虚构掌握。练习不写正式 FSRS。
- 待处理统一旧采集/新学习中需人决定的冲突/证据不足，准确返回 Session；临时网络不批量入队。Today/侧栏使用共同状态，停止不叫完成；活动按完成回答/教学/正式复习唯一 ID 去重。

### 17.4 来源、交接与实时性

- 来源稳定 ID/type/version/locator/fetched_at，生成讲义继续/跳过后不变成用户资料，混合来源逐项关联。公开快照复用，刷新/时效检查生成新版本。
- 资料包记录真实用途/互补性/证据，不足不伪造；所有搜索/教学/核验显式传角色模型。HTTP(S) 初始、每次重定向和实际连接均检查公网，阻止私网/保留地址/DNS 绕过，限制跳转/大小/耗时，不携带模型凭证/Cookie。
- 交接只含确认目标、相关步骤/理解、必要来源/知识和未决问题，保留原 Session，不复制全历史/旧保存授权。
- 回答最终校验落盘后独立完成，摘要后台失败不改成功。摘要绑定上下文版本，过期结果丢弃。
- SSE 保存后异步合并 ACK，慢 ACK 不阻塞读，不确认未落盘事件；稳定回答 ID/seq/revision 保证重放不重复。未完成内容不进入完成摘要/成果。
- 分测本地回显、识别、首段生成/显示及总耗时；受控目标 100 ms 本地反馈、200 ms 事件呈现、100 ms 显示缓冲，供应商慢调用单报。

- 保留单侧栏、开放居中回答、原生底部输入。按需显示结论/解释/例子/易错点/来源/下一步，不强套卡片模板；安全渐进 Markdown，最多一个主操作，保留自由输入。

## 1. 为什么需要 V2

V2 实施前的基线是一条批量任务链：Mac 保存采集内容，Python 服务运行整张采集图，结束后客户端才能取得结果。服务不可用时界面只显示“等待服务恢复”，任务事件没有进入主要体验，所谓“思考过程”实际只是本地状态历史。

这不能满足学习教练的核心体验：用户输入后应立即得到接收反馈，知道 Agent 当前在做什么、为什么需要自己参与、如何恢复，并能在同一上下文中继续学习。

V2 把产品从“一次采集对应一次模型任务”改为：

```text
学习 Session（持续对话与上下文容器）
├── Message / AgentRun（独立消息与本轮执行；可以没有学习任务）
└── Learning Task（一次可暂停、恢复和完成的学习目标）
    ├── Message（按需关联的用户与教练对话）
    ├── Task Event（可回放的工作过程）
    ├── Source / Evidence（资料与证据）
    └── Knowledge Link（形成的长期记忆）
```

V2 不是通用聊天或多 Agent 平台。用户只面对一个专门的学习教练，内部根据学习目标选择受控工作流。

## 2. 产品对象与生命周期

### 2.1 Agent Session

Session 是一段连续学习对话的上下文容器：

- 新 Session 默认 Auto，也可选择知识整理、资料学习、主题探索、问题攻克；选择作用于当前目标及后续任务；
- 保存完整可见对话、结构化摘要、当前与历史任务、资料引用和知识引用；
- 一个 Session 可以连续完成多个相关 Learning Task；
- Task 完成不会自动关闭 Session；用户可以继续学习或手动归档；
- 归档只从活跃列表移除，不删除对话、任务、资料或知识关联；
- 归档是无需确认的直接操作；若存在前台 Run，先持久化 stop 控制并冻结当前可见输出，再归档。归档反馈提供撤销，旧 revision 的迟到结果不能恢复输出；
- Session 保存自动主题标签和可空的人工主题标签。人工值覆盖自动值，用户可恢复自动；关联知识标签来自 KnowledgeReference，只读且不与知识主题模型合并；
- Session 之间默认隔离，不把其他 Session 全部历史注入当前任务。

Session 状态：

```text
active → archived
archived → active
```

已归档 Session 可以永久删除，须先确认不可恢复的范围。默认仅删除会话；用户可另选删除该会话独有、可证明创建归属的知识及练习记录。共享、仅引用和归属不明的卡片保留。细节见下文条件式教学与删除契约。

### 2.2 Learning Task

Task 是 Session 内一个可执行学习目标，不等同于一次输入或一次模型调用。一次 Task 可以跨多轮对话、等待用户选择、暂停、重试并恢复。

统一状态：

```text
accepted
→ queued
→ running
↔ awaiting_user
→ committing
→ completed
```

异常与终止状态：

- `retryable_failed`：外部服务、超时或可恢复结构错误；保留输入，由用户明确重试，不因重启自动重发模型请求；
- `needs_attention`：证据冲突、内容风险或必须由用户决定；
- `cancelled`：用户取消当前任务，Session 与已有消息仍保留；
- `terminal_failed`：无法在当前约束下继续，显示原因和可行下一步。

`completed` 只表示该 Task 的完成条件满足，不代表 Session 已归档，也不代表产生了长期记忆。

### 2.3 AgentRun 与 Session Event

AgentRun 管理一次前台回复/执行，可以不关联 Task；Task 管理跨轮学习目标。Run 状态为 accepted / queued / running / completed / interrupted / retryable_failed / terminal_failed；Session 的 paused 标志阻止停止后自动消费队列。Run 保存 revision、输入消息 ID、所处节点、意图、失败信息和结果引用。

新输入默认 steer，在可处理节点纳入。明确 queue 留待当前执行结束。stop 只停止回复并暂停队列，resume 显式恢复；cancel_task 结束学习目标但不删历史。模型调用不可取消时本地废止旧 revision，丢弃迟到结果，不宣称上游已停止计算。所有模型后的写状态、事件、知识提交检查当前 revision；停止不回滚已经完成的提交。

Session Event 支持没有 Task 的对话，session_seq 单调递增，包含 run_id/revision、可空 task_id、实际阶段、用户摘要、模型与脱敏诊断、消息及可选 Task 快照。Mac 先保存事件和消息再 ACK，不从文本反推 Task 状态。

### 2.4 Message 与 Task Event

Message 是用户应该阅读的对话内容；Task Event 是可回放的执行事实。两者不能混为模型思维链。

- 用户发送后，Mac 必须先保存用户 Message 并立即显示；
- 服务接受任务后，可以产生教练 Message、选择卡片或问题；
- Event 记录阶段、状态、路由依据摘要、耗时、重试、错误和恢复；
- Event 不保存或展示隐藏思维链、密钥、Authorization、无关完整正文；
- 重启后客户端按事件顺序号恢复，不能重复插入消息或知识。

## 3. 五模式与统一意图

产品只有 Auto、知识整理、资料学习、主题探索、问题攻克五个模式。“用户选择具体模式”是操作，不是第六种模式。旧协议枚举 `memory_organization` 保留，显示名称统一为知识整理。

| 模式 | 入口与默认行为 | 边界 |
|---|---|---|
| Auto | 结合本轮语义、当前任务和上下文自动调用四条工作流的所需能力 | 同目标内自动转接，界面保持 Auto；入库、改变目标、新建 Session 需要明确意愿 |
| 知识整理 | 梳理主题、知识点与关系，先交付整理结果 | 不默认已理解或入库；正式提交须理解条件满足且明确同意 |
| 资料学习 | 用户资料、公开资料或标注的生成讲义；分段讲解与理解检查 | 可追问或跳过检查；自述理解与验证掌握分开，不自动入库 |
| 主题探索 | 收窄目标、学习地图与合适资料；随后教学 | 稳定知识直接讲解；需查证时按需搜索、阅读与核验，证据足够即停止，不设资料确认门槛 |
| 问题攻克 | 先答再校准、知识依赖与路径、独立作答及追问 | 答案、提示、跳过或自述理解均不等于攻克完成 |

### 3.1 输入与模式的关系

- Auto 的普通问题先解答，深入学习可选；不强制创建训练 Task。
- Auto 收到无用途说明且无任务可续接的资料，先轻量整理，不要求用户替系统分类，也不自动教学、入库或排期。
- 主动选择问题攻克后提交新问题，默认展开攻克流程；问候、追问和“这次只解释”不强行套流程。
- 本轮明确要求优先；上下文解释指代；所选模式决定默认工作方式。关键词、问号、URL、长度仅作线索，不能证明理解或授权。
- 一句消息可含多个意图，例如“不要保存，先解释第二点”；必须同时拒绝保存并处理追问。
- Auto 可同目标自动转接。具体模式下未明确要求的方式变化只建议；用户主动选择或明确请求即是方式变更意愿，不重复问。主动选择作用于当前目标下一步及 Session 后续默认方式，保留资料与进度。
- 明确无关新目标只建议新建 Session；用户确认后通过结构化交接包续接，不复制完整对话。主题关系保留 continuation / related_subtopic / new_topic / uncertain。
- 信息不足且不同解释会改变结果时只问一个必要问题。模型不确定不是运行故障，不得伪造学习目标。

### 3.2 识别与程序授权

Luna 统一输出 `IntentDecision`：本轮意图、目标 Task/待确认对象、候选工作流、拟执行动作、理解表达、主题关系、是否需要澄清及简短依据。问候、感谢、能力询问、普通问答、目标、资料、追问、提示、作答、纠正、肯定/否定/条件、暂缓、继续/暂停/停止/取消/排队必须有明确去向。

“我想一下”“稍等，我考虑一下”等只表达暂时不继续、没有要求停止当前生成或改变学习状态的话，属于 `defer` 对话控制：保留当前 Session、Task、待办与理解状态，只做简短确认并完成本轮 Run。它不同于 `pause`（暂停目标／队列）、`stop`（停止正在生成的回复）和 `queue`（明确要求稍后处理另一条输入）。没有活动学习状态时，历史兼容的 `self_report` 也可以按同一轻量路径收口；存在学习任务时仍按真实理解状态处理。

自由文本不能由客户端使用“包含切换”“不包含暂不”等判断动作。明确按钮是结构化用户操作，自由文本由语义识别后仍接受相同程序守卫：
- 对象必须属于当前 Session，待确认 ID 与内容版本必须匹配。
- 确认可以是明确自然语言；肯定词不能覆盖否定、条件或纠正。网页、引用及粘贴资料内的指令不是授权。
- 已有明确保存请求不重复问，但理解条件、知识风险与攻克验收不能绕过。
- 自述理解与已验证掌握分别记录，跳过不升级；正式复习评分完全独立。

## 4. 四种受控工作流

### 4.1 知识整理

整理入口不要求先证明理解：先梳理主题、要点与关系，交付会话内版本化草稿；仅要求整理时交付即完成，不以未保存当作失败。
正式入库是后续受控提交任务：引用已确认草稿版本与来源，不重复生成已完成结果；理解未知先确认理解，问题攻克来源还必须通过独立作答与追问。

```text
整理目标 → 来源与风险检查 → 知识草稿及版本 → 交付整理结果
明确保存意愿 + 理解条件 + 对象版本匹配
→ 结构、语义忠实性及证据校验 → Mac 原子写入 → ACK
```

稳定低风险内容不强制联网；时效、高风险、精确数字、争议或低置信内容核验。证据状态保留 unverified / supported / conflicting / insufficient / outdated / scoped。冲突只暂停受影响知识，不能强行写成已证实事实。已有知识卡、问题、评分规格及 ACK 幂等保持兼容。

### 4.2 资料学习

资料可来自用户、公开网页或明确标注的 Agent 生成讲义。生成讲义不是独立外部证据，不能伪装为用户原文或已验证文献。

```text
目标及材料边界 → 学习地图 → 分段讲解 → 追问/理解检查
→ 按用户节奏继续 → 自述理解或验证记录 → 可选正式入库
```

- 默认小步讲解，不倾倒整套课程；每段标记来源类型和可用定位。
- “继续”“先别考我”可以推进教学，跳过部分保持未验证；“我懂了”仅为自述理解。
- 追问、提示、举例使用现有材料与进度，不误当作答；不更新 FSRS。
- 已知误解保留并补教，不能伪造已验证掌握；正式入库仍需理解条件与明确意愿。

### 4.3 主题探索

信息缺失且会影响教学时，只澄清一个关键问题；用途足够明确后建立学习地图并开始教学。
- 模型组织讲解；稳定知识无需联网，明确查证/时效/风险/不确定内容才筛选、读取与核验公开来源；相关追问复用适用的已读资料。单条可靠来源可以足够，不要求用户确认资料包。
- “直接教我”继续同一目标的教学，仍遵守检索条件；不会被当作练习答案或已理解证据。
- 搜索失败仅影响外部核验：有限尝试后可继续稳定基础内容，简短说明限制；风险、争议或时效结论保留待核实，不编造链接。

来源名称、日期/版本、定位与证据状态内部持久化。正文直接讲解并引用已读链接，不展示内部枚举或工具门槛；模型讲解不冒充独立外部证据。

### 4.4 问题攻克

进入条件：用户明确希望掌握问题、准备面试/工作解题、提供完整 JD，或已经选择问题攻克后提交新问题。Auto 普通知识问答只调用基础回答能力，不自动启动完整训练。

具体问题采用“先答再校准”：

```text
识别问题类型、目标和风险
→ 立即给一版可使用的基础答案
→ 标出关键假设、置信度和证据状态
→ 询问一个最影响深度的背景问题
→ 建立知识依赖与缺口地图
→ 给出针对性学习路径
→ 针对缺口讲解与练习
→ 用户独立作答
→ Agent 评价并追问
→ 达到独立作答标准
→ 询问是否形成记忆
```

首轮答案至少包括：

1. 结论或参考答案；
2. 相关知识点及其依赖关系；
3. 当前可能存在的认知缺口；
4. 针对性学习顺序；
5. 下一步校准问题。

面试类问题额外提供可口头表达的回答结构；一般问题提供可执行解法。稳定基础知识先直接回答；时效、高风险、争议或低置信内容自动查证，完成查证前明确标记为暂定答案。

完成判断：

- 用户必须先独立作答；
- Agent 从正确性、完整性、表达和迁移能力反馈；
- 根据薄弱点追问或补教，不重复整份答案；
- 能脱离参考内容回答当前题并处理合理变式后，Task 才可完成；
- 练习结果不直接写入正式复习评分；
- 完成后由用户确认是否形成长期记忆。

JD 入口先执行：

```text
解析岗位目标与职责
→ 生成能力地图
→ 标记高风险与高频要求
→ 生成按优先级排列的问题清单
→ 用户选择一题
→ 进入具体问题攻克
```

JD 不一次性生成整份答案，也不未经用户选择自动展开所有题。

## 5. 主界面反馈契约

### 5.1 即时反馈

提交一轮输入时：

1. Mac 生成稳定 `client_message_id`，先本地保存并立即显示用户消息；
2. 本地保存独立 Message；服务创建 AgentRun，确认存在学习目标时才关联 LearningTask；
3. 服务尚未就绪时显示“正在启动学习服务”，而不是沉默或伪装成处理中；
4. 服务接受后显示第一个真实工作阶段；
5. 无法启动时显示具体原因、重试和打开设置／运行详情入口；原始输入仍保留。

### 5.2 工作过程

主界面使用用户语言展示：

- 正在理解你的目标；
- 正在检查资料；
- 正在整理答案；
- 等你选择资料；
- 等你回答；
- 正在形成记忆；
- 已完成；
- 需要处理。

这些文案必须来自真实 Task Event，不得用循环动画假装模型仍在工作。

### 5.3 运行详情

每个 Task 卡片可展开“运行详情”，展示：

- 节点与阶段；
- 路由依据摘要；
- 开始时间、结束时间和耗时；
- 尝试次数与重试原因；
- 错误码、失败节点和恢复动作；
- 脱敏后的结构化摘要。

运行详情仍不展示隐藏思维链。开发模式中的全局运行记录继续存在，用于跨 Task 排查。

## 6. macOS 信息架构

主窗口侧边栏正式入口调整为：

1. **今天**：复习计划、学习活动指标、待处理和最近结果的数据看板；不提供输入；
2. **知识库**：查看、纠错、暂停和管理长期知识；
3. **待处理**：证据冲突、结构错误和需要人工决定的任务。

主窗口使用单一可收缩侧栏。今天、Agent、知识库、待处理四个入口固定，其下 Session 区跨页面保留。Agent 打开准备页，点击会话准确打开历史；不增加第二侧栏或窄窗 Session 弹层。

学习工作区：

```text
主侧栏                         Agent 工作区
────────────────────────────────────────────
今天                           标题 / 标签 / 归档
知识库 / 待处理                完整对话与真实流式回答
学习会话 [搜索] [归档视图] [+]  行内运行过程与操作
  活跃或已归档 Session         底部输入框
设置                           材料 / 学习方式 / 思考强度
```

- App 默认打开今天；点击 Session 恢复准确的历史和草稿，没有 Session 时提供新建入口。Today、侧栏和学习页共享准确的 selectedSessionID；
- 用户可新建、继续、归档和恢复 Session；
- Session 行按 §21 显示标题、最多一个主题标签与必要状态符号，不显示模式/完成文字；选中、悬停、失败、运行中和已归档不能只靠颜色区分；
- 右侧采用轻量顶部栏、居中内容列和底部锚定输入框。Agent 回答直接位于内容画布，用户消息轻量右对齐，运行与错误状态插入对应回答位置；
- 模式选择作用于当前目标和 Session 后续默认方式；切回 Auto 后由 Agent 自动调度，保留进度；
- 输入支持文字和公开链接；M1 不提供语音按钮；
- 键盘提交、焦点、长内容、窗口缩放和中英混排必须可用；
- 状态不能只依赖颜色或动画；Reduce Motion 下保持同等因果反馈。

Today 在状态卡下显示最近 26 周学习热力图。活动只来自已完成的知识回答、资料学习步骤和正式复习；问候、页面打开、失败、未完成生成与 preview 不计入。热力强度为 0、1、2、3–4、5+；按用户当前系统日历与时区归日并以 Run／ReviewAttempt ID 去重。悬停显示日期与类型分布，点击展开可跳转的当日明细。“最近学习”默认三条，页面内展开后在固定高度区域滚动全部进行中 Session。

## 7. 本地服务与恢复

### 7.1 App 托管服务

开发 Mac POC 由 App 管理本机 Python 服务：

- App 启动后在后台检查 `127.0.0.1:8742/healthz`；
- 未就绪时使用项目已配置的本地 Python 环境启动服务；
- 监控进程退出和健康状态，采用有限退避自动恢复；
- 同一 App 生命周期只允许一个受托管实例；
- App 退出时终止自己启动的子进程，不终止外部手动启动的兼容实例；
- 环境、解释器或配置缺失时展示可操作诊断，不显示密钥；
- Debug 使用本机 Apple Development 证书与固定 Team / bundle 身份，避免每次临时签名变化破坏系统的应用识别；CI 可显式关闭签名，仅用于编译。Release 分发、自启动代理与安装包仍不在 M1。

### 7.2 数据事实来源

Mac 本地数据库是长期事实来源，保存：

- Session 与归档状态；
- Session 自动／人工主题标签、标签版本与更新时间；
- 用户和教练 Message；
- AgentRun、LearningTask、待发送消息与操作，以及 Session/Task 最后消费与 ACK 序号；
- Event 的用户可见与诊断字段；
- Source、Knowledge 和关联；
- 结构化 Session 摘要。
- AgentRun 的可空活动类型与完成时间，以及 ReviewAttempt 的创建／完成时间；它们只为可验证的学习活动与正式复习写入，不从用户可见文案反推。

Python 保留执行 checkpoint；Session 消息与事件按 Mac ACK 裁剪（§8.1），旧 Task 投影仍用原有保留规则。未完成输入、确认版本和幂等收据不能因普通缓存裁剪丢失；服务重新取得任务时使用稳定 ID。

### 7.3 上下文预算（既有兼容实现，目标见 §18.3–18.5）

每轮上下文由以下部分组成：

- 当前 Task 目标和状态；
- 当前 Session 近期消息；
- 结构化 Session 摘要；
- 当前资料相关片段；
- 最多 5 条相关既有知识。

以下为历史 POC 描述，当前容量与完整消息策略以 §24 为准：路由与摘要曾规划约 3k tokens，教学与问题攻克约 16k tokens。旧 POC 用近期条数、字段长度和阶段摘要限制叙事窗口，未实现精确 token 计量；不能把目标预算当作严格性能保证。当前结构化任务状态与版本不被摘要改写。

跨 Session 可按 §18.4–18.5 检索允许复用的学习记录、相关知识，或接收用户确认的交接包；不注入其他会话全部对话、草稿或操作授权。上述最多五条字符串是当前兼容实现，不是完整学习记忆的最终结构。

### 7.4 新 Session 交接包

用户确认新建 Session 后生成：

- 最新输入；
- 推断学习目标；
- 相关已确认决定；
- 来源与知识引用；
- 未解决问题；
- 来源 Session ID。

不复制完整聊天记录。交接包以系统摘要形式显示，用户可以返回来源 Session。

## 8. API 与结构化契约

### 8.1 HTTP API

新入口（兼容扩展，不移除下面的旧接口）：
- `POST /v2/sessions/{session_id}/messages`：client_message_id、content、mode、delivery=steer|queue、受限上下文及可选明确操作；立即返回 message_id、run_id、可空 task_id。
- `GET /v2/sessions/{session_id}/events?after_seq=` 与 `POST /v2/sessions/{session_id}/ack`：按 Session 回放与确认本地消费位置。
- `GET /v2/runs/{run_id}` 与 `POST /v2/runs/{run_id}/actions`：稳定 action_id，stop/resume/retry/cancel_task/set_mode；明确操作检查 Session、Run、目标及状态。
- `POST /v2/tasks/{task_id}/commit-claim`：本机知识写入前领取当前有效提交。领取前的停止／替代撤销该提交；领取后进入幂等本机事务，停止不宣称撤回已经提交的知识，重启续接同一提交并 ACK。
- 自由文本一律进入 messages，不由 Swift 猜测 actions。旧 Task 动作接口保留，但同样使用确认与版本守卫。
- `IntentDecision` 为严格结构化枚举，不确定用澄清而不是四选一；运行异常区分超时、模型服务、空输出、拒绝及结构校验。仅结构修复最多一次，重试计数按实际模型请求，不把首次失败显示为第二次。
- 入库快照返回已确认的对象/草稿版本；Mac 只消费仍然有效的 committing 状态，同一知识 ID 与 ACK 幂等。停止或内容纠正先使未提交快照失效。已经完成提交不假装撤销。
- Mac 完整落盘后才 ACK。Python 对已 ACK 的 Session 回放缓存保留最近 64 条事件、至少最近 32 条消息及未完成运行所需输入；累计序号不重置，已完成 Run 释放模型输出缓存。Task 历史兼容投影暂保留；Mac 是完整原文、事件和引用的长期记录来源。
- 五模式修订的运行等待阈值：结构化能力探测默认 45 秒、正式模型步骤默认 90 秒，均可由环境变量覆盖。2026-09-03 的小型结构化探测实测约 33–39 秒，旧 8 秒探测会过早判为不可用；等待期间仍接收输入和停止操作，不以延长等待宣称模型已恢复正常。
- 开发 App 托管进程首次健康检查给予 90 秒冷启动时间（包括系统文件访问与 Python 依赖初始化），不能在 30 秒时打断仍在启动的服务；已就绪服务连续 10 秒不可达后才终止恢复，不因一次健康检查失败重启。仍按既有退避重试、连续失败最多四次；健康恢复后清零。记录解释器就绪、组件导入完成与健康就绪阶段，失败说明对应阶段，不把无输出直接断言为权限拒绝。旧进程的输出或退出回调不得覆盖新一次启动。
- 开发工程位于 macOS 受保护的桌面目录；临时签名变化可能要求重新授权。启动超时且没有服务输出时，提示检查系统文件夹访问授权与 `.venv`，不一概标为模型故障。由用户在系统提示或隐私设置中授权，不自动改权限、不绕过系统保护。

以下为旧 V2 Task 兼容接口：


`POST /v2/sessions/{session_id}/turns`

- 输入：`client_message_id`、`content`、`content_type`、Session 模式预设、客户端已知任务状态；
- 行为：幂等接受一轮输入，立即返回；
- 输出：`message_id`、`task_id`、`status=accepted|queued`、`next_event_seq`。

`GET /v2/tasks/{task_id}`

- 返回 Task 当前状态、模式、当前阶段、等待动作、错误和最终摘要。

`GET /v2/tasks/{task_id}/events?after_seq={seq}`

- 按序返回尚未消费的事件；重复读取结果稳定；事件窗口丢失时返回需要任务快照恢复的明确错误。

`POST /v2/tasks/{task_id}/actions`

- 输入：稳定 `action_id`、动作类型和结构化 payload；
- 支持用户选择、确认、回答、重试、取消、建议切换模式、创建交接包；
- 同一 `action_id` 幂等。

`POST /v2/tasks/{task_id}/ack`

- 输入：最后持久化事件序号以及需要确认的知识 ID；
- 只有 Mac 已可靠保存结果后才 ACK；重复 ACK 幂等。

v1 capture 与 review API 在 V2 真实体验验收通过前保留。

### 8.2 Task Event

每条事件必须包含：

- `event_id`、`session_id`、`task_id`、`seq`；
- `occurred_at`、`stage`、`state`、`node`；
- `user_summary`、可选 `detail_summary`；
- `attempt`、可选 `duration_ms`；
- 可选 `error_code`、`recovery_action`、`required_action`；
- 可选 `message` 或结构化结果引用。

事件顺序号在单 Task 内严格递增。客户端按 `event_id` 和业务对象 ID 去重。

### 8.3 结构化模型输出

必须定义并校验：

- `IntentDecision`（本轮意图、指代、目标、动作、工作流、澄清、依据与可选 `session_tags`）
- `ModeDecision`（保留旧协议兼容）
- `SourcePack`
- `EvidenceAssessment`
- `LearningPlan`
- `LessonStep`
- `UnderstandingCheck`
- `QuestionAnalysis`
- `JDAnalysis`
- `ProblemAnswer`
- `KnowledgeGapMap`
- `MemoryPackage`

模型输出结构错误最多自动修复一次；仍失败则进入可重试失败或待处理，不能伪造完成。

## 9. 模型角色

角色配置独立于产品模式：

- **Luna**：统一对话意图、主题关系与工作流判断、Session 摘要；§15 允许纯问候、感谢和简单能力介绍同次轻量回应；
- **Terra**：教学、问题回答、记忆生成、普通证据评估与语义验证；
- **Sol**：高风险事实和证据冲突判断。

启动时执行与实际请求相同的结构化能力检查，空响应、拒绝、结构校验失败不能报 ready。某角色不可用时：

- 当前实际配置仍使用固定角色模型；已实现的内部备用门禁须遵守 §18.6，但合格名单为空，不能降低用户选择的强度或擅自扩展供应商；
- 内部恢复耗尽后，受影响 Run/Task 显示用户可理解的影响与恢复动作，不展示原始模型错误；
- 不受影响的本地浏览、Session 编辑和历史数据仍可使用。

## 10. 兼容、隐私与非目标

## 25. 条件式教学、删除与旧数据接回（2026-09-06）

本节替代旧版主题探索的固定两条互补来源和资料包确认门槛。

- 讲解由模型组织；稳定新知识可直接回答，需查证时才读取网页，相关追问复用适用的已读资料。Agent 按需筛选、读取和引用；“直接教我”本身不决定是否核验。来源按支持范围和证据充分性判断，单条可靠来源可以足够。
- 搜索区分未调用、调用失败、无合适结果、证据不足、核验完成。缺词时根据当前公开主题补建查询；禁止发送私人整段对话、卡片、凭证及未发送草稿。有限失败后可继续稳定基础内容，风险、时效和冲突结论保持待核实。
- 模型知识、网页、会话记忆、卡片是有条件的模块。无历史或无相关内容时跳过个人关联；归档可召回、关闭记忆不可召回。不把讲过、自述、预览练习升级为独立验证或正式复习。
- 不确定且缺问题时补齐一个必要澄清，再执行依赖该判断的操作。结构错误属于系统错误；诊断仅包含字段位置、错误类型、合法枚举，以及固定的输出格式类别、字符/字节长度、JSON 解析行列/位置和受限请求关联 ID，不记录原始输出、输入、推理文本或凭证。每步骤最多两次模型/搜索尝试，记录真实尝试次数；保留成功 checkpoint。
- 格式恢复（2026-09-08）：每次失败尝试都保留独立脱敏事件，不能只留下第二次错误。JSON 语法/封装错误与字段/枚举错误分别生成定向修复规则；规则放在可信系统指令中，原始用户上下文保持结构完整。围栏错误明确要求重新输出完整 JSON 对象，不能剥围栏后直接接受。只在未显示正文、未失效且剩余预算允许时修复一次；模型、思考强度、最终 schema 与授权检查不变，停止/归档后的迟到结果不可发布。第二次仍失败则保留输入和进度，供用户手动重试。
- 完整的“直接教我”等教学控制语句在已知目标下直接续教；更长或引用中的文本仍交模型识别。判题意图必须提供能定位到本轮用户输入的 answer_evidence，失败仅做一次结构修复。讲过、继续和跳过检查不能在正文或状态中表述为已理解。
- 支持 Session 的 memory_lookup 事件及 POST /v2/runs/{run_id}/memory-results：绑定请求 ID、Run revision、Session lifecycle revision；最多 12 个候选，模型可选 0–2 条。幂等回传，拒绝过期结果；10 秒无结果则跳过。旧客户端候选字段继续兼容。
- 永久删除仅针对已归档会话；菜单和批量入口一致。确认时显示会话和影响数量，独有知识删除选项默认关闭；执行前重新计算，范围改变须更新确认。无法证明创建归属的历史卡片保留。
- 本地先以事务保存不含正文的 tombstone 和清理队列，再删除会话相关消息、任务、事件、Run、草稿、摘要、索引与 checkpoint。离线立即隐藏并停止召回，待服务恢复后幂等清理。服务及本地拒绝旧快照、旧结果和导入复活；其他会话原文保留，派生引用与缓存失效。保留卡片的来源链接显示“原会话已删除”。
- 旧库接回：备份源库与当前库，先副本演练；关闭日常 App 后事务导入，按原 ID 去重、冲突停止不覆盖，保留原库。接回 8 张卡、3 条预览练习及必需来源/题目/排期/关联；预览身份和原排期不变，不重启旧任务。历史索引仅从可确认的完成学习证据补建。
- 验证范围：原始 RAG 三轮、条件调用、搜索/格式失败与恢复；单个/批量/共享/离线删除和防复活；导入幂等、冲突回滚和预览统计。云端 CI 保持停用，结果写入本地验收记录。
