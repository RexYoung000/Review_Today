### 18.2 两个独立的用户选择

- 输入框底部「学习方式」只提供 Auto、知识整理、资料学习、主题探索、问题攻克。每个 Session 保存自身选择；新 Session 默认 Auto。主动切换从当前目标下一步生效，保留有效资料与进度，后续目标沿用。
- 「思考强度」只提供智能、深入思考，不采用 Lite/Pro/Ultra 商业档位。首用默认智能；现有 Session 保留其选择，新 Session 继承用户最近一次主动选择。发送、重启、目标完成或内部故障恢复都不得将深入思考重置为智能。
- 智能允许内部按任务调度，深入思考要求对应的能力保障。具体模型与强度映射必须实测并记录；不通过更改用户选择掩盖模型不支持。两按钮不是权限开关，不新增常驻权限面板。

### 18.3 当前上下文不等于学习记忆

- 当前上下文由本轮输入、任务与确认状态、近期消息、版本化摘要和必要检索结果组成；不重复发送完整历史。
- 输入框附近的容量提示表示本轮实际上下文占可用输入预算的比例，不是学习进度、永久记忆容量或全部聊天总长度。预算须考虑模型窗口与回答预留；应用自设更小预算时必须在详情说明。无法精确计量时标「约」或「暂不可用」，不能用条数伪造精确百分比。
- 容量接近预算时整理较早上下文，保留原始会话以便回查；目标、用户约束、确认对象/版本及当前进度不得依赖有损摘要成为唯一事实来源。具体计量、整理阈值与预留参数由实施测试确定并回写，当前没有数字阈值验收证据。
- 整理后台化、绑定上下文版本；不因整理清空草稿、改变强度/工作流、继承旧授权，或把已完成回答改成失败。路由、教学等内部请求分别受限，界面不随内部角色轮流显示互不相干的百分比。

### 18.4 三层学习记忆

术语约定：旧章节中的「形成记忆」「长期记忆」若指提交动作，均指正式知识卡入库；不代表禁止记录学习经历。学习记录自动维护与正式知识提交是不同事务。

| 层次 | 保存事实 | 使用边界 |
|---|---|---|
| Session 工作记忆 | 当前目标、步骤、追问、纠正、未决问题和本轮理解证据 | 支持连续学习；不能用压缩摘要改写权威任务状态 |
| 跨 Session 学习记录 | 具体概念/范围、讲解与作答事件、是否用提示、评价时间、原 Session/消息/步骤出处 | 默认可用于后续教学，即使未入库；不是永久掌握标签，也不等于新增正式卡片 |
| 知识与复习记忆 | 已保存卡片及版本、来源、正式 ReviewAttempt、排期 | 提供教学锚点与回忆入口；不因调用记忆而改卡片、评分或日期 |

共同规则：

- 区分已讲解、自述理解、独立作答验证，以及正式复习表现；证据保留适用范围和时间。不把「存了卡」「看过」「快到期」分别推断成掌握、验证或遗忘。
- 跨 Session 默认复用与当前目标有关的学习记录和卡片；不得注入其他会话全部历史、未发送草稿或原会话的待确认/入库授权。用户确认的新目标交接与按需记忆检索是不同操作。
- 归档只是收纳与停止执行，不排除学习记忆。提供独立「不用于跨会话记忆」操作，保留历史但排除该 Session 及其派生摘要/索引的跨会话检索。归档只读不阻止用户收紧这项引用策略，改变策略不恢复生成。已明确保存的知识卡独立存在；排除原会话不等于删除卡片或否认其他独立来源。
- 引用必须能定位原卡片/学习记录，附知识版本、理解证据与时间。用户纠正时使不适用的学习推断失效，不篡改正式复习历史；删除/排除/版本更新要使相关检索缓存失效，不能由旧异步结果重新引入。

### 18.5 用旧知识教新知识

执行顺序：识别本轮意图及对象 → 检查目标/工作流/权限 → 检索相关学习事实 → 判断理解证据和关联用途 → 回答/教学并给可追溯引用。

- 检索不仅比较字词，还识别前置知识、相似概念、易混淆概念和迁移应用；先限定同一用户及允许范围，再按相关性、版本与证据选择必要内容。不为每次寒暄运行完整记忆检索。
- 通常只在正文融入一两个有用关联，不硬凑。已验证且近期表现合适的知识可尝试作为教学基础；只讲过的内容使用「之前讲过」，不能说「你已经掌握」。没有可靠记录时正常讲解，不编造个人经历。
- 例：用既有数据库索引知识辅助理解 RAG 检索，同时说明两者不等同，给出可打开的原知识卡。示例只说明目标行为，不证明某个用户已学过索引。
- 近期正式复习暴露误解时可简短补教；临近复习只提供可选回忆，不劫持当前目标。教学提及/随堂练习不更新 FSRS，正式复习仍走原提交流程。
- 关联先作为教学建议，不自动改正式卡片；无需先建设可视化知识图谱或新的常驻面板。学习记录可自动维护，正式入库仍受独立确认和版本守卫约束。

### 18.6 内部主备与质量恢复

- 主备服务由内部配置确定，只能使用已允许的数据处理范围和经能力验证的模型。不要求学习用户逐次选择模型，不在正常界面宣布切换供应商；本次文档不配置任何新供应商、密钥或备用名单。
- 当前 Run 遇临时连接/超时/服务不可用，可以在统一的有限次数与总时限内重试或切换合格备用。探测、SDK、步骤修复不能层层叠加无限重试。401/403、凭证缺失、明确不支持仍分类处理，不能通过换线路绕过访问限制。
- 备用不得降低选定思考强度、改变学习目标/工作流、扩大工具权限或绕过质量与入库检查。无合格备用时诚实失败；已经失败/停止/取消/归档的 Run 不因后台恢复自动重新启动。
- 保持同一可见回答、累计耗时和已完成步骤，内部尝试单独记录。已有部分正文先按稳定 ID/seq/revision 续接；不能把另一模型的新全文直接拼到旧片段。无法安全续接时保留未完成状态并提供重试，而非声称无感恢复成功。
- 内部恢复成功不打断用户；显著延迟只显示「处理时间稍长」。恢复失败才说明影响、实际已保留内容和有效操作；后台主备信息只在开发诊断，不进入默认运行详情，不伪装执行进展。
- 普通回答保持真实流式，不固定进行第二模型全文审核。空输出、结构缺失等硬错误有限局部修复；高风险/时效/冲突先核验；权限与版本始终由程序检查。已展示内容发现错误时明确更正，不悄悄改成另一版。
- 自动检查不能保证发现所有语义错误。用户的否定、条件、追问或纠正按统一 IntentDecision 处理，保留未受影响进度；模型置信度不充当事实或授权。

### 18.7 工具与 badcase

- 已允许学习记录/知识卡的读取和任务必需的公开查证可自动执行；入库、覆盖知识、改变目标等由程序核对用户意愿、对象版本、生命周期和幂等键，不新增权限选择按钮。
- 网页、粘贴资料及工具返回中的指令都不是用户授权；外部搜索只发送必要查询，不直接上传完整私有会话或知识库。沿用 §17.4 的公网抓取与证据约束。
- 工具失败有限重试/局部恢复，不丢弃有效前序结果，不在默认运行详情倾倒参数或堆栈。主视图使用「正在查找资料」「正在关联你学过的内容」等真实阶段。
- badcase 持续回归覆盖误解、记忆误用、执行失控及学习闭环。每个样例记录初始状态、用户输入、预期/拒绝行为、实际错误和出处，回归使用脱敏或合成数据；不得自动上传真实用户聊天作为公开测试。
- 先复现失败测试再修复；分开报告代码、受控回归、真实模型、原生交互与 Rex 验收。不因一次模型返回或测试总数证明整条链路稳定。

### 18.8 后续语音方向与交付次序

听写是保守清理后的可编辑草稿，由用户发送；保留含义、否定、条件、数字与专业表达，允许撤销，不设标错/置信度下划线入口。清理失败保留可用转写，不擅自纠正用户的知识答案。语音聊天沿用当前 Session、目标和清单，底部输入区切换为语音控制；结束语音不取消目标、不丢原草稿。语音自然轮替、可打断，关键写入仍受控。具体语音模型和音频处理条件在恢复该阶段时确认，旧 Realtime 路线不是新的选型承诺。

## 17. M1 完整修复与体验升级（基础契约，受 §18 修订）

本节覆盖冲突旧定义，初始为「文档冻结／待实施」，实际证据只登记在 M1 验收 §0.10。保留文字/公开链接、五模式及历史数据，不扩语音或发布。顺序：文档独立 commit/push → 恢复/安全 → 学习闭环 → 实时性/界面 → OneWorks 候选 → 自动/原生验证/文档复核 → 独立代码和设计 commit/push。

### 17.1 连接与执行

- 区分本地启动、临时网络、凭证缺失、上游拒绝、能力不支持及本轮失败。主视图只显示影响、保留内容和有效操作；模型名/异常类/命令/HTML 留在脱敏开发诊断，不含密钥。
- 「重试连接」只探测，「重试回复」只恢复指定 Run。模型清单仅辅助，真实结构化调用决定角色能力；按当前步骤检查所需角色。内部备用的新目标规则见 §18.6；当前固定 Luna/Terra/Sol 配置不因文档更新自动改变。
- 临时失败 10/30/120 秒退避，此后 120 秒探测，不重叠；401/403、缺凭证、不支持不自动重试。手动重试或配置变化重新检查。
- 未开始的持久化消息恢复后自动处理；失败/中断/停止不自动重新执行。重启先协调 Run：仍运行则续接，执行丢失则中断。提交未知按消息 ID 查重，不创建第二份回答。
- 单 Session 单前台，控制、发送、事件及旧采集轮询独立；保留 steer/queue，停止暂停剩余队列。

### 17.2 共同权限、接口与快照

- Mac 原子保存归档状态、递增 lifecycle_revision 与待发控制，立即冻结输出，服务同步版本。恢复/撤销只恢复编辑，不恢复旧 Run/队列。
- 新旧 Task、Run、事件及提交 claim/本地知识写入共同检查 active、生命周期、Run revision、确认对象/内容版本。归档禁止发送/改模式/重试/入库，可读历史。
- 新版会话任务由会话处理器执行，旧处理器只适配旧任务，不重复投影新版消息；迟到事件可消费诊断，不恢复内容/成果/知识。已原子完成的知识不回滚，未提交旧版本拒绝。
- Task ACK 与归档使用同一事务锁检查版本并记录完成，新 Mac 的旧/新 Task 保存均先 claim。旧客户端没有 claim 时仅可确认仍 active 且版本有效的任务；已 claim 的本机原子提交允许迟到确认，但不恢复 Session 或生成。
- 新增 `POST /v2/sessions/{id}/actions`（action_id/action/lifecycle_revision）；`GET /v2/sessions/{id}/snapshot` 与 `POST /v2/sessions/{id}/snapshot/restore`（schema_version=1，仅恢复缺失 checkpoint）。冲突返回 409，不静默覆盖。
- messages 兼容增加 `expected_event_seq` 与 `lifecycle_revision`；客户端已有历史、服务检查点却缺失时返回 CHECKPOINT_REQUIRED，不能静默新建空会话。相同恢复快照使用指纹幂等；恢复撤销旧 pending/草稿授权，只导入状态，不触发模型。
- 当前恢复实现只接受覆盖本机已消费游标且事件范围连续的快照。后台快照滞后时保留本机历史并报告 SNAPSHOT_STALE，不猜测重建模型检查点；任意崩溃时刻的增量快照合成仍需补齐验收，不能宣称全量恢复完成。
- 快照包含身份/生命周期/模式/摘要、消息、Run 元数据、Task/计划、来源和待办；恢复旧运行成 interrupted，不调用模型/入库，不把导入当作新授权。
- Mac 长期保存完整记录，Python 仅执行检查点。清理须终态、已 ACK、无活跃引用，不能仅按 TTL。任务/事件兼容增加计划/来源/生命周期，健康结果增加分类/时间/恢复方式；旧接口不删。
- SwiftData 增量字段可空或安全默认；只有有证据的旧记录回填，缺失来源、步骤、掌握不猜测。

### 17.3 五模式与成果

- Auto 普通问题只完成本轮，寒暄不建 Task，无用途资料轻整理；知识整理交付版本化结果即完成；资料学习按范围讲解完成，不以跳过检查证明掌握；探索收窄/地图/真实互补资料包/确认后教学；攻克独立作答与合理迁移追问通过才完成。JD 先拆解再由用户选题。
- LearningPlan/步骤保存稳定 ID、版本、顺序、当前步骤、完成条件、讲解/理解状态及消息/来源引用。调整保留未受影响进度，追问/补学不重跑整条流程。
- Task 完成、理解（unknown/self_reported/verified）、知识提交分别记录。攻克通过即完成目标，保存独立；拒绝保存清除 pending/required_action，不重挂或催促。条件确认/纠正使旧授权失效。
- 小结来自已有评价/步骤：达成能力、仍需练习、入库状态，不额外调用模型、不虚构掌握。练习不写正式 FSRS。
- 待处理统一旧采集/新学习中需人决定的冲突/证据不足，准确返回 Session；临时网络不批量入队。Today/侧栏使用共同状态，停止不叫完成；活动按完成回答/教学/正式复习唯一 ID 去重。

### 17.4 来源、交接与实时性

- 来源稳定 ID/type/version/locator/fetched_at，生成讲义继续/跳过后不变成用户资料，混合来源逐项关联。公开快照复用，刷新/时效检查生成新版本。
- 资料包记录真实用途/互补性/证据，不足不伪造；所有搜索/教学/核验显式传角色模型。HTTP(S) 初始、每次重定向和实际连接均检查公网，阻止私网/保留地址/DNS 绕过，限制跳转/大小/耗时，不携带模型凭证/Cookie。
- 交接只含确认目标、相关步骤/理解、必要来源/知识和未决问题，保留原 Session，不复制全历史/旧保存授权。
- 回答最终校验落盘后独立完成，摘要后台失败不改成功。摘要绑定上下文版本，过期结果丢弃。
- SSE 保存后异步合并 ACK，慢 ACK 不阻塞读，不确认未落盘事件；稳定回答 ID/seq/revision 保证重放不重复。未完成内容不进入完成摘要/成果。
- 分测本地回显、识别、首段生成/显示及总耗时；受控目标 100 ms 本地反馈、200 ms 事件呈现、100 ms 显示缓冲，供应商慢调用单报。

### 17.5 学习手册与 OneWorks

- 保留单侧栏、开放居中回答、原生底部输入。按需显示结论/解释/例子/易错点/来源/下一步，不强套卡片模板；安全渐进 Markdown，最多一个主操作，保留自由输入。
- 学习清单固定标题下，默认一行目标/当前步骤，展开偏好按 Session 保存，长列表内部滚动不挡输入。真实 Task 才显示；点击看关联内容，不手动勾选/自动跳课。讲过/跳过/自述/验证用文字区分，不用百分比暗示掌握。
- 小结在对话内不弹窗/强制保存；Today 强调复习/准确续学/成果，热力图辅助。收轻空态/说明/空标签和高级排队操作，所有刷新保持焦点/阅读位置。
- OneWorks 网页实际制作「纸页伙伴」「记忆伙伴」两种抽象候选，奶白/石墨及青绿协调色；不沿用小狗，不扩动态角色。保存参数/工程及实际 PNG/SVG/透明导出，检查 16/32/64/128 px 和浅深背景。
- Rex 选择前不替换 V8；选定后精修/导出/原生检查才接入。不能以截图/放大图称高清母版，记录来源/使用条件/选择，不声明商标唯一性。

## 1. 为什么需要 V2

V2 实施前的基线是一条批量任务链：Mac 保存采集内容，Python 服务运行整张采集图，结束后客户端才能取得结果。服务不可用时界面只显示“等待服务恢复”，任务事件没有进入主要体验，所谓“思考过程”实际只是本地状态历史。

这不能满足学习教练的核心体验：用户输入后应立即得到接收反馈，知道 Agent 当前在做什么、为什么需要自己参与、如何恢复，并能在同一上下文中继续学习。

V2 把产品从“一次采集对应一次模型任务”改为：

```text
学习 Session（持续对话与上下文容器）
├── Message / AgentRun（独立消息与本轮执行；可以没有学习任务）
└── Learning Task（一次可暂停、恢复和完成的学习目标）
    ├── Message（按需关联的用户与教练对话）
    ├── Task Event（可回放的工作过程）
    ├── Source / Evidence（资料与证据）
    └── Knowledge Link（形成的长期记忆）
```

V2 不是通用聊天或多 Agent 平台。用户只面对一个专门的学习教练，内部根据学习目标选择受控工作流。

## 2. 产品对象与生命周期

### 2.1 Agent Session

Session 是一段连续学习对话的上下文容器：

- 新 Session 默认 Auto，也可选择知识整理、资料学习、主题探索、问题攻克；选择作用于当前目标及后续任务；
- 保存完整可见对话、结构化摘要、当前与历史任务、资料引用和知识引用；
- 一个 Session 可以连续完成多个相关 Learning Task；
- Task 完成不会自动关闭 Session；用户可以继续学习或手动归档；
- 归档只从活跃列表移除，不删除对话、任务、资料或知识关联；
- 归档是无需确认的直接操作；若存在前台 Run，先持久化 stop 控制并冻结当前可见输出，再归档。归档反馈提供撤销，旧 revision 的迟到结果不能恢复输出；
- Session 保存自动主题标签和可空的人工主题标签。人工值覆盖自动值，用户可恢复自动；关联知识标签来自 KnowledgeReference，只读且不与知识主题模型合并；
- Session 之间默认隔离，不把其他 Session 全部历史注入当前任务。

Session 状态：

```text
active → archived
archived → active
```

删除 Session 不属于 M1。后续若增加删除，必须单独定义知识引用、来源引用和不可恢复确认。

### 2.2 Learning Task

Task 是 Session 内一个可执行学习目标，不等同于一次输入或一次模型调用。一次 Task 可以跨多轮对话、等待用户选择、暂停、重试并恢复。

统一状态：

```text
accepted
→ queued
→ running
↔ awaiting_user
→ committing
→ completed
```

异常与终止状态：

- `retryable_failed`：外部服务、超时或可恢复结构错误；保留输入，由用户明确重试，不因重启自动重发模型请求；
- `needs_attention`：证据冲突、内容风险或必须由用户决定；
- `cancelled`：用户取消当前任务，Session 与已有消息仍保留；
- `terminal_failed`：无法在当前约束下继续，显示原因和可行下一步。

`completed` 只表示该 Task 的完成条件满足，不代表 Session 已归档，也不代表产生了长期记忆。

### 2.3 AgentRun 与 Session Event

AgentRun 管理一次前台回复/执行，可以不关联 Task；Task 管理跨轮学习目标。Run 状态为 accepted / queued / running / completed / interrupted / retryable_failed / terminal_failed；Session 的 paused 标志阻止停止后自动消费队列。Run 保存 revision、输入消息 ID、所处节点、意图、失败信息和结果引用。

新输入默认 steer，在可处理节点纳入。明确 queue 留待当前执行结束。stop 只停止回复并暂停队列，resume 显式恢复；cancel_task 结束学习目标但不删历史。模型调用不可取消时本地废止旧 revision，丢弃迟到结果，不宣称上游已停止计算。所有模型后的写状态、事件、知识提交检查当前 revision；停止不回滚已经完成的提交。

Session Event 支持没有 Task 的对话，session_seq 单调递增，包含 run_id/revision、可空 task_id、实际阶段、用户摘要、模型与脱敏诊断、消息及可选 Task 快照。Mac 先保存事件和消息再 ACK，不从文本反推 Task 状态。

### 2.4 Message 与 Task Event

Message 是用户应该阅读的对话内容；Task Event 是可回放的执行事实。两者不能混为模型思维链。

- 用户发送后，Mac 必须先保存用户 Message 并立即显示；
- 服务接受任务后，可以产生教练 Message、选择卡片或问题；
- Event 记录阶段、状态、路由依据摘要、耗时、重试、错误和恢复；
- Event 不保存或展示隐藏思维链、密钥、Authorization、无关完整正文；
- 重启后客户端按事件顺序号恢复，不能重复插入消息或知识。

## 3. 五模式与统一意图

产品只有 Auto、知识整理、资料学习、主题探索、问题攻克五个模式。“用户选择具体模式”是操作，不是第六种模式。旧协议枚举 `memory_organization` 保留，显示名称统一为知识整理。

| 模式 | 入口与默认行为 | 边界 |
|---|---|---|
| Auto | 结合本轮语义、当前任务和上下文自动调用四条工作流的所需能力 | 同目标内自动转接，界面保持 Auto；入库、改变目标、新建 Session 需要明确意愿 |
| 知识整理 | 梳理主题、知识点与关系，先交付整理结果 | 不默认已理解或入库；正式提交须理解条件满足且明确同意 |
| 资料学习 | 用户资料、公开资料或标注的生成讲义；分段讲解与理解检查 | 可追问或跳过检查；自述理解与验证掌握分开，不自动入库 |
| 主题探索 | 收窄目标、学习地图与合适资料；随后教学 | 外部资料为 2–4 个互补来源；明确要求直接教学时允许生成讲义 |
| 问题攻克 | 先答再校准、知识依赖与路径、独立作答及追问 | 答案、提示、跳过或自述理解均不等于攻克完成 |

### 3.1 输入与模式的关系

- Auto 的普通问题先解答，深入学习可选；不强制创建训练 Task。
- Auto 收到无用途说明且无任务可续接的资料，先轻量整理，不要求用户替系统分类，也不自动教学、入库或排期。
- 主动选择问题攻克后提交新问题，默认展开攻克流程；问候、追问和“这次只解释”不强行套流程。
- 本轮明确要求优先；上下文解释指代；所选模式决定默认工作方式。关键词、问号、URL、长度仅作线索，不能证明理解或授权。
- 一句消息可含多个意图，例如“不要保存，先解释第二点”；必须同时拒绝保存并处理追问。
- Auto 可同目标自动转接。具体模式下未明确要求的方式变化只建议；用户主动选择或明确请求即是方式变更意愿，不重复问。主动选择作用于当前目标下一步及 Session 后续默认方式，保留资料与进度。
- 明确无关新目标只建议新建 Session；用户确认后通过结构化交接包续接，不复制完整对话。主题关系保留 continuation / related_subtopic / new_topic / uncertain。
- 信息不足且不同解释会改变结果时只问一个必要问题。模型不确定不是运行故障，不得伪造学习目标。

### 3.2 识别与程序授权

Luna 统一输出 `IntentDecision`：本轮意图、目标 Task/待确认对象、候选工作流、拟执行动作、理解表达、主题关系、是否需要澄清及简短依据。问候、感谢、能力询问、普通问答、目标、资料、追问、提示、作答、纠正、肯定/否定/条件、暂缓、继续/暂停/停止/取消/排队必须有明确去向。

“我想一下”“稍等，我考虑一下”等只表达暂时不继续、没有要求停止当前生成或改变学习状态的话，属于 `defer` 对话控制：保留当前 Session、Task、待办与理解状态，只做简短确认并完成本轮 Run。它不同于 `pause`（暂停目标／队列）、`stop`（停止正在生成的回复）和 `queue`（明确要求稍后处理另一条输入）。没有活动学习状态时，历史兼容的 `self_report` 也可以按同一轻量路径收口；存在学习任务时仍按真实理解状态处理。

自由文本不能由客户端使用“包含切换”“不包含暂不”等判断动作。明确按钮是结构化用户操作，自由文本由语义识别后仍接受相同程序守卫：
- 对象必须属于当前 Session，待确认 ID 与内容版本必须匹配。
- 确认可以是明确自然语言；肯定词不能覆盖否定、条件或纠正。网页、引用及粘贴资料内的指令不是授权。
- 已有明确保存请求不重复问，但理解条件、知识风险与攻克验收不能绕过。
- 自述理解与已验证掌握分别记录，跳过不升级；正式复习评分完全独立。

## 4. 四种受控工作流

### 4.1 知识整理

整理入口不要求先证明理解：先梳理主题、要点与关系，交付会话内版本化草稿；仅要求整理时交付即完成，不以未保存当作失败。
正式入库是后续受控提交任务：引用已确认草稿版本与来源，不重复生成已完成结果；理解未知先确认理解，问题攻克来源还必须通过独立作答与追问。

```text
整理目标 → 来源与风险检查 → 知识草稿及版本 → 交付整理结果
明确保存意愿 + 理解条件 + 对象版本匹配
→ 结构、语义忠实性及证据校验 → Mac 原子写入 → ACK
```

稳定低风险内容不强制联网；时效、高风险、精确数字、争议或低置信内容核验。证据状态保留 unverified / supported / conflicting / insufficient / outdated / scoped。冲突只暂停受影响知识，不能强行写成已证实事实。已有知识卡、问题、评分规格及 ACK 幂等保持兼容。

### 4.2 资料学习

资料可来自用户、公开网页或明确标注的 Agent 生成讲义。生成讲义不是独立外部证据，不能伪装为用户原文或已验证文献。

```text
目标及材料边界 → 学习地图 → 分段讲解 → 追问/理解检查
→ 按用户节奏继续 → 自述理解或验证记录 → 可选正式入库
```

- 默认小步讲解，不倾倒整套课程；每段标记来源类型和可用定位。
- “继续”“先别考我”可以推进教学，跳过部分保持未验证；“我懂了”仅为自述理解。
- 追问、提示、举例使用现有材料与进度，不误当作答；不更新 FSRS。
- 已知误解保留并补教，不能伪造已验证掌握；正式入库仍需理解条件与明确意愿。

### 4.3 主题探索

每次收窄一个关键目标，建立学习地图，再选择材料路线：
- 外部路线：用户资料、公开链接，或 Agent 查找 2–4 个互补真实来源；确认资料包后进入资料学习。
- 直接教学路线：用户明确希望 Agent 直接教时，可以生成讲义并进入资料学习；稳定基础知识可先讲，风险内容仍查证。
- 同目标下 Auto 自动转接并说明；生成讲义与外部来源采用不同来源标记。来源不足不伪造 URL，可请求材料或建议直接教学路线。

外部资料包包含来源名称、用途、日期/版本、范围、定位与证据状态；Agent 讲义记录模型来源与版本，不声称外部证据支持。

### 4.4 问题攻克

进入条件：用户明确希望掌握问题、准备面试/工作解题、提供完整 JD，或已经选择问题攻克后提交新问题。Auto 普通知识问答只调用基础回答能力，不自动启动完整训练。

具体问题采用“先答再校准”：

```text
识别问题类型、目标和风险
→ 立即给一版可使用的基础答案
→ 标出关键假设、置信度和证据状态
→ 询问一个最影响深度的背景问题
→ 建立知识依赖与缺口地图
→ 给出针对性学习路径
→ 针对缺口讲解与练习
→ 用户独立作答
→ Agent 评价并追问
→ 达到独立作答标准
→ 询问是否形成记忆
```

首轮答案至少包括：

1. 结论或参考答案；
2. 相关知识点及其依赖关系；
3. 当前可能存在的认知缺口；
4. 针对性学习顺序；
5. 下一步校准问题。

面试类问题额外提供可口头表达的回答结构；一般问题提供可执行解法。稳定基础知识先直接回答；时效、高风险、争议或低置信内容自动查证，完成查证前明确标记为暂定答案。

完成判断：

- 用户必须先独立作答；
- Agent 从正确性、完整性、表达和迁移能力反馈；
- 根据薄弱点追问或补教，不重复整份答案；
- 能脱离参考内容回答当前题并处理合理变式后，Task 才可完成；
- 练习结果不直接写入正式复习评分；
- 完成后由用户确认是否形成长期记忆。

JD 入口先执行：

```text
解析岗位目标与职责
→ 生成能力地图
→ 标记高风险与高频要求
→ 生成按优先级排列的问题清单
→ 用户选择一题
→ 进入具体问题攻克
```

JD 不一次性生成整份答案，也不未经用户选择自动展开所有题。

## 5. 主界面反馈契约

### 5.1 即时反馈

提交一轮输入时：

1. Mac 生成稳定 `client_message_id`，先本地保存并立即显示用户消息；
2. 本地保存独立 Message；服务创建 AgentRun，确认存在学习目标时才关联 LearningTask；
3. 服务尚未就绪时显示“正在启动学习服务”，而不是沉默或伪装成处理中；
4. 服务接受后显示第一个真实工作阶段；
5. 无法启动时显示具体原因、重试和打开设置／运行详情入口；原始输入仍保留。

### 5.2 工作过程

主界面使用用户语言展示：

- 正在理解你的目标；
- 正在检查资料；
- 正在整理答案；
- 等你选择资料；
- 等你回答；
- 正在形成记忆；
- 已完成；
- 需要处理。

这些文案必须来自真实 Task Event，不得用循环动画假装模型仍在工作。

### 5.3 运行详情

每个 Task 卡片可展开“运行详情”，展示：

- 节点与阶段；
- 路由依据摘要；
- 开始时间、结束时间和耗时；
- 尝试次数与重试原因；
- 错误码、失败节点和恢复动作；
- 脱敏后的结构化摘要。

运行详情仍不展示隐藏思维链。开发模式中的全局运行记录继续存在，用于跨 Task 排查。

## 6. macOS 信息架构

主窗口侧边栏正式入口调整为：

1. **今天**：复习计划、学习活动指标、待处理和最近结果的数据看板；不提供输入；

主窗口使用单一可收缩侧栏。三个主入口固定，其下可折叠、可搜索、独立滚动的学习 Session 区跨页面保留。点击会话打开学习工作区，不增加独立学习按钮、第二侧栏或窄窗 Session 弹层。

学习工作区：

```text
主侧栏                         Agent 工作区
────────────────────────────────────────────

知识库 / 待处理                完整对话与真实流式回答
```

- App 默认打开今天；点击 Session 恢复准确的历史和草稿，没有 Session 时提供新建入口。Today、侧栏和学习页共享准确的 selectedSessionID；
- 用户可新建、继续、归档和恢复 Session；
- Session 行显示标题、运行状态、最多两个主题标签与模式；选中、悬停、失败、运行中和已归档不能只靠颜色区分；

- 键盘提交、焦点、长内容、窗口缩放和中英混排必须可用；

## 7. 本地服务与恢复

### 7.1 App 托管服务

开发 Mac POC 由 App 管理本机 Python 服务：

- App 启动后在后台检查 `127.0.0.1:8742/healthz`；
- 未就绪时使用项目已配置的本地 Python 环境启动服务；
- 监控进程退出和健康状态，采用有限退避自动恢复；
- 同一 App 生命周期只允许一个受托管实例；
- App 退出时终止自己启动的子进程，不终止外部手动启动的兼容实例；
- 环境、解释器或配置缺失时展示可操作诊断，不显示密钥；
- Release 分发、自启动代理、签名和安装包不在 M1。

### 7.2 数据事实来源

Mac 本地数据库是长期事实来源，保存：

- Session 与归档状态；
- Session 自动／人工主题标签、标签版本与更新时间；
- 用户和教练 Message；
- AgentRun、LearningTask、待发送消息与操作，以及 Session/Task 最后消费与 ACK 序号；
- Event 的用户可见与诊断字段；
- Source、Knowledge 和关联；
- 结构化 Session 摘要。
- AgentRun 的可空活动类型与完成时间，以及 ReviewAttempt 的创建／完成时间；它们只为可验证的学习活动与正式复习写入，不从用户可见文案反推。

Python 保留执行 checkpoint；Session 消息与事件按 Mac ACK 裁剪（§8.1），旧 Task 投影仍用原有保留规则。未完成输入、确认版本和幂等收据不能因普通缓存裁剪丢失；服务重新取得任务时使用稳定 ID。

### 7.3 上下文预算（既有兼容实现，目标见 §18.3–18.5）

每轮上下文由以下部分组成：

- 当前 Task 目标和状态；
- 当前 Session 近期消息；
- 结构化 Session 摘要；
- 当前资料相关片段；
- 最多 5 条相关既有知识。

上下文目标预算：路由与摘要约 3k tokens，教学与问题攻克约 16k tokens。当前 POC 用近期条数、字段长度和阶段摘要限制叙事窗口，未实现精确 token 计量；不能把目标预算当作严格性能保证。当前结构化任务状态与版本不被摘要改写。

跨 Session 可按 §18.4–18.5 检索允许复用的学习记录、相关知识，或接收用户确认的交接包；不注入其他会话全部对话、草稿或操作授权。上述最多五条字符串是当前兼容实现，不是完整学习记忆的最终结构。

### 7.4 新 Session 交接包

用户确认新建 Session 后生成：

- 最新输入；
- 推断学习目标；
- 相关已确认决定；
- 来源与知识引用；
- 未解决问题；
- 来源 Session ID。

不复制完整聊天记录。交接包以系统摘要形式显示，用户可以返回来源 Session。

## 8. API 与结构化契约

### 8.1 HTTP API

新入口（兼容扩展，不移除下面的旧接口）：
- `POST /v2/sessions/{session_id}/messages`：client_message_id、content、mode、delivery=steer|queue、受限上下文及可选明确操作；立即返回 message_id、run_id、可空 task_id。
- `GET /v2/sessions/{session_id}/events?after_seq=` 与 `POST /v2/sessions/{session_id}/ack`：按 Session 回放与确认本地消费位置。
- `GET /v2/runs/{run_id}` 与 `POST /v2/runs/{run_id}/actions`：稳定 action_id，stop/resume/retry/cancel_task/set_mode；明确操作检查 Session、Run、目标及状态。
- `POST /v2/tasks/{task_id}/commit-claim`：本机知识写入前领取当前有效提交。领取前的停止／替代撤销该提交；领取后进入幂等本机事务，停止不宣称撤回已经提交的知识，重启续接同一提交并 ACK。
- 自由文本一律进入 messages，不由 Swift 猜测 actions。旧 Task 动作接口保留，但同样使用确认与版本守卫。
- `IntentDecision` 为严格结构化枚举，不确定用澄清而不是四选一；运行异常区分超时、模型服务、空输出、拒绝及结构校验。仅结构修复最多一次，重试计数按实际模型请求，不把首次失败显示为第二次。
- 入库快照返回已确认的对象/草稿版本；Mac 只消费仍然有效的 committing 状态，同一知识 ID 与 ACK 幂等。停止或内容纠正先使未提交快照失效。已经完成提交不假装撤销。
- Mac 完整落盘后才 ACK。Python 对已 ACK 的 Session 回放缓存保留最近 64 条事件、至少最近 32 条消息及未完成运行所需输入；累计序号不重置，已完成 Run 释放模型输出缓存。Task 历史兼容投影暂保留；Mac 是完整原文、事件和引用的长期记录来源。
- 五模式修订的运行等待阈值：结构化能力探测默认 45 秒、正式模型步骤默认 90 秒，均可由环境变量覆盖。2026-09-03 的小型结构化探测实测约 33–39 秒，旧 8 秒探测会过早判为不可用；等待期间仍接收输入和停止操作，不以延长等待宣称模型已恢复正常。
- 开发 App 托管进程若启动 30 秒后仍无法响应健康检查，终止该次启动并按既有退避重试，最多四次；不再仅因 Python 进程存在就无限显示启动中。模型能力检查不阻塞消息接收。
- 开发工程位于 macOS 受保护的桌面目录；临时签名变化可能要求重新授权。启动超时且没有服务输出时，提示检查系统文件夹访问授权与 `.venv`，不一概标为模型故障。由用户在系统提示或隐私设置中授权，不自动改权限、不绕过系统保护。

以下为旧 V2 Task 兼容接口：


`POST /v2/sessions/{session_id}/turns`

- 输入：`client_message_id`、`content`、`content_type`、Session 模式预设、客户端已知任务状态；
- 行为：幂等接受一轮输入，立即返回；
- 输出：`message_id`、`task_id`、`status=accepted|queued`、`next_event_seq`。

`GET /v2/tasks/{task_id}`

- 返回 Task 当前状态、模式、当前阶段、等待动作、错误和最终摘要。

`GET /v2/tasks/{task_id}/events?after_seq={seq}`

- 按序返回尚未消费的事件；重复读取结果稳定；事件窗口丢失时返回需要任务快照恢复的明确错误。

`POST /v2/tasks/{task_id}/actions`

- 输入：稳定 `action_id`、动作类型和结构化 payload；
- 支持用户选择、确认、回答、重试、取消、建议切换模式、创建交接包；
- 同一 `action_id` 幂等。

`POST /v2/tasks/{task_id}/ack`

- 输入：最后持久化事件序号以及需要确认的知识 ID；
- 只有 Mac 已可靠保存结果后才 ACK；重复 ACK 幂等。

v1 capture 与 review API 在 V2 真实体验验收通过前保留。

### 8.2 Task Event

每条事件必须包含：

- `event_id`、`session_id`、`task_id`、`seq`；
- `occurred_at`、`stage`、`state`、`node`；
- `user_summary`、可选 `detail_summary`；
- `attempt`、可选 `duration_ms`；
- 可选 `error_code`、`recovery_action`、`required_action`；
- 可选 `message` 或结构化结果引用。

事件顺序号在单 Task 内严格递增。客户端按 `event_id` 和业务对象 ID 去重。

### 8.3 结构化模型输出

必须定义并校验：

- `IntentDecision`（本轮意图、指代、目标、动作、工作流、澄清、依据与可选 `session_tags`）
- `ModeDecision`（保留旧协议兼容）
- `SourcePack`
- `EvidenceAssessment`
- `LearningPlan`
- `LessonStep`
- `UnderstandingCheck`
- `QuestionAnalysis`
- `JDAnalysis`
- `ProblemAnswer`
- `KnowledgeGapMap`
- `MemoryPackage`

模型输出结构错误最多自动修复一次；仍失败则进入可重试失败或待处理，不能伪造完成。

## 15. 学习界面与实时反馈修订（2026-09-04）

本节为本轮已确认实施契约；与早期固定输入高度、完整生成后回显及所有回应均调用 Terra 的描述冲突时，以本节为准。实施前必须独立提交并推送本文与设计、产品、架构、决策及验收文档；实际验证结果另行回写，不预先标记完成。

### 15.1 体验与轻量回应

- 原生 NSTextView 统一正文／占位／中文预输入；Return 发送、Shift Return 换行、⌘ Return 兼容，选词不得发送。64–160 pt 内容自适应再内部滚动，底部按钮独立，保存失败保留输入。
- Mac 按 Session 保存未发送草稿，切换恢复、新会话清空；未发送草稿不属于模型上下文。只移除对话头像，侧栏品牌保留。
- 全行点击／键盘展开运行详情，完成后的普通运行收敛为一行；阅读上文不抢滚动，提供回到最新，主动发送定位新消息。
- 工作阶段短暂逐字呈现，正文真实增量输出，额外缓冲 ≤100 ms；历史不重播，Reduce Motion 下即时呈现增量，无脉冲及打字动画。累计执行计时换阶段不重置，停止冻结、重试另计；服务等待和排队不标为思考。
- `IntentDecision.light_reply` 可选字符串：纯 greeting / thanks / capabilities，以及没有学习状态副作用的 `defer`，可以直接完成轻量对话；无活动任务／待办／草稿时，旧的单一 `self_report` 也兼容收口。目标、操作、澄清、核验、模式变化、理解升级或混合意图如“谢谢，请保存”不得走捷径。此路径只发布回应并完成 Run，不能改 Task、待办、草稿或理解状态。五个模式均遵守，普通知识问题仍由 Terra 回答。
- 模型能力探测是服务级后台状态，不是当前 Run 的“思考阶段”。服务与消息协议可用时，探测进行中或部分角色异常不得占用对话顶部主状态；只在能力确实受限时显示紧凑、明确的能力提示，具体角色与错误留在开发诊断或本轮实际失败详情。所有角色均不可用、服务不可达或协议不兼容时，才使用阻塞性服务横幅。

### 15.2 实时与兼容协议

- 新增 `GET /v2/sessions/{session_id}/events/stream?after_seq=`（text/event-stream）；SSE id 使用现有 Session seq，数据复用原事件页结构，断线使用最后本机已持久化游标补齐。旧 JSON 事件读取、ACK、Task、Action 接口全部保留。
- 事件新增 `response.started`、`response.delta`、`response.completed`、`response.interrupted`、`response.failed`。payload.response 包含 response_id、revision、chunk_seq、text（当前快照）、delta（本次增量）及 status。Session/Run 标识、seq、时间等仍来自原事件信封。文本片段不覆盖主工作阶段、不逐片段显示技术日志。
- 回答 ID 在本次生成期间稳定，最终 message_id 使用同一 ID。Mac 对相同回答 upsert，不新增重复气泡；旧客户端只消费最终 message。部分文本只存预览，不进入 Python 的完成消息与默认摘要；Mac 同样过滤未完成消息的默认上下文。
- 模型适配层流式读取结构化输出，仅投影白名单正文／答案／反馈字段，不发送 JSON 或内部推理；结构、证据及程序守卫完成前，不发布学习状态、待执行动作或入库授权。已知风险先核验；生成途中发现低置信／证据问题时明确标记，阻止相关提交。
- Run revision 与稳定片段顺序阻止停止／替代请求继续输出。停止保留可见部分并标未完成，不自动消费队列。失败／重启不自动重发模型，显式重试保留已完成步骤缓存，仅重做未完成生成步骤。
- Mac 原子保存部分回答、事件和游标后 ACK；重复 ACK、重放、事件缺口和旧 revision 均有测试。停止本地守卫在请求发出前生效，不宣称上游计算已立即取消。
- 启动做真实流式能力探测，区分结构化可用与增量可用。相同模型／兼容接口只能整段返回时显示“当前模型仅整段返回”，仍可使用，但不算流式验收通过；不静默改模型。接口回退不能在已经显示部分回答后自动重复生成。
- 2026-09-04 适配发现：当前供应商曾在 `response.created` 之前发出文本事件，并重复发送 created，严格 SDK 聚合器会中断。读取底层 Responses SSE：仅允许忽略尚无公开正文时的空白／重启前导，正文开始后更换响应标识视为协议错误；必须收到 completed 并通过完整结构校验才可完成。403、超时等独立报错，不以兼容适配掩盖。一次探测等待约 102 秒，属于供应商耗时，不计作客户端性能改善。
