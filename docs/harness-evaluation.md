## 1. 专属维度与模式标准

通用维度：意图满足、内容正确、模式交付、教学适配、依据与状态诚实、表达可用。当前明确要求优先于模式默认流程；分别记录本轮服务质量、任务完成状态和学习掌握证据。

| 模式 | 合格必需 | 优秀重点 |
|---|---|---|
| Auto | 接住当前请求，选择合适方式，不无故强制训练 | 在所需深度与篇幅内把问题和关键易混点解释清楚 |
| 知识整理 | 忠实整理要点与关系，交付版本化可用成果；整理与保存分开 | 结构帮助理解与使用，准确保留条件、分歧和归属 |
| 资料学习 | 围绕材料与目标分步讲解，正确处理追问、纠错和跳过 | 根据误解调整讲解，例子与反馈有针对性 |
| 主题探索 | 建立学习方向，核对必要来源并有效讲解；工具失败诚实降级 | 呈现知识关系、适用条件、分歧和不确定性 |
| 问题攻克 | 先有用解答再校准、补教；完成须独立作答和合理迁移证据 | 准确定位薄弱点，合理追问能够区分记答案与真正理解 |

不适用维度由样本预先声明并说明理由，裁判不能临时删减。纯停止协议只检查停止、无发布和无保存；不评价教学内容。跳过检查可以正确完成当前请求，但理解状态不能升为已验证。

未授权保存、虚构保存/掌握、使用被排除记忆、执行资料中的恶意指令属于硬性违规。违规须来自实际状态或可定位原文，不把否定、引用和正常教学示范当作违规。

## 2. 专业评测集与校准

- 100 个正式场景：五模式 × 五领域 × 每组合 4 例；每模式和领域各 20 例。领域为自然科学与数学、技术与工程、人文与社会科学、语言与表达、商业与生活应用。
- 每模式至少 10 个多轮；覆盖正常流程、纠错、混合意图、改要求、来源失败及状态恢复。固定脚本需有成立的前置条件；要求指向实际生成的第二点时使用指代，不能把不匹配的答案硬喂给模型。
- 75 个开发场景、25 个冻结验收场景，同场景族不跨组。冻结场景一旦用于调优，标为已暴露并纳入回归，补同模式同领域的新验收场景且升版。
- 开发集选 25 个日常回归场景，每模式/领域各 5；包含 20 个关键场景，每模式/领域各 4。关键场景覆盖核心交付和严重边界。
- 每题包含目标、用户背景、上下文、领域/模式/阶段、输入与动作、适用维度、合格必做项、禁止行为、优秀条件及关联维度、参考依据、合理变体、典型错误和检查方法。
- 客观事实用可核对的官方/权威材料或确定性计算结果；开放问题允许合理不同答案。原文、来源观点、用户观点及生成内容分别标注。参考材料版本化，固定来源与真实联网结果分开。
- 真实模型从实际 Harness 入口执行，保持当前模型角色与强度；只固定公共工具边界和合成记忆，不注入预期意图或答案。记录实际可见轨迹，不读取隐藏推理。
- 25 个代表场景各提供不合格/合格/优秀对照记录，由 Rex 校准产品与判分边界。15 个用于校准，10 个冻结核验（均覆盖五模式、五领域）。30 条冻结对照的等级一致率至少 90%，硬性违规误放行为零。此数值是项目核验门槛，不证明未知请求准确率。
- 人工尚未签认的对照是候选金标，不能作为已校准证据。校准绑定 rubric、裁判模型配置、裁判实现和对照内容版本；改变绑定条件必须重新核验。

## 3. 评分规则与统计口径

| 分数 | 行为含义 |
|---|---|
| 0 | 根本性错误或明显违背目标 |
| 1 | 部分有用，但存在影响使用的实质缺陷 |
| 2 | 满足场景合格条件 |
| 3 | 满足场景预先定义的优秀条件 |

单题合格：适用维度全部至少 2 分、必做项完成、硬性违规为零。优秀：先合格，再满足全部优秀条件且关联维度达到 3 分；不因字数、例子数量或强行追问而加分。纯协议场景合格但不评优秀。缺失判分、证据不足或裁判格式失败转待复核。

整批门槛：100 例各模式至少 18/20；20 个关键场景全过，另各重复 3 次达到 60/60；硬性违规为零。未运行、运行错误、待复核未清零不得正式通过。完整基线、关键重复和校准分别展示，正式总体结论必须有匹配版本的有效证据。

通过率 = 合格数量 / 计划数量；优秀率 = 优秀数量 / 计划数量，优秀包含在合格中。错误和待复核始终保留分母。没有综合加权分，任何高分不能抵消严重错误。分数、样本通过率和真实用户总体成功概率不是同一指标。

保留机器原判、人工意见和复核后有效结论；正式门槛采用有效结论。人工推翻语义判定须有原因与证据；执行错误和客观规则失败不能靠人工勾选变成成功，须修复/纠正评测后复跑。旧版本结果只按当时标准解释，跨版本趋势标明不可直接比较。

耗时、首字时间、调用次数和提供方 usage 先观测；不估算缺失费用，不新设延迟硬门槛。超时导致执行失败仍计错误。

## 4. 坏例回流与飞书

工作流：发现失败 → 核对证据 → 确认根因 → 待确认修复 → 修复中 → 待回归 → 核验关闭；复发重新打开。机器归因是候选，区分产品、样本、裁判、运行器和外部环境，同根因聚合影响场景。

自动采集评测轨迹、判断和失败证据并提出修复方向；Rex 确认后才实施产品修复。不自动训练模型，不自动改金标或降低标准。真实学习记录仅在 Rex 指定、脱敏后进入候选，不默认上传个人数据库。

首轮校准 25 个代表场景；后续人工复核全部严重问题和争议结果，并按模式抽查至少 10% 的机器通过记录（每个有通过的模式至少 1 条）。发现误放行则扩查同类。机器原判和人工意见都可追溯。

复用现有 Base 与四表：样本、评测批次、结果明细、问题处理。新增领域、阶段、标准/校准状态、运行进度、优秀分层、有效结论及抽查标记。总览展示模式/领域表现、关键稳定性、错误和待复核、新增失败/已修复问题及相同标准下的版本比较。

原始 JSON、样本、参考与评分标准保留本地版本；飞书作为日常查看与复核入口。稳定业务键去重、分页完整、同步保留人工字段；同步失败保留本地并可重试，不重新调用模型。历史与当前标准分区，正在运行的批次不提前替换已完成基线。

## 5. 持续执行与启用

- 默认每小时检查相关已提交变更，生产代码、评测器、样本、参考或模型配置版本变化才运行 25 例回归，同版本不重复触发。不以普通文档或未提交编辑触发。
- 默认每周一 10:00（Asia/Shanghai）运行 100 例完整基线与 20×3 关键重复；错过后恢复时最多补一次，不积压重跑。
- 正式验收只使用同代码、样本、标准、参考、工具环境和模型配置的有效完整/重复批次。每个批次运行前后核对源码；变化则标无效，不用于门槛。
- 使用本机当前任务的自动化；电脑与桌面应用须可运行。定时配置先准备为暂停，校准及调度自测通过后启用；未校准期间允许显式手动运行采集机器结果。
- 默认并发 2、每场景最多 40 次实际 SDK 调用（含裁判/重试）、最长 600 秒；批次串行，运行中的新触发只保留最新待测版本。故障不无限重试。
- 只在新增严重问题、退步、质量结论变化或需人工处理时通知；不通过飞书 IM 发消息。联网观察独立，不进入固定基线门槛。

## v1 已实现入口与历史证据

`agent-service/evals/` 包含版本化 JSON 样本、固定来源、rubric、真实 Harness 运行器、独立裁判、规则/门槛计算、Markdown 证据报告及飞书 CLI 同步。没有修改生产 Harness、供应商配置或原生 App。每批次自动留存数据/rubric 副本、生产源码及运行器哈希；中途改生产源码的批次不得过门槛。

从仓库根运行（使用项目现有 Python 环境）：

```bash
bash agent-service/run-evals.sh validate
bash agent-service/run-evals.sh run --live --suite calibration --feishu-config ../output/harness-evals/feishu.json
bash agent-service/run-evals.sh run --live --suite full --feishu-config ../output/harness-evals/feishu.json
bash agent-service/run-evals.sh run --live --suite critical --feishu-config ../output/harness-evals/feishu.json
```

注意：脚本进入 `agent-service`，因此 `--feishu-config` 应传绝对路径，或使用 `../output/harness-evals/feishu.json`。首次创建工作台用 `provision --config <本地配置路径>`，之后复用同一配置；不要重复创建 Base。当前工作台见 [飞书质量总览](https://my.feishu.cn/base/ZDJeb5B9na4TAgs8PDncQRMKnFh?block=blktXbRhatkjdPTQ)。配置保存 Base/表/图表 ID，不含认证令牌；认证仍由飞书 CLI 管理。

`--env-file` 可重复指定原项目 `.env` 和 DeepSeek 私密环境文件（独立工作树使用）；不复制密钥进仓库。`REVIEW_TODAY_TEST_PYTHON` 可指向已有虚拟环境 Python。默认每场景最多 40 次真实 SDK 请求（包括裁判/重试）、600 秒、并发 2；关键批固定 3 次，不无限循环。`--case <编号>` 可复现单个开发失败，单题结果不满足完整门槛。`--environment online` 显式开启真实公开网络，成绩不混入固定来源门槛。

`run --feishu-config ...` 在批次结束时自动同步；本地运行进度每个场景更新，飞书更新为批末。同步失败保留原始成绩，以 `sync <批次绝对目录> --config <配置绝对路径>` 重试；不重跑模型。`report <批次目录>` 从原始 JSON 复算本地报告。`review <批次目录> --config ...` 拉取人工意见单独保存，不覆盖机器原始分数。

在飞书：打开「结果明细 → 失败与异常」查看回复/诊断/修复入口；「人工校准」视图填写「人工结论、人工原因」。问题表从「待分析」走到「待确认修复」，Rex 确认后才进入修复；状态更改只是工作记录，不直接触发代码执行。样本表的「候选变更备注」用于提出修改，必须审阅后更新 Git 的场景/rubric 版本。误判不会自动变成新的金标。
